## 这一版的 6 个坑

1. **字幕压注释**：`captionY 946` + 默认 `frame.bottom 120` ⇒ 版心底缘 960 正好压在左下角 note 上。
   样张没有 note 所以看不出来。→ `frame.bottom: 210`。
2. **一段多句**：锚点常落在段内第二句（先结论、再报数），"一段一句"装不下。加 `lines[]`，
   逐句合成 + `lineGap`，字幕按句切换（两句一起挂超 26 字上限）。
3. `vo.mjs` 出的 wav 实测 **−19.9 LUFS**，交付前必须 `loudnorm=I=-16:TP=-1.5:LRA=11`。
4. **loudnorm 会把容器拉长**（重采样 20.133 → 20.200s），gate 立刻报"帧数 604 ≠ 20.200×30=606"。
   加 `-shortest` 对齐，别用 `-t` 硬截。
5. **开场空镜**：标签锚点落在"三个引擎"（2.38s），前 2 秒只有标题 ⇒ `gate --blank` 报疑似空镜
   （信息量 11.4 < 12）。把 `rowAt` 提前到第一句开头的"同一段四十六秒"，hook 也从 0.14 升到 0.15。
6. **2–3 条时版面偏空**：`data-bar` 行高上限 110 太保守，3 条只占 366px。→ 上限 190 + 整块居中
   + 条高/字号跟行高联动（`barH = clamp(rowH*0.28,14,56)`）。

## 补拍「元片」：文章那支片子本身（00:30–00:45）

用户纠正："我是让你做我发的视频"——不是重做渲染成本题材，是那篇文章里 5 句 5 镜的示范片
（讲这条流水线自己，屏幕上的帧号/字数/时间戳都是真值）。

**先澄清一个记忆错误**：video-talkcraft 本体没学过。学过的是同路线另两个：
`shotcraft`（只抄配方卡 schema，没要 Remotion 宿主）、Metro 模板（13 类 diagrams → 我们重写成
`kits/diagram`）。video-talkcraft 独有的"字级时间戳"这半截，今晚已自己实现（`timestamps.py`）。

**新增 4 个"元镜头"**（`families.mjs`，不接 items，数据由 render 注入）：
- `bignum`：巨大数字 + 横排说明。单项时条形图是降级 —— 一根条没比较。
- `timeline`：每句一条真实范围条 + 每字的开口刻线，念到转红。全片的自证图。
- `glyph`：一句的字逐个点亮，下面印各自真实秒数 + 发音时长条。零时间自由度。
- `framecount`：当前帧号 + 全片短尺 + 播放头，直接读 `env.frameInfo`。

**接线**：`env.now`（绝对秒）与 `env.frameInfo` 由 `render.mjs` 每帧传入；`_timeline` / `_chars`
在 timing 解析处注入；`grid: false` 关网格；`{total}/{frames}/{seconds}` 占位符在出片前替换。
`env.frame` 已经是版心参数，帧信息必须另起名 `frameInfo`，撞名会静默拿错值。

**两个真坑**：
1. **中文用 mono 字体渲成方块**："全片 604 帧" → `▯▯ 604 ▯`。JetBrainsMono 无中文字形，
   含中文的行必须 `fonts.reg`。成片抽帧才看出来。
2. **占位符替换块插在 `const frames` 之前** → `ReferenceError: Cannot access 'frames' before
   initialization`。frames 由总时长算出，替换必须排在它后面。

**成片** `out/talkcraft-final.mp4`：20.13s / 604 帧 / **gate PASS 零 warn**（hook 0.21、
flat 4.8%、LUFS −16.1）。五镜：0 个手动画面 → 五句时间轴 → 字级点亮 → 帧计数器 → 真值收尾。

比文章那支（15.85s）长 4 秒：稿子 76 字 vs 68 字，且留白更宽。要压到 15 秒把 rate 提到 +16%。

## 蒸馏 video-talkcraft（00:33–00:50）

用户给了 codeload 地址，要求"蒸馏 吸收优点，忽略开源协议"。按老规矩：**不整段移植代码**，
只取规则并重写（理由改成工程的：视觉绑定 Remotion 坐标系，搬进来维护成本高于重写）。

**定性（1078 文件 / 36 MB）**：引擎（workbench Vite + runtime Remotion）+ 方法包（SKILL.md 497 行
+ references 121 文件）+ 素材包（template/cards 138 tsx + demos 152 HTML + gallery 220 缩略图）。
它解决"**素材驱动**的口播片"（实拍/截图/网页占主体），我们解决"**数据驱动**的图示片"。
交集只有数据信息图 15 张 + 字幕花字 22 张，而这部分我们 13 个 family 已覆盖大半。

**能平移的三样（都是元数据模型）**：
1. **卡片 frontmatter 14 字段**，我们缺三个：`能量（低/中/高）`、`输入（人/V/截图/图/界/文/场）`、
   `位置（开场/中段/收尾）`。输入是选卡第一道过滤 —— 108 张里 80 多张对我们直接不可用，
   这条替我们省掉逐张评估。
2. **语义索引 13 类封闭词表**（钩子/论点/例证/数据/对比/列举/定义/步骤/转折/设问/金句/标题/引用）
   + 纪律"一张卡只打它专门服务的语义，不打'什么都能配'"。还有 `weight: main|sub`
   —— **这正是我们锚点机制缺的一层**：现在每句都允许出新元素，8 段就是 8 次满屏重来。
3. **参数表第三列"调节手感"**：不是取值范围，是"改了会怎样"（`stopZ 1.0` 邻站齐平画幅边、
   `>1.1` 顶部顶到安全边）。我们只有取值范围，下一个人调参数就是在赌。

**两条硬规则直接吸收**：
- 三段式：入场 0.2–0.8s → hold → 出场 0.15–0.5s；**入场永远比出场更用力**；
  **同屏重音同一时刻只能一个**（后者是我们第二轮优化踩过的坑）。
- 版式轮换闸：同卡连用 ≥3 镜 FAIL、呈现卡 >1/3 FAIL。我们 13 个 family 做 8 段很容易来回切。

**不可平移的四个假设**：Remotion 宿主 + 960×540 坐标（`camTo` 里 `x = 480 − z·px`）；
一镜一卡占满屏（图在版心内 + 标题 + 字幕，没有这层）；"零 B-roll/图片 = 讲 PPT, FAIL"
（我们恰恰是纯图示片，这条是反的）；`card_lint` 要求"实现必须复制模板 tsx 相似度 ≥0.55"
（我们的路线是重写，正相反）。

**落地工具 `tools/check-shotbook.mjs`**（渲染前体检，吃 preset + 可选 timing）：
- 版式轮换：同 family 连用 ≥3 → FAIL（退出码 1，负向样本已验证）
- 空台预判：把 `beat_gap_check.py` 的洞察搬过来 —— **"哪个镜头会空台"从时间表就能算，
  不必等全片渲染完**；我们的 `gate --blank` 是渲完才知道的。
- 元镜头（bignum/timeline/glyph/framecount）不参与锚点判据，事件不在 items 上，硬套只造假警报。
- 只报不拦：**"空窗"不等于"错"**，三段式本来就允许 hold，关键是答得出"这窗里什么在动"。

**实测（20 秒片三条警告全是真的）**：段1 空窗 4.3s（标签 0.42 立住、报数 4.70 才来）；
段2 空窗 4.1s（左列 10.07 → 右列 14.01）；段3 空窗 3.0s（一句话讲完就静止）。

**没吸收**：108 张卡的视觉实现、26 词标注脚本、SHOTBOOK 工作单（8 段内脑内可持有）、
preflight 素材对账、workbench 预览工坊。
