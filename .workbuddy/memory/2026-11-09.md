   没给本仓库 Actions 写权限。换新包名 `cutduo-renderd`，GITHUB_TOKEN 自建有写权限。
3. `COPY .vendor/` 会永久占一层（145 MB），后续 `rm` 删不掉 → 必须用两阶段构建。
4. `pkill -f "docker build"` 会杀掉执行它的 SSH 会话（命令后半段含同样字符串）。
5. 容器内访问 GitHub/deb.debian.org 大文件会静默挂死（宿主同 URL 有 13–17 MB/s）
   → 需要 `--network=host`、`ARG APT_MIRROR`、`.vendor/` 离线通道三件套。

**探针缺陷修复**：worker 长期 unhealthy 的根因是「一个探针服务两种角色」——
worker 不监听端口，打 /healthz 必然被拒。改为 `renderd/healthcheck.py` 按 PID1
分角色：api 打健康端点，worker 只判进程存活（不探 DB，避免把 DB 抖动误报成 worker 挂了）。
验收：worker `healthy` + 真实渲染 `job_460f19605370`（10.89 s，pass）。

**发布 v0.2.0 / v0.2.1**：v0.2.0 部署后 `/healthz` 仍报 `0.1.0`（版本号硬编码在
`renderd/__init__.py`，与 git tag 无关）→ 改为 `RENDERD_VERSION` 环境变量优先、
CI 按 ref 注入（tag 取纯版本号，分支取 `0.0.0+sha`），发 v0.2.1 修正。
教训：**版本号必须有单一事实源**，否则「线上跑的是哪个版本」无法回答。

回滚就是换回上一个 tag。
