## 门禁盲区补洞（同日，绿点续）

清完架构债后重查「现有检查到底测了什么」，发现 `npm run check` 的 API 段全走 `probe`：
- probe 在 `render.mjs` 里 `process.exit(0)` 早退 ⇒ worker 分片 / concat / 音轨混流从没执行过
- 「回执只信 ffprobe」是 docs/API.md 的硬承诺，却没有任何断言验证它
- 所有 probe 无音轨 ⇒ concatParts 的「PCM→aac」分支（mp4 塞 pcm 会整轨静音）从没跑过

补：`tools/smoke.sh` 的 api 段加一条 api.render 端到端（paper + 现场合成 3s PCM wav），一次验三样。
```
PASS  api:render 端到端 回执 2573 帧 == ffprobe 2573 帧 · 音轨 pcm→aac
```

**负向验证（两条都必须能红）**：
- contract.mjs 回执帧数 +1 → 2574 vs 2573 → FAIL ✓
- concatParts 音轨策略改成永远 `-c:a copy` → 产物 `pcm_s16le` → FAIL ✓

代价：check 17s → 31s。教训：**「有 10 条 probe」不等于「测了 10 条路」**——
要问 probe 与 render 在代码里是否走了同一条分支。
