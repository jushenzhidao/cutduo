# P1 启动包

P0 的产出是「知道素材会怎么坏」。这份包里是 P1 第一周要用的四样东西：取材、算账、采购、门禁。

---

## 一、BSK 取材 runbook（证明「素材不用搬家」）

**这一步的唯一目的**：拿着一台装着客户账号的浏览器，把一条完整链路手工跑通，全程录屏。它不是自动化工程，是**一次商业验证**——验证「客户不需要先把素材上传到我们平台」这件事是真的。

### 前置

| 项 | 说明 |
|---|---|
| `bsk` CLI | 按仓库 README 的一行脚本安装，落在 `~/.local/bin/bsk` |
| 浏览器扩展 | Chrome / Edge 商店安装（Chromium ≥125） |
| 登录态 | 用**客户授权账号**登录，不用自己的号做演示 |
| 连通性 | `bsk doctor` 通过；`bsk --help` 确认当前版本子命令（0.3.x 与 0.2.x 有差异，别照抄旧文） |
| 隔离 | 任务跑在独立 Agent Window；需要借用已开标签页时显式借用、结束归还 |

### 三条取材路径（按客户素材实际在哪选一条）

| 路径 | 场景 | 关键动作 | 注意 |
|---|---|---|---|
| A 创作中心草稿箱 | 客户素材已经在抖音/视频号/B站 后台 | 打开素材库 → 按日期/合集筛选 → 逐条取回原片 | 后台给的是转码后的版本还是原片，必须当场确认；拿错版本后面所有质量结论都失效 |
| B 企业网盘 / 飞书 | 素材在共享链接里 | 打开分享页 → 展开目录 → 批量取回 | 分享链接可能带有效期和水印；水印版本不能进语料 |
| C 客户自有 DAM | 有账号体系的内容库 | 登录 → 按标签检索 → 取回 | 这类客户的真实痛点是「权限粒度」，记录下来，是定价依据 |

### 记录表（跑完必须填满这 10 项，否则这次试验没有产出）

| # | 字段 | 为什么记 |
|---|---|---|
| 1 | 素材总条数 / 成功取回条数 | 决定这条路径的可用性 |
| 2 | 单条平均耗时 | 直接进 P1 的端到端预算 |
| 3 | 单条平均字节数 | 决定出口带宽成本（见第三节，这是最大的一项） |
| 4 | 拿到的编码/封装分布 | 反哺 P0 语料：真实分布和你合成的 21 条差多少 |
| 5 | 是否触发验证码 / 二次确认 | 触发频率决定要不要做人工介入队列 |
| 6 | 是否需要借用已开标签页 | 决定 Agent Window 是否够用 |
| 7 | 页面结构是否有反爬（懒加载、无限滚动） | 决定选择器策略 |
| 8 | 失败条目的失败原因分布 | 这一步的分布就是 P2 失败分类学的输入 |
| 9 | 客户看到过程后的第一反应 | **最重要的一项**：他惊讶的是"不用上传"，还是"这有什么稀奇" |
| 10 | 录屏文件路径 | 销售素材 |

### 从采集结果到 IR 的映射规则

| 采集到的 | 写进 IR 的哪里 | 规则 |
|---|---|---|
| 文件字节 | 对象存储 | 键用 `sha256` 前两位分桶，不用原始文件名（同名不同内容会互相覆盖） |
| 内容哈希 | `assets[].sha256` | 必填。去重、缓存、审计都靠它 |
| 时长 | 不写 | IR 里只有 `in_frame` / `out_frame`，且是整数帧；秒是展示层的事 |
| 原始分辨率/帧率 | 不写 | 那是 `probe` 的输出，属于素材元数据，不是时间线 |
| 客户选的入点出点 | `clips[].in_frame` / `at_frame` | 从播放器读到的秒 → 帧，只能乘 fps 后**向下取整**，且必须回读校验 |
| 平台/账号 | `delivery` | 发布目标；不进渲染 |

### 合规红线（写进代码，不是写进文档）

1. 只操作**客户自己授权的账号**，不用任何他人凭证。
2. **发布必须人工确认**——BSK 扩展 popup 的「允许请求人工帮助」保持开启，不做无人值守发布。
3. 不做去水印、不搬运他人内容、不做批量刷量。
4. 平台 ToS 与《反不正当竞争法》是硬约束。这条一旦踩，前面所有技术工作归零。

### 失败模式与应对

| 现象 | 应对 |
|---|---|
| 验证码 / 短信 / 人脸 | 走 `request-help` 交还用户，**不要**尝试绕过 |
| 页面结构变更 | 语义选择器 + 失败即求助；禁止"重试 10 次"式死循环（会触发风控） |
| 无限滚动加载 | 设定明确终止条件（条数上限或日期下界），不做"滚到底" |
| 上游项目停更 | 缓解：`bsk` CLI 与扩展源码 MIT 可本地构建。方案里要写明"最小可自持部分是哪几个 crate / 哪个目录" |

## 二、GPU 采购规格单

**一句话**：买 L4 / L40S / T4 / A10G，**不要买 GeForce**。

| 型号 | NVENC 引擎 | 并发编码会话 | 建议用途 |
|---|---|---|---|
| **L4** | — | 无会话上限（按引擎吞吐） | 主力：1080p 批量模板渲染，性价比最好 |
| **L40S** | — | 无会话上限 | 4K / 多轨合成 / GPU 特效链 |
| **T4** | — | 无会话上限 | 存量机型，能买到便宜的可以用 |
| **A10G** | — | 无会话上限 | 介于 L4 与 L40S 之间 |
| GeForce RTX 40/50 系 | 1–3 个 | **全系统 12 路（驱动层锁）** | ❌ 不要用于渲染农场 |

**为什么不能买 GeForce**：会话上限锁在驱动层，不是显存不够。超限报错是：

```
OpenEncodeSessionEx failed: out of memory (10)
```

这句报错**指向显存**，实际是许可上限。你会在压测时看到"显存还很空但编码一直失败"，然后花两天查显存泄漏。RTX 5090 有 3 个编码引擎、RTX 4060 只有 1 个，但全系统并发上限都是 12——引擎数决定吞吐，不决定上限。

**镜像必须锁死三样东西**：

| 组件 | 为什么要锁 |
|---|---|
| NVIDIA 驱动 | ffmpeg 构建时的 `nv-codec-headers` 版本必须 ≤ 宿主驱动支持的 SDK。升驱动不重建镜像 → 编码直接崩，且代码一行没改 |
| ffmpeg 版本 | 滤镜行为会随版本变（本仓库就踩到：ffmpeg 9 不再支持用 metadata 写旋转矩阵） |
| 字体集 | 字体变了字形像素就变了，跨端一致从物理上失效 |

**一个反直觉的量**：编码不是瓶颈。NVENC 很快，真正的耗时在**解码 + 缩放 + 颜色转换 + 合成**——这些跑在 shader / CUDA core 上，不在编码器里。所以看 `nvidia-smi dmon` 时要盯 `sm` 列，不要只盯 `enc` 列。

**显存估算**：1080p 单路约 200–500MB（取决于滤镜链和是否 zero-copy）。L4 的 24GB 够跑十几路，但真实并发应受 CPU 侧合成能力限制，先按 4–6 路/卡起步压测。

## 三、定价速算

### 三个公式

```
① 按分钟卖
   毛利 = 售价/分钟 − (算力 + 带宽 + 存储 + 重试)
   代入：0.06 − 0.049 ≈ 0.011 → 18%

② 按条卖
   单条成本 = 输出分钟 × 每分钟成本
   15s 成片 = 0.25 min × 0.049 ≈ ¥0.012
   毛利 = (2.00 − 0.012) / 2.00 ≈ 99.4%

③ 按席位卖
   单席成本 ≈ 月成片条数 × 单条成本
   199 元/席，月产 500 条 = 成本 ¥6 → 毛利 97%
```

### 成本参数（改成你自己的采购价）

| 参数 | 本次取值 | 你的值 | 敏感性 |
|---|---|---|---|
| 16 vCPU spot | ¥1.8/hr | | 低（占 31%） |
| 吞吐 | 2× 实时 | | 中 |
| 成片码率 | 8 Mbps（60MB/min） | | **高（占 61%）** |
| 出口单价 | ¥0.5/GB | | **高** |
| 失败率 | 5% | | 低 |

**两个立刻能做的动作**：

1. **把出口剥离**：`delivery.egress = customer_bucket`，成片直传客户自己的 OSS，签名 URL 交付。这一项省 ¥0.030/分钟 —— 比把吞吐从 2× 提到 4×（省 ¥0.007）大四倍。
2. **别给干净素材转码**。P0 语料里只有 1/21 能零转码直通，说明绝大多数素材必须转；但如果客户的素材来自同一个导出模板（B 端很常见），直通率可能到 50%+，成本直接减半。

### 结论

**计量单位先改，再谈优化。** 按分钟计价会让你被迫和阿里云 IMS 的 ¥0.06/分钟对表，而你的成本结构撑不住那个比较组。按条计价，客户比较的对象变成外包剪辑师的 ¥150–500/条，同一套成本结构立刻变成 99% 毛利。

## 四、门禁

```bash
cd cutproof
./ci/gate.sh
```

五步，任何一步失败即非零退出，可直接挂 CI：

| 步 | 做什么 | 失败意味着 |
|---|---|---|
| 1 | 语料自检 | 某条语料没复现出预期故障 → 测试用例失效，不是代码坏了 |
| 2 | 探针 + 归一化 + 8 项规格校验 | 归一化产物不合 canonical 规格 |
| 3 | 渲染正确片 + 错片 | 渲染链路坏了 |
| 4 | 证据回执（L1 + L3） | 成片不合断言 |
| 5 | 负向测试 | **字体缺失的错片被放行了** —— 这是最不能容忍的一种 |

第 5 步是这套门禁的核心。它测的不是"能不能渲出片子"，而是"**渲错了能不能拦住**"。只做正向测试的渲染流水线，一定会在客户那里第一次见到错片。
