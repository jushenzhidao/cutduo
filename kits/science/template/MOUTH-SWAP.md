# 口型：用现有姿态图做嘴部替换（已验证可行）

上一轮结论是「口型只能靠音频包络驱动起伏」，并记录了两条失败路线（贴椭圆 / 整图切换会跳）。
本次用**已生成的 m0–m3 口型变体**做「只贴嘴部」，出片验证：**可行**，无需新素材、无需 lip-sync 模型。

样片：`out/mouth-demo-lip.mp4`（150 帧 / 5s / 30fps，用 `demo.edge.json` 的真实 `mouthCurve` 驱动）
对照表：`out/mouth-demo-sheet.png`（每 0.4s 取一帧）

## 为什么这次能成

| 上次的判据 | 本次实测 |
|---|---|
| 「同一 reference 出的图构图有差异，切换会跳」 | 配准（缩放 + 平移搜索）显示 m0–m3 与 idle **scale=1.000, dx=dy=0**，脸区残差 MAE 1.3–3.1 |
| 「全身都有结构性差异」 | 确实存在（thr>90 仍有 2.8 万像素），但**只贴嘴部**就不受影响 |
| 贴片会被看出来 | 加羽化 + 局部色彩匹配后，两帧差异被限制在 **83×55 px**（thr>20），即接缝低于可见阈值 |

## 落地参数（别再从 zero 猜）

坐标系**一律用 raw 图（880×1184）**，不要和 `idle.png`（720×980，0.954 缩放 + 补边后的产物）混用——
上一轮「坐标差 160px」就是混用这两个空间导致的。

```
人物 alpha 包围盒   (161, 133) 565×995          # idle_raw.png 抠图后
唇部 bbox           (369, 435) 84×54            # HSV: h<0.045 或 >0.95, s>0.55, 0.08<v<0.62
贴片 box            (345, 423) 132×90           # 唇部外扩：左右+24 下+24 上+12（上边少留，避免带进鼻子）
羽化                rounded_rect inset=14, radius=14, blur=11
色彩匹配            取贴片四周 16px 边条均值，逐通道求增益（实测 0.95–1.06）后套到贴片上
```

贴图位置（画面 1920×1080，人物高 994，底部沉出 92px）：

```js
const BB = { x:161, y:133, h:995 };  const SC = 994 / BB.h;
const FY = 1080 + 92 - 994;                       // 头顶
drawImage(fig, FX, FY - BB.y*SC, fig.w*SC, fig.h*SC);
drawImage(patch, FX + 345*SC, FY - BB.y*SC + 423*SC, 132*SC, 90*SC);
```

**两个必须记住的偏移**：① 人物按 bbox 顶部对齐，所以画人物和画贴片都要减 `BB.y*SC`；
漏减会让贴片掉到下巴以下 133px（本次踩过）。② 贴片 box 的上边距要比左右小，否则羽化会把鼻底带进来。

## 驱动

`preset.mouthCurve`（`vo.py` 产出，30fps，0..1）→ 量化成 4 级：
`level = min(3, round(v * 3.2))`，对应 `mouth0..3.png`（闭 / 微开 / 开 / 大张）。

实测该窗口（8–13s）的级分布：`{0:73, 1:25, 2:40, 3:12}`，即一秒钟大约换 3–5 次，
不会出现「一直张着嘴」或「一直闭着」。

## 还没做的

1. **没接进模板**：`src/layouts.js` 的 `figureSlot` 还没调用贴片（本次只在独立样片里验证，
   避免与另一会话同时改同一文件）。接入点就是 `figureSlot` 画完人物后补一行 `drawImage`。
2. **4 级循环不够细**：真实语音需要 6–8 档（含圆唇、咧嘴），现在 4 档能读出「在说话」，
   但快速连读时会有跳档感。加档只需再生成 2–4 张变体，坐标流程已固化。
3. **侧脸/手势姿态**（explain/point/open）没有对应口型变体，只有正脸可用。

## 2026-11-13 01:00 · 接进模板后的实测（含一个真 bug 与一个未解决的缺陷）

### 修掉的真 bug：Skia 侧从未拿到口型贴片

`skia-kit/science.mjs` 的 `primeFigures()` 只喂了四张姿态图，没喂 `__MK_MOUTHS`。
浏览器由 `index.html` 的 `<img data-mouth>` 提供，Skia 没有 DOM ⇒ `figureSlot` 里
`M.half / M.open` 恒为空 ⇒ **口型只在浏览器有，Skia 静默缺失**（与当初姿态图那次同类）。

- 证据：曲线峰值 0.95 处，修复前嘴巴是默认闭合形态；修复后同帧差异 **精确落在贴片区 178×150 px**。
- 修法：`primeFigures` 补加载 `assets/figures/mouth/m_{half,open,round}.png` 进 `win.__MK_MOUTHS`。
- 回归：完整片 2369 帧 / 78.967s / 12.3s 出片，`gate.mjs` **PASS**（0 平帧 / 0 黑帧）。

### 未解决：贴片整体对不齐，肉眼是一层抹痕

| 观察 | 数据 |
|---|---|
| 贴片远大于嘴 | 贴片 210×150，而嘴只有约 85×55 ⇒ 覆盖鼻底到下巴，变体与基准的皮肤/鼻影差异整片可见 |
| 各变体嘴位不同 | 与基准的差异质心 x=446.5–449.9（四个变体高度一致），而按 `figureSlot` 锚点反推应为 raw x≈416 ⇒ 差约 32px |
| 自动定位不可靠 | HSV 取"偏红偏暗"会抓到腮红/下巴阴影（(371,455)）；取最暗质心会掉到下巴（(409,490)）；两者与差异质心差 60–80px |

试过并放弃的三条：① 贴片缩到 132×90（脸颊灰印消失，但嘴位偏移仍在）；
② 按各自 HSV 嘴心裁切（定位本身不稳）；③ 用 `idle.png` 坐标反推（`idle.png` 是 raw×0.954 再补边，
两个空间不能混——这正是历史记录里"坐标差 160px"的来源）。

### 正确的下一步（不建议再用颜色/亮度找嘴）

1. **人工标 4 个点**（左右眼角 + 左右嘴角）在各变体上做仿射，而不是自动分割——嘴只有 85px 宽，
   任何基于颜色阈值的定位误差都在 20px 量级，等于吃掉 1/4 嘴宽。
2. 或者**从源头消掉偏移**：生成口型变体时锁死构图（同 seed + 首图 reference + "exact same framing"），
   让嘴心在所有变体里恒定，就不再需要逐张对齐。
3. 贴片尺寸应当紧贴嘴（约 120×84），只用 8–12px 羽化；**大贴片在这种"变体全身都有细微差异"的素材上不可行。**

## 2026-11-13 01:10 · 结论修正：这套素材做不出无缝口型，贴片已关闭

按"人工标点做仿射"的思路走了一遍，先证伪了对齐假设：

- **脸是对齐的**。瞳孔连通域检测：idle 与 m1/m2/m3 的眼睛中心**完全相同**（314.2,320.6）与（564.6,308.2），
  差 <0.1px。所以"重构图导致错位"不成立。
- **错的是素材本身**。变体与 idle 在**整张下半脸**上都不同（差异 >60 的像素约 3.5 万，覆盖鼻唇沟、脸颊阴影），
  不只是嘴。放大的差异图能看到微笑形状的亮区 + 一层整体矩形差异。

于是三种贴法全部失败，且是构造性的：

| 方案 | 结果 |
|---|---|
| 整块矩形贴片（210×150 / 143×105 都试过） | 贴纸感：变体皮肤/鼻影与基准不同，整块可见 |
| 只贴更小的嘴 | 鬼影：变体嘴位与基准不重合（差 30px 量级） |
| 逐像素差异蒙版（只有变了的像素贴） | 断续碎片：微笑与圆唇重合处没有差异，贴不上去，成为抹痕 |

**决定：关闭贴片调用**（`src/layouts.js` 里 `if (false && mouth > 0.30)`，附完整原因注释），
回落到音频包络驱动整体起伏。重出片 2369 帧 / 12.0s / gate PASS，
与关闭前同帧逐像素比对 **差异 0 像素**（干净回退）。

**要真正做口型，只有两条路**：
1. 素材端锁死构图（同 seed + 首图 reference + "exact same framing"），让"只有嘴变"成立；
2. 接专门的 lip-sync 模型（当前模型池没有，见上一节）。

`skia-kit/science.mjs` 里补的那段（把 `m_*.png` 喂进 `__MK_MOUTHS`）**保留**：
它与画面无关，重开贴片时直接可用，也让两个宿主行为一致。
