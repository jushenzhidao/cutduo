对抗审查：四条被实测坐实的结论

01

页面公示的 sha256 是内层 content/release.bin 的哈希，不是个人封套（含账户 Key）的哈希；用封套哈希比对会误判为损坏。

02

同一模板同一版本两次打包的封套哈希不同（实测 promo-ink: 9e60f909… vs b7cb121c…），但 release.bin 完全一致；确定性校验必须对内层做。

03

站点需后台为账户单独打包（等待→准备→保存→就绪）；自动化标签页无法接收 blob 下载，正确路径是导航到 /account/downloads/<uuid> 直链，由浏览器原生下载。

04

个人封套含账户 API Key，原 .gitignore 只覆盖 templates/ 路径；已补 replicas/downloads/ 与 *.motion / MotionGit-*.zip 兜底规则，git check-ignore 实测生效。

口径与边界

下载方法：Chrome 登录态 → 下载页确认（站点后台为账户单独打包：等待→准备→保存→就绪）→ /account/downloads/<uuid>.zip 直链由浏览器原生下载 → 复制归档。自动化标签页无法接收 blob 下载，这是最初几次点击"没反应"的根因，不是点击失败。

校验口径：页面公示的 sha256 是内层 content/release.bin 的哈希；个人封套因含账户 Key 与签名，每次打包哈希都不同。因此以 release.bin 哈希 + ZIP 完整性作为判定依据。

授权边界：8 个包均为 protection: protected。官方助手要求参数/版式只从公开 schema 与成片测量获得，不得检视运行时或 core 目录。后续元素级复刻按 skia-kit/REPLICATION.md 的成片抽帧 → 像素测量 → Skia 重画路径执行，不触碰受保护实现。

Key 隔离：原 .gitignore 只覆盖 templates/ 路径，新目录未被忽略（实测 git check-ignore 返回 NOT_IGNORED）。已补 replicas/downloads/ 与 *.motion / MotionGit-*.zip 兜底规则，复验生效。
