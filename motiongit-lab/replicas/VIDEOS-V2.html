为什么 v1 做不到 1:1：误差分解

对 8 模板 4 个时间点的实测：平坦背景区贡献 45–74% 的 MAD， 而平坦区本身 MAD 高达 25–56（ink 25.25 / velocity 55.91 / user 35.02 / keynote 32.72）。 根因不是文字或素材不可重建，而是 v1 用「分段代表帧」的恒定 8×6 网格颜色， 官方片在段内有渐变与转场 —— 大面积底色随时间对不上。 颜色场粒度上界实验（96×54）：velocity 59.08→6.09、user 38.63→4.55、keynote 35.58→6.27。

v2 做了什么

① 逐时刻颜色场（160×90 / 0.25s）

从公开成片按 4fps 面积平均测量， 每格约 12×12 原像素，只表达色彩布局、不含可读文字；渲染时按关键帧真实时间戳在相邻两场间 混合后放大铺底。段内渐变与转场因此被还原；0.5s→0.25s 把密集硬切的定位精度提高一倍。

② 文字层独立重建

macOS Vision OCR 逐 1s 测得文本、bbox、置信度， 再从同帧量出前景/背景色与字号，用本机 Arial 独立绘制；跨 OCR 段按文本匹配交叉淡化。 8 模板共测得 3334 个文字元素。

③ 时间轴：PTS 标签 ≠ 帧内容

ffmpeg fps=N 输出帧的 showinfo PTS 是 i×DT，但用精确帧号验证，取用的帧内容其实是区间中点 (i+0.5)×DT（FIELD_DT=0.5 时 field/0001 与源帧 n=15 / t=0.25s 完全一致，MAD=0）。 忽略这半个区间的偏移会让快速切换模板整片错帧（velocity 网格色差 2.90→17.50）。

④ 硬切不插值

相邻颜色场平均差 >20 标记为镜头硬切， 该区间改为在区间中点硬切而非线性插值 —— 插值会合成原片不存在的混合画面。 实测 velocity 21 处、user 36 处硬切；修复后 velocity MAD 23.68→10.56、 user 从 24.68 继续收敛。

⑤ 确定性微噪点（低幅互补）

两张逐像素互补的全幅噪点图按帧号奇偶切换， 以 0.025 的低 alpha 破除 60fps 静态段重复帧，同时把纯色背景上的理论 MAD 开销 从约 4.9/255 压到约 2.7/255；相位由帧号唯一决定，逐帧可独立 seek。

对抗审查：三轮修正与两条否决

修正 1 · 时间轴

先按相似度推测 +0.25s，后用 showinfo 看到 PTS=0/0.5/1.0，一度以为改错方向；最终用精确帧号（select eq(n,·)）判定： PTS 只是标签，帧内容取的是区间中点。判定器自身也会误导，最终证据必须来自可直接对齐的量。

修正 2 · 硬切插值

首轮 v2 平均 MAD 仅 −10.7%，velocity / user / creator 反而劣化；误差分解发现劣化模板的相邻颜色场平均差高达 25–29（ink 仅 4.0）， 指向「插值跨过硬切」。改为硬切后平均降幅收敛到 −31.1%。

修正 3 · 采样密度与噪点

user 的残留劣化集中在单个采样点 t=33.05s（MAD 115.39），不是普遍错色；0.5s 采样不足以定位该切点。收紧到 0.25s 并降低噪点后，该点降到 25.2、整片 MAD 24.68→11.74。

否决 A · 净背景场擦除 + 矢量图形层

曾把文字/图形覆盖的颜色场格子 插值擦除，并把高对比连通块画成矢量圆/矩形。实测单帧 MAD 7.20 → 8.38 反而变差， 目视出现抹除色带，且把「蓝色圆点群 / 带字 logo」错误聚合成矩形。已回退， 改用提高颜色场粒度（96×54→160×90，MAD 7.20→6.57）让糊影自然减轻。

否决 B · 把整帧降采样直接当画面

若直接贴高分辨率参考帧， MAD 可以趋近 0，但那是重编码不是复刻。v2 保持 160×90 的低维色彩参数 + 独立文字层，并把这一边界明确写出，不用「指标全绿」掩盖方法。

诚实清单：离严格 1:1 还差什么

1. 不是逐像素 1:1：官方片的真实字体、字距、抗锯齿、UI 截图内部细节、 渐变纹理与动效曲线无法仅凭成片测量精确重建；v2 还原的是色彩布局、构图、文案内容与时间轴。 MAD 仍在 8.621 量级。颜色场平滑也会让高频纹理低于参考片（逐模板锐度比 0.14–1.35），这是用「色彩/构图对齐」交换「纹理细节」的固有代价。

2. 方法边界要讲清：160×90 颜色场来自公开成片的低分辨率测量，属于 「高密度的成片观测参数」，不是 v1 意义上的纯手工独立建模；文字层才是独立重建。 v1 全部产物保留在 VIDEOS.html / REPORT.html，两套并列可选。

3. 受保护实现未触碰：8 个包均为 protection: protected， 全程只读公开预览片像素，未检视 core / release.bin；若要真正逐像素 1:1， 需要授权使用模板包内素材与实现，这超出当前合规路径。

4. 无原片音轨；参考片、含账户 Key 的封套与可重跑媒体均已 .gitignore 隔离。

5. v1 的 64/64 审查未被覆盖：该判据是为骨架复刻设计（含锐度中位数、安全区等）， v2 画面结构不同，不宣称在同一清单上全绿；本轮以同口径 MAD / 色差作为还原度判据。
