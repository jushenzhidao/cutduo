# tools/knowledge · 内容模型（6 母版 × 4 时长档）

这层 **不做视觉**。它回答三个问题，然后把片子交给已有版式渲染：

1. 这个选题有多复杂？→ 五项打分 → 推荐时长档
2. 这个母版在这一档该有哪几拍？→ 按 priority 裁拍，不是均匀压缩
3. 写好的稿子有没有走样？→ 拍数 / 时长 / 钩子位 / 段长 / 文案密度

> 不在 `kits/` 下：那里每支目录都必须是可渲染版式（`tools/smoke.sh` 会查 capabilities 一致性）。
> 这里没有渲染器，只产骨架给 `kits/science`、`kits/paper` 等。

来源：`andyhuo520/vibe-knowledge`（MIT）的 `references/01-templates.md`（6 母版）、
`13-duration.md`（4 档时长 + 复杂度打分）、`11-absorbed.md`（对位硬规则）、`14-pitfalls.md`（坑）。
**只蒸内容模型，不蒸它的 44 套视觉实现与 `cine` 引擎**——那部分是 DOM + three.js + playwright，
与本仓 Skia 直出重复且更慢（判据见 `docs/vibe-knowledge-蒸馏-2026-11-14.md`）。

## 用法

```bash
# 1. 先算复杂度（五项各 0–2：概念数 / 前置知识 / 因果链 / 证据密度 / 分歧反转）
node tools/knowledge/new.mjs --score 1,0,2,2,1
#   复杂度 6/10 → 中等 · 推荐「标准」

# 2. 生成骨架（可直接渲染，args 是占位文案）
node tools/knowledge/new.mjs --template A --tier 标准 \
  --title "本福特定律" --sub "为什么假账总被数字 1 出卖" -o content/knowledge-bfd.json

# 3. 换文案 → 审查 → 渲染
node tools/knowledge/new.mjs --audit content/knowledge-bfd.json
node render.mjs --kit science --params content/knowledge-bfd.json --out out/bfd.mp4
```

## 六种母版

| 代号 | 母版 | 适合 | 惯例时长 | 首选版式 |
|---|---|---|---|---|
| A | 猜谜概念片 | 抽象概念（熵、本福特定律、贝叶斯、相变） | 3:30–4:30 | science |
| B | 两难选择片 | 历史事件、博弈论、心理学实验 | 定长 2:55（系列化） | paper |
| C | 痛点原理片 | 日常困扰 × 冷门物理/心理学原理 | 2:00–2:30 | science |
| D | 一条主线片 | 学科体系、技术史、器物身世 | 约 3:00 | paper |
| E | 闯关片 | 考试题型、方法论、流程 | 4–6 分钟 | clay |
| F | 六面轮转片 | 哲学流派、观点对比 | 45–60 秒 | paper |

A 与 B 有完整拍表（上游逐拍给了"做什么 + 画面"）；C–F 上游只给流程，这里如实保留为 `flow`，
没有替它编拍表。

## 四档时长与裁拍

| 档 | 时长 | 字数 | 拍数 | 能讲到 | 要砍掉 |
|---|---|---|---|---|---|
| 速览 | 45–60 s | 250–360 | 5–7 | 钩子 + 结论 + 一个例子 + 回问 | 前情、出处展开、对照组 |
| 精讲 | 1:30–2:00 | 500–720 | 7–9 | 主线 + 1 个关键证据 + 1 次反转 | 第二条证据、历史对照 |
| 标准 | 2:30–3:00 | 820–1080 | 10–12 | 主线 + 2–3 证据 + 反转 + 对照组 + 回问 | 次要环节、两说并列只留一处 |
| 深挖 | 3:30–5:00 | 1160–1800 | 14–20 | 完整因果链 + 两说并列 + 误区纠正 | 基本不砍 |

**裁拍按 `priority`**（1 必留 / 2 可砍 / 3 先砍），不是按比例压缩。短档砍到只剩必留拍时，
说明这个选题撑不起这么短——该换选题或换档。深挖档用 `expand` 把可展开的拍拆成两拍。

## 两个必须知道的实现细节

**1. 拍长 ≠ 段长。** 母版一拍 12–16 s，而 `science`/`paper` 这类静态版式单段超过 8 s 就是死画面。
实测：1:1 映射时 `freezedetect` 报 **15.6 s 静止**；按 ≤8 s 自动拆段后降到 **6.6 s**，门禁 PASS。
所以骨架里 `beat` 字段指向母版拍，`dur` 是渲染段——一段拍可能对应 2–3 个渲染段，拆段处 note 写明"接着上一段写"。

**2. 拍长按 role 加权。** 冷开场 0.65、章节 1.15–1.2、片尾 0.6——均分会让钩子拖沓、章节仓促。

## 审查会拦什么

| 级别 | 判据 |
|---|---|
| FAIL | 拍数不在档位区间；总时长不在档位区间；各段 `dur` 之和 ≠ `durationSeconds`；未知母版 |
| warn | 首段不是钩子位；文案密度 <2.5 或 >8 字/秒；单段 >8 s；画面字超长像整句 |

审查只判**结构**，判不了"讲得对不对"。事实核查仍然要靠 `facts.md` 式的出处台账 +
`node src/gate.mjs --ocr --expect "…"` 验证屏幕字。
