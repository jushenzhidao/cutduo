# iso 拆解片 · 素材接收清单

> 目的：一次说清"发什么素材能让拆解更准"，避免来回猜。
> 拆解片需要两份数据，来源完全不同：**几何表**（层×件×尺寸×位置）来自素材；**镜头表**（每拍时长、
> 机位、转场、字卡）来自导演判断，素材帮不上。

## 一、素材效用分级（按"能消掉多少猜测"排）

| 档 | 素材 | 能读到什么 | 还要我猜什么 | 效用 |
|---|---|---|---|---|
| A | **爆炸图 / 装配图**（iFixit 式线稿或实拍爆炸图） | 分层顺序、每层有哪些件、件的相对位置与叠压关系 | 绝对尺寸（用外廓尺寸等比反推，误差 5–10%） | 最高，一支片从十几轮改到 2–3 轮 |
| B | **拆机视频**（30s 以上，能看清先拆什么） | 层的顺序、谁盖谁、有无隐藏层（屏蔽罩、排线、支架） | 全部尺寸、件的准确位置 | 高 |
| C | **多角度外观照**（正/背/侧/45°，带尺寸标注更好） | 外廓比例、厚度、圆角、按键与开孔位置 | 内部层级与零件（仍需常识建模） | 中 |
| D | 官方规格 + 一张主图 | 三围、重量、卖点数字（做字卡用） | 几乎全部几何 | 低（= 现在这条路） |
| E | CAD / STEP / 工程图 | 直接转几何，不用建模 | — | 最高但基本拿不到 |

**素材的第二个用途：验收基准。** 现在 gate 只能证明"不空、不黑、帧数对"，证明不了"结构对"。
有 A 档素材就能加一步：渲染的爆炸静帧与素材爆炸图并排对照，核层数、层级顺序、缺件——这是目前
完全没有的能力。

## 二、硬边界（预期管理，先说清）

引擎只有三种凸块：`box` / `cyl` / `prism`，靠 `r` 参数做倒角。

- **没有曲面**：弧面玻璃、渐变曲面、编织纹理、镜头球面都做不出来；
- **没有贴图**：材质是纯色 + 面明暗 + 描边；
- **没有零件级细节**：螺丝、焊点、排线走线、注塑天线带不建模。

⇒ 即使给到几百件的零件级爆炸图，能吸收的是**分层结构与主要件**（20–70 件量级），不是逐件复刻。
这个预期不提前对齐，出片一定会"觉得不像"。

## 三、素材不解决的部分

镜头表、每拍时长、转场选择、字卡文案、配乐与音效——全部是导演判断，与素材无关。
素材只让"画的东西对不对"变准，不会让"讲得好不好"变好。

## 四、发素材时的最小信息

```
产品：      名字 + 一句话定位（是什么 / 卖点是什么）
外廓：      长 × 宽 × 厚（mm）—— 三个数就够，我用它反推所有件
结构：      能数出几层就写几层（"屏幕/主板/电池/中框/后壳" 即可）
素材：      放到 refs/<产品slug>/（该目录不入库，只在本地）
片型：      时长 / 配色（dark 深色柔光 或 split 灰橙）/ 要不要配乐
```

## 五、拿到素材后我的流程

1. **几何草稿**：读素材 → 写 `parts / layers / arrays / hero / mech`，然后：

   ```bash
   # 统一比例尺正交三视图（正/侧/俯 + 尺寸线），和素材照片并排核外廓比例
   node tools/iso-ortho.mjs --params content/<片>/params.json --out out/ortho.png
   ```

   这张图同时会对账 `content.bounds`：手写常量偏大 6–7% 是常态（两支现成片都偏），
   偏差 >2% 会红字告警。再配一张爆炸静帧核层级顺序；
2. **确认**：你只需回"层对不对、哪几层要单独展示"；
3. **镜头表**：我定 9–12 拍（亮相→升起→爆炸→逐层→特写→阵列→合拢→收尾）与转场；
4. **出片**：gate（完整性/响度）+ pacing（hold 判据）+ 抽帧拼图；
5. 有 A 档素材时，加一步渲染爆炸帧 vs 素材的并排对照。

## 六、反而没用的素材

- 纯营销渲染图（只有外观，零内部信息）—— 等于 C 档以下；
- 分辨率低到看不清分层的爆炸图 —— 会让我猜错层数，比没有更糟；
- 被裁切/带水印的图 —— 边缘与开孔位置失真；
- 只给名字不给尺寸 —— 比例靠猜，出片"看着像但比例不对"。
