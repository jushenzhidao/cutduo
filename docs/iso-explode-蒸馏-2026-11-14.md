# iso-explode-film 蒸馏（2026-11-14）

> 对象：`Warrickchenxin/iso-explode-film`（等轴爆炸大片 skill，51 文件 / 2.2 MB / JavaScript + Python）
> 判据：本项目「半蒸馏」标准 —— 上游是**版式枚举**还是**机制参数**；换宿主能否讲新内容。
> 用途口径：**实体产品的拆装广告片**（硬件、结构、机构；30 秒量级，无口播）。

## 一、结论

1. **它是「内容模型 + 几何渲染器」，不是模板。** 核心资产是三样：一份把产品写成「层 / 阵列 / 核心件 / 机构」
   的 SPEC、一套把通道（lift / ex / burst / pull / split / hover / act）映射到零件位移的骨架、
   一支按分镜生成机位与字卡的时间线。视觉代码（SVG + Chrome 截图 + numpy 合成）对本仓零价值。
2. **整条链可以压进 Canvas2D。** 上游每帧走「Chromium 截图 → OpenCV 透视 → numpy 运动模糊 → PIL 字卡」，
   本实现把投影、面、排序、明暗、桌面、阴影、标注、字卡全画在一个 Skia ctx 里：**同一支量级从 0.3 帧/秒到 123 帧/秒**。
3. **不能照抄的是"常量"，不是"结构"。** 上游的机位、焦距、最近距离是按一张产品广告照片反推后**冻结**的；
   换产品就不成立。本仓改成「按主体包围盒反算」——这是本次最重要的一次改写（§四.1）。
4. 许可证 MIT（`LICENSE` + `THIRD_PARTY_NOTICES.md`，等轴测部分基于 Anatomy 工具包）。按用户要求不做协议
   约束，但实现仍是重写：结构同构、代码独立，没有整段移植。

## 四、三条不可平移（实测，不是推断）

### 1. 机位不能是常量表

上游 `look.md` 给的是一组**冻结**的机位：HERO `yaw −27.186° / pitch 54.53° / roll 9.49° / zoom 2.687`，
焦距 `3.6328 × 1003 px`，相机最近 `450 mm × radius/270`。这些数字是按一张产品广告照片反推出来的，
对所有产品复用；但**核心件被 pull 抬走 26 mm 后，同一组数字会把主体顶出画面**（本仓实测两轮：整帧空白、
只剩顶壳边缘）。

改法：每个镜头先取主体（整机 / 核心件 / 某阵列 / 某一层），按当前通道状态求世界包围盒 → 试投 →
反算 `zoom = min(fill·W/bw, fill·H/bh)` 与 `pan`；核心件镜头再补「当前 − 取景时」的高度差。
这一改让"换产品"从改代码变成改 JSON。

### 2. 遮挡顺序不能按面心深度

顶壳是 152×74 的大板，面心深度被 x/y 拉低 ⇒ 电芯（在其下方 7 mm）反而被判定更近，画到顶壳上面。
上游用「两两分离平面 + 姿态预算」解决；本仓每帧对零件对做分离轴测试，得到偏序图再拓扑排序。

两种"看着合理"的兜底都试过，都错：
- **互穿时按深度补边** → 造出环（实测 32 条边被违反，顶壳与电芯互相压）；
- **有环时把剩下的按深度插回** → 打乱已经排好的顺序（64 条边被违反）。
现在的规则是：两轴结论相反（屏幕上本来就分开）或三轴全重叠（互穿）**都不建边**，环只可能来自真互穿。

### 3. 桌面不能进三维投影

上游把桌面当三维平面画（每像素反投影回 z=底面），透视与投影都对。本仓特写镜头 `D ≈ 2.6R`，
6R 见方的桌面远端落进相机背后，透视除法把坐标翻到另一侧 ⇒ **橙色铺满整帧**（实测）。
改成屏幕空间一条斜线（`lx = 0.58W`，字卡永远在灰侧）：这只剩"摄影棚背景"的语义，不需要三维正确。

顺带一条：**运动模糊不可平移**。上游甩镜用最多 12 个子帧合成，中间帧看不出零件交错；我们没有子帧合成，
只能靠"先合层再甩镜"（0.2 s 合层，0.16 s 后开始甩）把穿模窗口压掉。


九种镜头全部实现：`hero / rise / explode / part / action / array / stack / assemble / end`。

### 2. 实测数字

| 项 | 上游（8 核笔记本，自述） | 本仓（15 worker） |
|---|---|---|
| 片长 | 30 s × 2 版（900 帧 ×2） | 27.3 s（1638 帧） |
| 耗时 | 1.5–2 小时 | **13.3 s** |
| 吞吐 | ≈0.25–0.33 帧/秒 | **123 帧/秒** |
| 单帧成本 | ≈3.3 s（浏览器截图 + numpy 合成） | **8.1 ms** |

差距两个数量级，来源不是优化技巧，是**管线形状**：上游每帧都要起一次页面、截一次图、算一遍逐像素透视；
本仓一帧就是一次 `ctx` 调用。上游的代价换来的是运动模糊与真实透视 warp——本仓用更简单的针孔投影替代。

交付门禁：两版均 `PASS`（空帧 0.0% / 黑帧 0.0% / 帧数 1638/1638 / freeze 1.6s / −17.0 LUFS）。
`--require-audio` 也过：19 条音效事件（whoosh 转场、impact 落位、tick 按压、rise 飞散）+ 代码合成配乐。
节奏体检：`0/9 段不达标`（hold 最小 30f、p50 38f；最长静止 1.47s）。
smoke：`PASS iso 1169237 bytes`；段型契约 `9 == 9`；API `validate` 无告警。

### 3. 示范片交付（两版）

| 版本 | 文件 | 体积 | 说明 |
|---|---|---|---|
| 橙色桌面 | `out/iso-powerbank.mp4` | 3.7 MB | 灰橙分割背景 + 暖色投影 + 两个参照方块 |
| 深色柔光 | `out/iso-powerbank-dark.mp4` | 4.7 MB | 同一套动画，`ISO_LOOK=dark`；深底 + 四块柔光 + 冷色亮边，整片色调压 18% |

音频：`tools/synth-bgm.mjs` 代码合成（122 BPM，Am 进行；drop 自动落在爆炸开头 5.4s），
另加 19 条内置音效事件（转场 whoosh、落层 impact/tick、飞散 rise、收尾 impact）。

直接归一会顶到 −0.2 dBTP（实测），成片过不了 −0.5 dBTP 那条线。

## 六、已知未做 / 弱项（如实记）

1. **`array` 与 `stack` 两镜偏弱**：电芯这类"薄而小"的层，按自身包围盒取景后，上方巨大的顶壳仍会闯进画面；
   `stack` 在 pitch 11° 下只剩两条板。上游靠更低机位 + 运动模糊掩盖，本仓没有子帧合成。
2. **没有穿插检测**：`scan.mjs` 的等价物（逐帧两两求分离平面）没做。当前策略是"排序器对互穿不建边"，
   互穿时画面会随机破面——属于内容错误，靠建模纪律兜（README 已写明）。
3. **`dark` 配色只实现未验收**：`looks.dark` 有深色底 + 四块柔光 + 冷色亮边，但示范片只跑了 `split`。
4. **配乐未移植**：上游是代码合成（Am–F–C–G / 120 BPM / tap·whoosh·thud 六种提示音）。
   本仓示范片无声；要配乐走 `params.audio` 或 `tools/audio-bed.mjs`。
5. **字卡偏重**：上游鸿蒙 Thin 150px，本仓 132px NotoSC Regular。可考虑给 iso 引一套更细的 CJK 字重。
6. **几何仍然要人写**：CAD/网格清单脚本（`cad_inventory.py` / `mesh_inventory.py`）没移植；
   当前从 JSON 手写零件（示范件 40 件，约 20 分钟）。上游的 84 / 480 件规模靠脚本+rig，本仓还没到那一步。

## 七、值不值得继续

**值得。** 这支版式补的是本仓完全没有的一类画面：**"实体结构"**。现有 8 支版式全是平面排版/界面，
讲"电池怎么装、按键怎么响、光怎么导"只能靠文字；iso 能把这些直接画出来，且不需要任何素材（不贴图）。

下一步优先级（按性价比）：
1. `array` / `stack` 两镜重新取景（把非主体的层临时排除出取景包围盒，或给这两镜单独的"近摄"通道）；
2. `dark` 版跑一遍验收（同一份 content，`look: "dark"`）；
3. 把 `cad_inventory.py` 的思路接进来：从零件清单生成 `parts[]` 骨架，人只调材质与层。
