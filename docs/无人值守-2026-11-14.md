## 四、T3：偏离原计划（重要）

**原计划**：新建 `kits/dataviz` 独立版式。
**实际做法**：在 `paper` 里加 `chart` 段型（line / bar）。

**理由**：图表是**内容呈现方式**，不是**视觉语言**。新建一支版式会把纸感背景、字幕、关键词卡、字体注册全部复制一遍，而图表本身只关心数据。本仓的架构是「一支版式 = 一套视觉语言」，所以图表应该是一个段型。

`guide.json` 里 `pairing.G` 已从 `dataviz` 改为 `paper`，并附了这条说明。

### 实现

```json
{ "type": "chart",
  "args": { "chart": "line", "title": "1880–2024 全球平均气温",
            "series": [{ "label": "全球", "points": [[1880,-0.16], ..., [2024,1.28]] }],
            "axis": { "xFrom": 1880, "xTo": 2024, "yFrom": -0.5, "yTo": 1.4 },
            "notes": [{ "at": [2024,1.28], "text": "2024 最热", "side": "left" }],
            "at": 0.3, "stagger": 0.28,
            "caption": "示意数据 · 相对 1951–1980 均值" } }
```

- 轴先长出来（`at-0.45 → at+0.15`），再落点——**顺序本身就是"图表在被画"**。
- 跨零时自动画零线（虚线）。
- `line`：点按顺序落下并连线，注释钉在指定点上（抖动虚线 + 不闭合感）。
- `bar`：柱子从基线长出，`emphasis` 指定强调色；**x 轴不画数字**（类目标签已在柱下，否则重叠）。

### 两个已知问题

1. **`chart` 段的 `freeze` 会被严重高估**：8 s 的测试片报 `freeze 8.0s`。原因不是画面静止，是标记点只占画面约 0.02%，低于 `freezedetect` 的 0.2% 阈值。**这是检测灵敏度问题，不是缺陷**——但这意味着 `chart` 为主的片在这条判据上不可信。
2. **y 轴刻度未必是整数**（如 1.4 / 0.8 / 0.1 / -0.5）。可以传 `axis.yFrom/yTo` 取整，但没做自动取整。

## P5 · `if/then` 校验补上（原以为只是"部分未检查"，实际是 9 条约束全失效）

`api/validate.mjs` 原先刻意不支持 `if/then/else`，理由是"宁可报 unsupported 也不静默放过"——这个设计取向是对的，但代价被低估了。

`kits/paper/params.schema.json` 用 `allOf` + 9 组 `if/then` 对每种段型分别约束必填 args：

```json
{ "if":   { "properties": { "type": { "const": "number" } } },
  "then": { "properties": { "args": { "required": ["value"] } } } }
```

**不支持 = 这 9 条全部失效**。实测：传一个没有 `value` 的 `number` 段，API 校验 `ok: true`，渲染出来是空白。

已补：

```js
if (sch.if && typeof sch.if === 'object') {
  let hit = false;
  try { hit = validate(sch.if, val).valid; } catch { hit = false; }
  const branch = hit ? sch.then : sch.else;
  if (branch && typeof branch === 'object') walk(branch, val, path);
}
```

if 的判定用一次子校验，它的 errors **不并进**当前错误（否则会刷一堆"if 不成立"的噪音）。

**正反向验证**：

| 用例 | 结果 |
|---|---|
| 正常 chart 参数 | `ok: true`，**warnings 0**（原来的 "if/then 不支持" 警告消失） |
| 缺 `value` 的 `number` 段 | `ok: false` → `/scenes/0/args/value: 缺少必填字段 value` |
| 全量 API validate（10 个 preset） | **10/10 通过**，无误报 |

# 第三轮（13:02–13:18）：跨版式可行性的实测

## 结论：**「母版 × 版式自由组合」不成立**

我之前在 `kits/STYLES.md` 写过「`paper` 与 `editorial` 段型相同，换 `--kit` 就换视觉」——**这条是错的**，已删。

### 实测过程

`paper` 与 `editorial` 的 params 结构几乎相同（只差 `audio`），于是把《生日悖论》的
`params-abs.json` 直接喂给 `kits/editorial/canvas-editorial.mjs`：

```
✓ /tmp/ed.mp4  6126 帧 / 102.1s / 1 worker
gate: 6126/6126 帧 · 空帧 0% · 黑帧 0% · freeze 3.6s · PASS
```

**一切看起来正常。** 抽帧才发现：

| 时刻 | 实际画面 |
|---|---|
| 22 s | **一片白纸**，只有角落一行字幕 |
| 50 s | 「回问」页 |
| 90 s | **与 50 s 完全相同**（后半段卡死） |

### 根因

`editorial` 的段型分发是一个 `switch`，末尾是：

```js
default: bg('paper');     // 不认识的段型 → 画一张白纸
```

`paper` 昨天新增的 `grid` / `chart` 它不认识，于是画白纸，**不报错、不警告**。

而 `gate` 只看像素统计（帧数 / 空帧 / 黑帧 / freeze / 响度），一张白纸加文字完全"正常"，
6126 帧全部通过。

### 修复

`default` 改为抛错：

```
Error: editorial 不支持段型 "grid"。支持：hero / point / number / compare / steps / quote / checklist / outro。
（grid / chart 是 paper 的段型，editorial 没有对应画法）
```

正常路径不受影响（`inputs-v6.json` → 1131 帧 / 11.33 s）。

### 教训（这条比修复本身重要）

**JSON 结构相同 ≠ 渲染语义相同。** 静默降级（画白纸）比报错危险得多——因为门禁是围绕
"像素是否异常"设计的，它天然抓不到"像素都正常但内容错了"。

同类风险还存在于其他版式：任何版式的 `switch` 若有 `default` 兜底而不报错，都会埋同一个坑。
建议后续做一个 `tools/check-kit-contract.mjs`：把每支 kit 的段型清单与其 schema 的 enum 对表，
不一致就报错。**本次未做。**

## 顺带确认的三件事

1. **`chalkboard` / `night-card` 不能接 knowledge 的母版**：它们的参数是 `motion.json` 里的自定义 schema
   （`parameters.schema` + `defaultPreset`），与 `scenes/t0/t1` 是两套模型。所以「7 母版 × 8 版式 = 56」
   实际可用的是 **7 母版 × 3 版式**（paper / science，以及段型全部在 editorial 支持范围内的子集）。
2. `editorial` 读 `FPS = d.fps || 24`，所以 fps 不是问题；问题是段型覆盖。
3. `gate` 对"无音轨"只告警（`editorial` 输出无声片，因为它的入口不吃 `--audio`），这条设计是对的。

|---|---|

意思是「桌面演示里放照片 / 放视频片段」这两个段型，**本地能渲、走 API 会被拒**。已补进 `kits/desk/params.schema.json`。

# 第六轮（13:20–13:56）：40–45 秒画面静止

用户实测指出《本福特定律》40–45 秒画面不动。查下来是**三个独立 bug 叠加**，不是单个问题。

## 现象

抽帧算帧间平均灰度差：`40→41s 0.12`、`41→42s 0.12`、`44→45s 0.03`——基本为零。画面里只有一条极淡的弧线和字幕。

## 根因 1 · 用户写的 screens 时间被当成绝对秒（主因）

`script.json` 里 C05 的卡片写的是 `[["一万到十万", 1.2], …]`——**段内相对秒**。
但 `build.mjs` 把所有 args 一视同仁地按「实际 t0 − 骨架 t0」平移，结果：

```
cards 时间 1.2 → 71.72      （段落范围 37.79–42.86）
```

71.72 远超段末 ⇒ 三张卡片永不出现 ⇒ 只剩字幕。这也解释了为什么 C02 / C06 / C07 的画面同样偏空。

**修**：两套时间语义必须分开处理，merge 之后无法区分：

| 来源 | 语义 | 处理 |
|---|---|---|
| 骨架 args（v8t） | 绝对秒（`cards[][1]` 是 7.868，落在段 5.32–11.44 内） | 按 `t − base.t0` 平移 |
| 用户在 script.json 写的 screens | **段内相对秒** | 直接 `+ t` |

## 根因 2 · 场景空隙渲染的是「最后一个场景」

`paper` 的 `renderFrame` 原文：

```js
const sc = scenes.find((s) => t >= s.t0 && t < s.t1) || scenes[scenes.length - 1];
```

每两个场景之间有 0.25 s 空隙（gap），落在空隙里就取 `scenes[末尾]` = **outro**。
所以每个间隙都闪一帧片尾卡（实测 43.0 s 闪出「不是巧合」）。

**修**：空隙时保持**上一个已结束场景的末态**：

```js
const done = scenes.filter((s) => s.t1 <= t);
const sc = done.length ? done[done.length - 1] : scenes[0];
renderPaper(Math.min(t, sc.t1 - 0.001), sc);
```

## 根因 3 · point 段的卡片之间有 1.5 s 空档

修完前两个后，40–42 秒仍有 0.5–0.6 的微小变化。原因不是 bug——`point` 段的设计就是「小字逐张淡入」，
三张卡之间天然有空档，而卡片本身面积小，像素变化天然低。

**修**：C05 换成 `grid`（100 个点逐个落下，每点 0.034 s，约 3.4 s 铺满），
并且「数量」本来就该用点表达，比三行小字更贴题。

## 结果

| 时刻 | 修前 | 修后 |
|---|---|---|
| 40→41 s | 0.12 | **1.13** |
| 41→42 s | 0.12 | **2.19** |
| 42→43 s | 28.5（切段） | 4.82 |
| 44→45 s | 0.03 | **2.13** |
| freeze | 6.0 s | **5.2 s**（告警线 10 s） |

39→40 s 仍是 0.86（点阵在这一秒刚好出现得稀疏），属于边界情况，未再处理。

## 连带修的一个排版 bug

`pGrid` 的标题用 `(ox + (cols-1)*gap)/2` 定位，会偏到点阵左半边的中心。
正确是 `ox + (cols-1)*gap/2`。已改。

## 回归

`smoke` 22 PASS · `temporal` 92/92 · `benford.mp4` PASS / −17.0 LUFS / 台账未上屏 0 · 发布包已重出。

# 第七轮（13:26–13:46）：把「画面空着但门禁全过」变成可检查的

第六轮修了三个 bug，但留下的教训是：**这三个 bug 都能让画面"看起来正常"地空着**，
而帧数 / 空帧 / 黑帧全部通过，`freeze` 也只报 5.2 s（告警线 10 s）。观众看到的是"卡住了"。

## 为什么 freeze 不够

`freeze`（`freezedetect=n=0.002`）判的是"像素变化 < 0.2%"，即**几乎完全不动**。但实测：

- `paper` 版式的画面变化量中位 **0.29**、p10 **0**——它天然就"静"（纸背景 + 少量文字）；
- 真出问题的段落（只有一条淡弧线）变化量 **0.11**，与正常段落（0.3–4.8）**同一量级**。

两者在"动作量"上分不开。所以换指标。

## 换指标：画面信息量（灰度标准差）

只取**画面主体区**（crop 掉底部 18% 字幕区），缩到 240×105 灰度，逐秒算标准差。三档实测：

| 画面 | std |
|---|---|
| 纯纸背景（插进去的 3 秒空镜） | **0.0 – 1.5** |
| 引文页（几行小字 + 引号） | 18 – 20 |
| 常规图文版式（关键词卡 + 大字） | **56** 左右 |

阈值取 **12**、连续 **≥2 秒** 报警。只报不拦——`paper` 是留白版式，判太紧会误伤引文页。

## 实现

```bash
node src/gate.mjs out/film.mp4 --blank
```

```
ffmpeg -vf "fps=1,crop=1920:842:0:0,scale=240:105:flags=area,format=gray"
```
读 rawvideo 逐帧算均值与标准差，找连续低于阈值的区间。

## 正反向验证

| 用例 | 结果 |
|---|---|
| `benford.mp4`（修好后） | **零告警** |
| 往片中插 3 秒纯纸背景（38 s 处） | `疑似空镜 1 处（最长 38–41s，该段信息量 0.0）` |

已接进 `make.sh` 的门禁步骤（`--blank`），并在 grep 里加了「空镜」关键字——否则报了也看不见。

## 一个观察

插入 3 秒纯色后，`flat%` 只涨到 4.2（阈值 ≤8% 不拦），说明「空帧占比」这条老判据对**局部**空镜
不敏感——它只看全片比例。`--blank` 补的正是这个洞：**局部连续空镜**，不看占比。

## 回归

`smoke` 22 PASS · `temporal` 92/92 · `benford.mp4` PASS / 台账未上屏 0 / 空镜 0 处。

# 第八轮（13:30–14:25）：science 版式的第一支真内容片

## 为什么做这支

`paper` 和 `science` 是两套**平行**的段型体系（16 种段型、完全不同的 args）。
在此之前只有 `paper` 被真内容压过。`science` 若不能被母版驱动，它就只能当 demo。

## 《抗生素的另一面》（C 母版 × science，62 秒）

选题由版式倒推：`science` 的图标是**医学科普专用**（只有 gut / hip-joint / drop / radiation / shield / check / clock 七个），
所以必须选一个能用 `gut` 讲的题。「抗生素为什么会让人拉肚子」正好：机理清楚、图标对得上、是高频经历。

7 段 / 273 字：cover → talk → talk → **diagram** → talk → tip → outro。

**成品**：`out/gut-antibiotic.mp4` — 1862 帧 / 62.1 s / PASS / −16.2 LUFS / freeze 4.4 s / 空镜 0 处 / 台账 6 条。

## science 与 paper 的结构差异（不能复用一个 build）

| | paper | science |
|---|---|---|
| 段容器 | `scenes` | `segments` |
| 时间 | 显式 `t0/t1` + 链式 `@prev` | **只用 `dur` 累积** |
| 时间轴语义 | 绝对秒 | 相对累积 |
| 段型 | hero/point/number/grid/chart… | cover/talk/diagram/matrix/focus/tip/outro |
| 字幕 | `captions` | `captions`（同格式） |
| 顶层 | brand/accent | **还要 theme / subtitle / fadeOutSeconds** |

所以写了 `content/gut-antibiotic/build.py`（science 专用）：配音 → 统一转 wav → 拼 gap → 生成 segments + captions。

## 踩的两个坑

**1. concat 静默丢段（音画差 1.51 s）**

edge-tts 出的是 **24 kHz mp3**，段间静音是 **44.1 kHz wav**，混在一起喂 `concat` demuxer 会**静默丢段**：

```
7 段 + 6 × 0.25s gap 应得 62.05s，实际只拼出 60.55s —— 少掉全部 1.5s 的 gap
```

修：先把每段 mp3 转成统一的 44.1 kHz mono wav，再拼。没有报错，只有时长对不上——正是"静默失败"。

**2. `--blank` 把片尾卡判成空镜**

`outro` 只有两行大字，信息量 6.2，低于阈值 12，被判「疑似空镜 60–62s」。
那是版式设计不是缺陷。给 `checkBlank` 加 `skipTail`（默认跳过最后 4 秒），
自检仍有效（插 3 秒纯背景在 30 s 处 → 报「30–33s，信息量 0.0」）。

## 顺带修的两个兼容

- `render-all` 只认 `audio/mix-final.wav`（science 只有 `vo-norm.wav`），且只认 `params-chain.json`
  → 都加了回退，现在三支片全部 `✓ done`。
- `publish-pack` 只读 `params.scenes`，对 science 的 `segments` 会得出「0 段」→ 封面时刻也算错。
  现在两种容器都认，`segments` 用前缀和算绝对时刻。

## 当前三支片

| 片 | 母版 × 版式 | 时长 | 大小 | 状态 |
|---|---|---|---|---|
| 生日悖论 | A × paper | 102.1 s | 4.4 MB | PASS |
| 本福特定律 | C × paper | 68.5 s | 3.4 MB | PASS |
| 抗生素的另一面 | C × science | 62.1 s | 6.6 MB | PASS |

## 一个观察

`science` 的视觉密度明显高于 `paper`（6.6 MB / 62 s vs 3.4 MB / 68 s，同样 CRF 下码率差近一倍）——
因为它是 3D 讲解员 + 器官贴图 + 大色块，每帧都在变。这也解释了为什么它的 `hook`（开场运动）是 **0.50**，
而 `paper` 的片子只有 0.07–0.09：**paper 是静的，science 是动的**，两条线的门禁体感不会一样。

# 第九轮（13:37–14:12）：science 补配乐 + 骨架防呆 + 一个潜伏 bug

## 1. science 补上配乐层（`tools/audio-bed.mjs`）

science 片之前只有旁白——跑通链路优先，配乐留了口子。这轮补上。

问题：`content/<片>/bgm.mjs` 是 paper 专用的，它读 `scenes[i].t0`，而 science 用 `segments[].dur`，
喂进去直接读不出边界。所以写了通用脚本：

```bash
node tools/audio-bed.mjs --slug gut-antibiotic --style chillwave
node tools/audio-bed.mjs --slug benford --style electrohouse
```

- **段落边界两种容器都认**：`scenes` 有 t0 就用 t0，只有 `dur` 就用前缀和累积（含 0.25 s gap）。
- **三层曲风预设**：`electrohouse` / `chillwave` / `hiphop`，每层 4 个 loop（鼓 / 贝斯 / 和声 / 氛围），
  选曲原则是**不抢旁白**——中低频、无强旋律。
- **包络按段落推进**：开场只留鼓与和声，中段加贝斯，转折后加氛围，收尾 2.2 s 淡出。
- loop 是本机资源（`/Library/Audio/Apple Loops/Apple`），**找不到就报错并列出可用曲风**，不静默降级成"没配乐"。

science 片接上后：−16.2 LUFS、`--require-bgm` 通过（旁白间隙不再是纯静音）。

## 2. 骨架防呆：`screens` 不再给空对象

`new-film` 生成的 `script.json` 里，每一拍的画面参数原来是 `screens: [{}]`——**空对象**。
用户只能靠猜字段名，而猜错不会报"参数不对"，是一路崩到渲染函数里
（第七轮实测：`quote.lines` 写成元组、`compare.left` 写成数组，错误是 `l.replace is not a function`）。

现在直接从 `kits/paper/presets/v8t.json` 取同段型的真实结构，把时间平移成**段内相对秒**再填进去：

```json
// 改之前
"screens": [{}]

// 改之后（quote 段）
"screens": [{ "lines": ["快不是*赶工*", "是删掉重复"], "at": 0.4, "by": "视频节奏笔记" }]
```

用户拿到的是一份**能直接改的结构**，不是一道填空题。这直接消灭了第七轮踩过的那三类错。

## 3. 顺带抓到一个潜伏 bug：`number` 的 `from` 被当成时间平移

给骨架填结构时发现 `number` 段出现 `from: -11.44`。查下来：时间字段的白名单里有 `from`，但
**`from` 是「数字滚动的起点值」，不是时间**——`number` 段从 0 滚到 30.1 才对。

实测影响：

```
benford 的 number 段：t0=18.21  from=18.21   ← 错，数字从 18 滚到 30，而不是从 0 滚
```

（`birthday-paradox` 的 `from` 一直是 0，因为它的 build 是旧版本，没这条平移——两边行为不一致，更难发现。）

修：白名单改为 `at|leftAt|rightAt|strikeAt|itemAt`，去掉 `from` 和本仓未使用的 `until`。
两处 walk（`new-film.mjs` 的脚本生成、`content/benford/build.mjs`）都已改，benford 已重出。
