# lemo-opuscar 三条路试验（2026-11-14）

> 对 `lemomo-ai/lemo-opuscar`（15.7K★ / 100 种风格）的三条吸收路线做实测。
> 结论先行：**第 3 条（批量搬）比我上一条判断的轻得多，但仍不推荐；第 1 条已有 3/7；第 2 条值得做但渲染成本 2–4 天。**

## 一、先把体量摸清（这与直觉相反）

| 项 | 实测 |
|---|---|
| 仓库 clone（depth 1） | **281 MB / 16 s** |
| `core/` 代码 | **21 个文件 / 189 KB**（渲染调度 `video.mjs` 仅 8.2 KB） |
| `core/` 其余 | 12.8 MB，几乎全是 3D 素材（polyhaven 的胡桃木、台灯） |
| 单个风格 | 中位 **0.9 MB**（最大 3.3 MB，含 demo 素材） |
| npm 依赖 | **2 个包**（`playwright-core` + `three`），3 秒装完 |

我上一条说"适配 1–2 天/个"，**这个判断错了**——框架只有 189 KB，且做法与我们的 `webcanvas` 完全一致：每个 worker 开一个浏览器，JPEG 截图管道给 ffmpeg，分段无损拼接。

## 二、第 3 条：批量搬 —— 实测卡在素材，不在代码

真跑一支（`swiss-motion`，388 KB，最轻档）：

```
✓ clone 281MB / 16s
✓ npm i     2 packages / 3s
✗ 缺字体 Archivo-VF.ttf          → 手动下 Google Fonts 补上
✗ 缺字体 UnifrakturMaguntia      → 再补
✗ 缺字体 DMSerifDisplay          → 再补
✗ 仍报 pageerror: A network error occurred（未定位到具体文件）
```

**根因：素材不入库。** 它的 `build.sh` 注释写得很清楚——字体从 Google Fonts 拉，某些 demo 还要从美国国会图书馆下 100 MB 扫描图、从 HuggingFace 拉 Kokoro 语音模型、拉三套采样库（salamander / vsco2ce / vcsl）。

所以"搬一支"的真实成本：

| 类型 | 工作量 | 说明 |
|---|---|---|
| 纯代码 / 系统字体 | **1–2 小时** | 改 `--kit` 指向它的 `demo/`，套我们的 gate |
| 要外部字体 | **+0.5 小时/支** | 逐个查 `fonts.css` 补 |
| 要扫描图 / 模型 / 采样库 | **+2–4 小时/支** | 100 MB 起，且部分源站可能不通 |

**结论：技术上可行，但每支都要单独处理素材，且改不动。** 730 行 WebGL2 shader，想调一个颜色得读代码——这不是"模板库"该有的形态。

真要接，正确做法是**包成 `kits/lemo-<style>`**（走 webcanvas 路径），而不是并入我们自己的版式体系。

## 三、第 1 条：Native moves —— 7 个里已有 3 个

`swiss-motion/STYLE.md §8` 列了 7 个"只有这种媒介能做的动作"，每个都带「fits content like…」三个例子：

| # | 动作 | 我们有没有 |
|---|---|---|
| 1 | **网格即数量**（行列变成数量：楼层、时刻表、城区） | ✗ 缺 |
| 2 | **吸附即节拍**（每次到达都是一次打击） | ✓ 有——音效 cues 卡在段切换 |
| 3 | **Programme**（一套规则应用到多件物） | ✓ 有——同一版式出多支片 |
| 4 | **极端尺度对比**（巨大元素 + 小字注释） | ✓ 有——`number` 段 |
| 5 | **例外**（一个元素打破网格，线性不对齐） | ✗ 缺 |
| 6 | **刀切**（一条线删掉一个元素） | ✗ 缺（`focus` 有 strike 划线，但那是"划掉旧认知"，不是"切"） |
| 7 | **回流**（其他元素围绕变化重排，最近的先动） | ✗ 缺 |

**值得补的是 #1 和 #5**：

- **#1 网格即数量** 对《生日悖论》直接有用——253 对就是 23×11 的点阵，观众一眼能数出"这么密"。成本约 2 小时（在 `paper` 加一个 `grid` 段：`{rows, cols, highlight: [[r,c],...], label}`）。
- **#5 例外** 适合"反直觉"的段落——全班 23 个点里，有一个点颜色不同且不吸附到网格。

其余四个要么已有，要么收益不明显。

## 四、第 2 条：半蒸馏 dataviz —— 值得做，但要 2–4 天

`styles/dataviz/STYLE.md` 是这批里质量最高的，可蒸的是**内容模型**而非视觉代码：

**核心主张**：*The chart is the film.* 每个标记是真实数字，每个动作是有意义的图表操作（标记落下、轴生长、尺度变化、序列变形、注释钉上）。**你改取景，永远不改数字。**

**选图判据**（可直接变成 schema 校验）：

| 数据是关于 | 图表 |
|---|---|
| 比较类别 / 排名 | 条形、排名赛 |
| 两个量的关系 | 散点 / 气泡 |
| 地点 | 地图 / choropleth |
| 部分与整体 / 人数 | 单位图 / waffle |
| 前后对比 | 斜率 / dumbbell |
| 分布 | 直方图 / beeswarm |
| 流向 | Sankey |
| 随时间变化 | 折线 / 点列 / 条纹 / 面积 |

**三层让它成为故事而不是信息图**：

1. **人的尺度** —— 手写笔记钉在标记上（我们已有 `facts.md` 台账，每个数字有出处，天然对应）
2. **一个表演者** —— 一支铅笔画出每个标记（**我们没有**）
3. **声音化** —— 每个标记是一个音高，趋势先被听见再被读到（我们有 `earshot`，可以做）

**分镜结构**（11 拍，与 A 母版的 13 拍同构）：

```
Cold open（极近特写第一个点，≈4×）
Title（拉远到 1.55×，垂线变成 x 轴）
Early life（跟随铅笔，最新的点在 62% 画幅）
Climb（随曲线上摇，荷兰角 0→−1.5°）
Frame break（2 帧内 punch-in + 衰减抖动）
Rush（快拉回 1.0×，滚转 −3°）
The cut（硬切到空槽：虚线柱 + 2026 + 水平线）
Reveal（停在最后一点写注释，再拉回全景）
Morph（锁死镜头——变形本身就是运动）
Scale（拉到 0.72× 加入更早的纪录）
Echo（推向空格，它扩张成片尾卡）
```

最妙的是 **"The cut"** ——把"未知的下一个值"当作高潮（硬切到一个空槽）。

**落地成本**：

| 步 | 内容 | 成本 |
|---|---|---|
| 1 | `guide.json` 加 G 母版（11 拍 + 图型判据 + 三层） | 2 小时 |
| 2 | `kits/dataviz`：真图表绘制（轴、标记、尺度变换） | 1–1.5 天 |
| 3 | 铅笔表演者 + 手写注释（per-glyph jitter） | 1 天 |
| 4 | 声音化（每个标记一个音高，走 earshot） | 0.5 天 |

**这条是唯一真正符合"半蒸馏"判据的**：上游是机制参数（数据 → 图表映射 → 分镜），不是版式枚举。换内容能讲新故事，不是复现那一支。

## 五、结论

| 路线 | 判断 | 理由 |
|---|---|---|
| 1 Native moves | **做 #1 #5** | 各 2 小时，直接改善现有版式 |
| 2 半蒸馏 dataviz | **值得做** | 唯一符合判据的；先做内容模型（2h），渲染看排期 |
| 3 批量搬 | **不做** | 卡素材、改不动、每支 2–6 小时且无法统一维护 |

**顺带修正一条**：我之前说"适配 1–2 天/个"，实测框架只有 189 KB、依赖 2 个包——**代码侧 1–2 小时就够**，成本全在素材。判断方向对，数量级错了。
