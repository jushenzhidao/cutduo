# vibe-knowledge 蒸馏评估（2026-11-14）

> 对象：`andyhuo520/vibe-knowledge`（公众号《Claude Code 也能一条龙做知识短视频了》）
> 判据：本项目「半蒸馏」标准 —— 上游是**版式枚举**还是**机制参数**；换宿主能否讲新内容，还是只能复现那一支片。

## 一、结论

1. **它不是渲染引擎，是知识类短片的内容模型 + 风格注册表 + 质检规格。** 渲染走 DOM + CSS + three.js + playwright 逐帧 seek，按本项目口径属"浏览器档"，蒸它**不会带来任何速度收益**。
2. **可蒸的是四层：内容模型（6 母版 × 4 时长档）、风格注册表（44 套 × 14 字段）、音效配方（earshot 252 条）、质检判据（OCR 回读 / BGM 互相关 / 冻结检测）。**
3. **不蒸的是视觉实现**：`styles/_samples/*.js` 累计约 260 KB 手写绘制函数（单文件最大 `styles3_film.js` 42 KB），蒸了等于用 DOM 重画换掉 skia-kit 的 344 fps。

## 四、精华清单（按性价比排序）

### 1. earshot：252 条配方音效 —— 本次唯一"立刻能用"的

- 仓库 `Leonxlnx/earshot`，**MIT，4738★**，0.4.0，287 files，2026-11-06 更新（比 vibe-knowledge 活跃）。
- **不是音频文件，是配方**：`forge_v2.json` 183 条 + `forge04.json` 51 条 + `fit.json` 15 条 + `pluck.json` 3 条 = 252。纯 DSP（numpy/scipy），**无模型、无网络、无采样**。
- 每条自带实测元数据：`dur_s` / `onset_s` / `peak_s` / `end_s`（在 −1 dBFS 渲染上量的 1 ms 包络）⇒ 对齐可以按"参考点"算，不用手调毫秒。
- 命令行即渲染：`earshot sfx render whoosh_fast/crisp -o w.wav --dur 0.8 --apex 0.32`；整片一套 `earshot kit init --preset launch -o audio/kit.json` → `kit render` → `kit.lock.json`（带缓存）。
- **对本项目的直接价值**：`src/audio-mix.mjs` 现在只有 4 个合成音（whoosh/tick/impact/rise），且上游 33 个音效因发行期物理删除拿不到。earshot 补的是同一位置，且**许可证干净**。
- 上游给的角色→编号→增益→对齐表可直接抄（`references/10-earshot.md`），共 24 个角色。

### 2. 旁白对位硬规则（9 条）+ 音效时机中位数

可写进 `kits/science` 的规则表，且与现有实测互相印证（本项目切点中位 2.75s、跟句子不跟动作）：

| 规则 | 数值 | 出处 |
|---|---|---|
| 元素出现对齐锚词 | −0.2 ~ +0.1 s | 11-absorbed §一.2 |
| 最长静止 | ≤ 3 s；落位后稳 0.5–0.75 s 再离场 | 同上 .6 |
| 计数落定 | 起点 = 说出时刻 − 滚动时长；**有出处的真实数据不做中间值滚动** | .3 |
| 强调预算 | 关键词砸入 ≤4 次 / 反向镲 ≤1 / 全帧冲击 ≤3（全片） | .5 |
| 画面字 | ≤8 字关键词，同屏最多两组；字幕整句 ≤16 字、整句出入 | .7 |
| 音效总量 | 全片 ≤8 个 | 02-premium §声音.3 |
| 音效时机 | 轻触早 60 ms、敲击早 40 ms、点击早 11 ms、弹入晚 30 ms、嗖声最响点晚 37 ms、反向镲晚 42 ms | 10-earshot 末尾 |
| 语速 | 5.5–6 字/秒；句间 ≤0.35 s；拍间 ≤0.25 s | 02-premium §声音.0 |

### 3. 质检四项判据 —— 补 `gate.mjs` 的内容层盲区

现有 `gate.mjs` 只验**交付完整性**（空帧 ≤8% / 黑帧 ≤3% / 帧数差 ≤1 / 音画 ≤0.10 s）。上游 `qa.py` 验的是**内容正确性**，四项互补：

| 检测 | 实现 | 阈值 |
|---|---|---|
| OCR 回读 | macOS Vision（`swiftc` 编 `ocr.swift`）逐帧 OCR → `ocr.txt` → 对照 `facts.md` | 屏幕数字/引文必须与台账一致 |
| 冻结检测 | `freezedetect=n=0.002:d=3` | >3 s 报警（违反"最长静止"）；**>10 s 判录制事故** |
| 响度 | `ebur128=peak=true` | −14.5 LUFS 左右，真峰值 ≤ −1 dBTP |
| ~~BGM 存在性~~ | ~~与参考曲做互相关~~ | **❌ 已证伪，见下** |

> **第 4 项在本仓不成立（2026-11-14 实测）**：参考曲 `Mellow Drizzle Soft Pad`，有 BGM 的片相关只有
> 0.058 / 0.080，无 BGM 是 0.048 / 0.024 —— 有/无只差 **0.03**，抄 0.12 会把两首真 BGM 判成"没有"。
> 原因是 `gain −15 dB + 低通 + sidechain + loudnorm` 把波形改得面目全非；连"平均音量"都分不出
> （−16.9 vs −17.0 dB）。**替代判据**：旁白间隙是否存在 −45 dB 以下静音段——有 BGM 0 段 / 0.0 s，
> 无 BGM 20–22 段 / 28.7–28.9 s。这是**单向**判据（能证伪"没铺满"，不能证明"有"）。
>
> 教训：跨仓搬阈值前必须在本仓成片上量一遍。上游那个 0.12 是它自己链路下量的，换了混音链就失效。

> 唯一可迁移的是那条思路：**"存在性用证据证明，不用配置声明"** —— 比读 `params` 字段可靠。

### 4. 6 母版 × 4 时长档 —— 新 kit 的内容模型

- 母版：A 猜谜概念 / B 两难选择 / C 痛点原理 / D 一条主线 / E 闯关 / F 六面轮转。每个含拍级动作表 + 对标作品 + 关键手法（标题延后、一个主道具贯穿、结尾回问）。
- 共用手册 7 条：前 3 秒让观众参与 / 标题延后 / 一个主道具贯穿 / 每事实挂出处 / 画面字只放关键词 / 每章一句金句 / 结尾回扣开头。
- 时长：5 项复杂度各 0–2 分 → 0–3 简单 / 4–6 中等 / 7–10 复杂 → 速览 45–60 s（250–360 字，5–7 拍）/ 精讲 1:30–2:00（500–720）/ 标准 2:30–3:00（820–1080，10–12 拍）/ 深挖 3:30–5:00（1160–1800，14–20 拍）。
- **落点**：新增 `api/kits/knowledge.mjs`（`capability` + `adapter`）+ `api/registry.mjs` 一行；内容模型写 `guide.json`，参数写 `params.schema.json` 后跑 `python3 tools/gen-schema.py --write`。

### 5. 44 套 catalog + STYLE.md 七字段 —— 风格元数据

- `catalog.json` 顶层：`_how` / `styles` / `templates` / `families`。每条 14 字段：`key/no/name/en/cat/one/fit/templates/tone/keywords/sample/verified/fam/tier`。
- 家族分布：东方 7 / 暗场概念 7 / 图解与设计 8 / 剪辑与纪实 5 / 明亮流行 5 / 印刷与纸 5 / 游戏 4 / 电影感 3 = 44。**基础档 38 套，增强档 6 套**（dunhuang / qinghua / woodcut / collage / scroll / copper，依赖 Renoise 生图，约 8 积分/段）。
- `STYLE.md` 的可迁移段是「**能改到什么程度**」三段式：放心改 / 一改就变味 / 不能改。这正好补 `docs/AGENTS.md` §1.1 的决策语言——比"可改/不可改"两档更可操作。
- 注意：本项目已有 `kits/{paper,editorial,clay,collage}` 与上游同名风格，**不要按名字对齐**，上游 44 套是"长相 + 讲法"的组合，我们的 kits 是渲染宿主。

## 五、对抗审查：这份东西自身的缺陷

1. **样本只有 15 条作品，且它自己承认 7/7 头部作品没有旁白。** 它的整套规则是"给无旁白作品加旁白"的差异化路线，不是知识短片的普适定律。照抄会把差异当标准。
2. **单日发布、17 天零提交。** 内容冻结是优点（可复现），但没有维护、没有 bug 修复。把它当"事实源"而不是"上游依赖"。
3. **速度完全不可比。** DOM + three.js + playwright 逐帧 seek，属浏览器档（本项目 film-kit 实测 55 fps）。任何"用它更快"的推断都错——它省的是参数与改稿轮次，不是渲染。
4. **6/44 风格依赖商业积分。** Renoise 报价：轻 25–40 / 标准 250–300 / 旗舰 600–700 积分；第 01 期实测 246 积分。基础档 0 积分这条原则与我们一致（"能代码就代码"），但增强档在我们环境里没有对应通路。
5. **它的视觉层是"手写绘制函数集合"**，不是参数化系统。`styles3_film.js` 单文件 42 KB 是手写绘制，蒸过来等于把我们的 Skia 优势换掉。
6. **出处模型假设可查证文献。** `facts.md` 的 T1/T2/T3 分级（原始文献/权威二手/社区线索）对历史科普成立；对 AI 网关、协议适配这类主题，T1 往往是源码本身。**但"屏幕上每个数字必须与台账逐条对上"这条与题材无关，成立。**

## 六、建议顺序（最小可验证优先）

| 步 | 动作 | 可量化判据 | 成本 |
|---|---|---|---|
| 1 | earshot 接入 `src/audio-mix.mjs`，替换现有 4 个合成音 | 音效 4 → 252；对齐从手调毫秒 → `onset_s`/`peak_s` 实测值 | 半天 |
| 2 | `gate.mjs` 加三项（OCR 回读 / BGM 互相关 / `freezedetect` 3 s） | 负向自检：插黑场 FAIL、音轨截短 FAIL、健康片 PASS 仍成立 | 半天–1 天 |
| 3 | 新增 `kits/knowledge`：蒸 6 母版 + 4 时长档 + 对位 9 条，视觉复用现有模板 | 同一选题能出两种母版、两种时长，且过 `gate.mjs` | 2–4 天 |
| 4（可选） | 44 套 catalog 做成风格注册表 | `describe` 能返回可选风格与母版搭配 | 1 天 |

**不建议做**：整体搬迁 `cine` 引擎或 `styles/_samples`。收益是"多 44 种长相"，代价是丢掉 Skia 直出的速度与确定性，且要重写 260 KB 绘制函数。

## 七、落地结果（2026-11-14 当日）

| 步 | 状态 | 产出 | 实测 |
|---|---|---|---|
| 1 earshot 音效 | ✅ | `src/audio-mix.mjs`、`tools/esfx-render.py`、`tools/esfx-warm.mjs`、`docs/音效-earshot-2026-11-14.md` | 252 条入库；出片 7.9 s → 13.0 s（首次）→ **8.3 s（缓存后）**；内置音路径 md5 一致 |
| 2 门禁判据 | ✅ | `src/gate.mjs`、`tools/ocr.swift`、`tools/facts-check.mjs` | 五项内容层判据；26 支片新旧判定 **0 支不一致**；见下"证伪" |
| 3 内容模型 | ✅ | `tools/knowledge/`（`guide.json` + `knowledge.mjs` + `new.mjs`） | A 母版标准档：12 拍 / 30 段 / 165 s → 4950 帧 / 18.0 s / gate PASS |
| 4 风格注册表 | ⬜ | — | 44 套 catalog 尚未落到 `describe`；等有第二个风格需求再做 |

第 2 步最终落了五项判据（原计划三项，另加响度与台账对照）：

| 判据 | 取舍 |
|---|---|
| 最长静止 | 告警线 10 s —— 上游 3 s 在本仓会误杀 12/26 |
| BGM 铺底 | 弃互相关，改旁白间隙 —— 上游 0.12 在本仓只差 0.03 |
| OCR 回读 | 直接用，但要容错匹配（OCR 会把 `cutduo` 读成 `cutauo`） |
| 响度 | 上游 −14.5 LUFS 不采；本仓口径是 loudnorm **−16**，实测 5 支全落 −15.9 |
| 台账对照 | 上游的 `facts.md` 结构直接可用；反向清单必须滤时间码/分辨率/章节号（滤前 22 个 → 滤后 11 个） |

**第 2 步推翻了两条上游阈值**（这是本轮最有价值的结论）：

1. **「最长静止 ≤3 s」在本仓不成立。** 26 支成片实测：最长 8.5 s，12 支超过 3 s，且 showreel 的 8.5 s 静场是刻意版式节奏。告警线改 10 s（= 实测最大 + 1.5 s 余量），26 支 **0 支触发**。这与当年 hook 0.5 误杀 13/19 是同一类错误——上游的线是它自己片子上的分布。
2. **BGM 互相关 ≥0.12 在本仓证伪。** 有 BGM 0.058 / 0.080，无 BGM 0.048 / 0.024，有/无只差 0.03；平均音量也分不出（−16.9 vs −17.0 dB）。**改用旁白间隙**：有 BGM 0 段静音，无 BGM 20–22 段 / 28.7 s。

第 3 步还暴露一条结构性约束：**母版拍长 ≠ 渲染段长**。母版一拍 12–16 s，而 `science`/`paper` 这类静态版式单段超过 8 s 就是死画面——1:1 映射实测 `freezedetect` 报 **15.6 s**，按 ≤8 s 自动拆段后降到 **6.6 s**。这条约束上游没有（它的 `cine` 每拍内有多次画面变化），是本仓版式能力决定的本土化改动。
