# 出片案例库

> 每次出一支片，跑一次 `node tools/case-loop.mjs <slug>`，自动生成一份案例并追一行留痕。
> 本目录是**无人值守任务的原始记录**：读数、审出的问题、修法、复测结果都在里面。

## 怎么用

```bash
node tools/case-loop.mjs sample-1000          # 审一支：门禁 + 节奏 + 读屏幕三类检查
node tools/case-loop.mjs sample-1000 --quiet  # 只写文件
```

产物：
- `docs/cases/<slug>.md` —— 这支片的案例（读数 + 自动审查 + 人工留痕区）
- `docs/cases/LOG.md` —— 追加式时间线，一行一次

退出码 `0` 无硬缺陷 / `1` 有硬缺陷 / `2` 输入错误。可以挂进 CI。

## 它查什么

| 层 | 检查 | 来源 |
|---|---|---|
| 完整性 | 帧数 / 空帧 / 黑帧 / 音画差 / 响度 | `src/gate.mjs` |
| 节奏 | 最长静止 / 段末落位停留 / 归因 | `tools/pacing.mjs` |
| 事实 | 台账 → 屏幕（有没有上） + 屏幕 → 台账（有没有出处） | `tools/facts-check.mjs` |
| **同屏重复** | 相邻段画面均差 <1.0 判雷同 —— 同拍拆两段却共用一份 screens | 本工具 |
| **章节号** | 卡面 `NN / MM` 的 MM 必须等于拍数，不能是子段数 | 本工具 |
| **字幕覆盖** | 文案逐句与屏幕文字做 LCS 比对（容忍 OCR 单字误识） | 本工具 |
| 语速 | 每拍字数 ÷ 该拍配音真实时长 | 本工具 |

**它看不到什么**（必须人眼看帧）：构图是否平衡、语义是否自洽、柱子有没有画出界、颜色对比够不够。本轮就有一条硬缺陷是人工看帧才发现的（见 `sample-chart.md` 的 pChart 基线 bug）。

## 缺陷台账（按类）

### 1. 同屏重复（4 支旧片，已全部修复）
现象：同一拍被 `ceil(dur/7)` 拆成多段，但只写了一份 `screens`，第二段从 0 重放入场动画。
证据：`info-check` 42.64s 与 48.94s 两帧平均差 **0.14**（同一帧级别）。
修法：给每拍补第 2 份 `screens`，**并且必须换 `cast`（大卡文字）**——只换正文实测只差 0.18% 像素，
观众看到的还是同一块绿卡。补屏后 benford +7、reno-order +7、info-check +4、selection-bias +1。
源头加固：`build.mjs` 在 `parts > screens.length` 时告警，`--strict-screens` 变硬错误。

**试过并否决**：把复用屏的元素时间整体前移 999s（让画面从"已落位"开始）。被 `auditTiming` 正确拦下
——时刻早于段起点会让元素永不出现。时间轴校验不接受负偏移。

### 2. 章节号分母 = 子段数（已修，随本轮重渲生效）
现象：7 拍的片写「05 / 14」。已在 `kits/paper` 用 `paperBeatOrder()` 改为按拍计。
本轮 4 支旧片重渲后全部显示 `NN / 拍数`。

### 3. pChart 柱基错位（已修，高，仅影响截断纵轴）
现象：柱底基线写死 `yS(0)`，纵轴从 95 起时基线落在画布外，柱子画到画面底部、穿过字幕带。
修法：`base = yS(yFrom > 0 ? yFrom : 0)`。`yFrom=0` 的常规图表不受影响。

### 4. compare 划掉线划错边（已改默认值）
原来缺省 `strikeAt = leftAt + 1.4`，等于每个 compare 都划左栏；而多数片把「正确的一侧」放左边，
划上去等于画面否定自己的论点。**已改为默认不划，要划必须显式给 `strikeAt`。**
