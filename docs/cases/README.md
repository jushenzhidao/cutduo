# 出片案例库

> 每次出一支片，跑一次 `node tools/case-loop.mjs <slug>`，自动生成一份案例并追一行留痕。
> 本目录是**无人值守任务的原始记录**：读数、审出的问题、修法、复测结果都在里面。

## 怎么用

```bash
node tools/case-loop.mjs sample-1000          # 审一支：门禁 + 节奏 + 读屏幕三类检查
node tools/case-loop.mjs sample-1000 --quiet  # 只写文件
```

产物：
- `docs/cases/<slug>.md` —— 这支片的案例（读数 + 自动审查 + 人工留痕区）
- `docs/cases/LOG.md` —— 追加式时间线，一行一次

退出码 `0` 无硬缺陷 / `1` 有硬缺陷 / `2` 输入错误。可以挂进 CI。

## 它查什么

| 层 | 检查 | 来源 |
|---|---|---|
| 完整性 | 帧数 / 空帧 / 黑帧 / 音画差 / 响度 | `src/gate.mjs` |
| 节奏 | 最长静止 / 段末落位停留 / 归因 | `tools/pacing.mjs` |
| 事实 | 台账 → 屏幕（有没有上） + 屏幕 → 台账（有没有出处） | `tools/facts-check.mjs` |
| **同屏重复（结构）** | 每拍段数 > screens 数 ⇒ 后段必然复用前段。确定性，不依赖抽帧 | 本工具 |
| **同屏重复（像素）** | 同拍各段取**段中**、只比**内容区**，均差 <0.35 判雷同 | 本工具 |
| **章节号** | 卡面 `NN / MM` 的 MM 必须等于拍数，不能是子段数 | 本工具 |
| **字幕覆盖** | 文案逐句与屏幕文字做 LCS 比对（容忍 OCR 单字误识） | 本工具 |
| 语速 | 每拍字数 ÷ 该拍配音真实时长 | 本工具 |

**它看不到什么**（必须人眼看帧）：构图是否平衡、语义是否自洽、柱子有没有画出界、颜色对比够不够。本轮就有一条硬缺陷是人工看帧才发现的（见 `sample-chart.md` 的 pChart 基线 bug）。

### 两个探测器都曾经是瞎的（2026-11-14 修正）

| 缺陷 | 旧实现 | 后果 | 现实现 |
|---|---|---|---|
| 非相邻复用 | 只比**相邻段** | 3 段拍的复用发生在第 1↔第 3 段，完全漏掉；round-window 5 处、报 0 | 结构判据 + 同拍**全组合**比对 |
| 字幕干扰 | 用**全幅**比较 | 字幕一换就判"不同"（round-window 全幅 2.21，大半来自字幕与进度条） | 只比内容区 y36–310 |
| 采样点太早 | 固定段首 **0.8s** | 元素还在入场，两边都近空白 ⇒ 误判雷同 | 取**段中**（0.55×段长，夹在 0.8–3.5s） |

**教训**：探测器的判据也要被检验。上一轮报的「全库 0 高」是假绿，真值是 round-window 5 处高缺陷。

## 缺陷台账（按类）

### 1. 同屏重复（4 支旧片，已全部修复）
现象：同一拍被 `ceil(dur/7)` 拆成多段，但只写了一份 `screens`，第二段从 0 重放入场动画。
证据：`info-check` 42.64s 与 48.94s 两帧平均差 **0.14**（同一帧级别）。
修法：给每拍补第 2 份 `screens`，**并且必须换 `cast`（大卡文字）**——只换正文实测只差 0.18% 像素，
观众看到的还是同一块绿卡。补屏后 benford +7、reno-order +7、info-check +4、selection-bias +1。
源头加固：`build.mjs` 在 `parts > screens.length` 时告警，`--strict-screens` 变硬错误。

**试过并否决**：把复用屏的元素时间整体前移 999s（让画面从"已落位"开始）。被 `auditTiming` 正确拦下
——时刻早于段起点会让元素永不出现。时间轴校验不接受负偏移。

### 2. 章节号分母 = 子段数（已修，随本轮重渲生效）
现象：7 拍的片写「05 / 14」。已在 `kits/paper` 用 `paperBeatOrder()` 改为按拍计。
本轮 4 支旧片重渲后全部显示 `NN / 拍数`。

### 3. pChart 柱基错位（已修，高，仅影响截断纵轴）
现象：柱底基线写死 `yS(0)`，纵轴从 95 起时基线落在画布外，柱子画到画面底部、穿过字幕带。
修法：`base = yS(yFrom > 0 ? yFrom : 0)`。`yFrom=0` 的常规图表不受影响。

### 4. compare 划掉线划错边（已改默认值）
原来缺省 `strikeAt = leftAt + 1.4`，等于每个 compare 都划左栏；而多数片把「正确的一侧」放左边，
划上去等于画面否定自己的论点。**已改为默认不划，要划必须显式给 `strikeAt`。**

## 出片流程已接通（2026-11-14 20:20）

以前所有检查都存在、但**没有一支 make.sh 串过它们**，等于没有。现在每个 `content/<slug>/make.sh` 长这样：

```
预检   check-beats   ← 秒级，分镜不一致直接停在渲染前（不再白渲一遍）
…渲染…
质检   tools/qc.mjs  ← 文案体检（只报）→ 门禁（硬拦）→ 案例留痕
```

`tools/qc.mjs <slug>` 是统一入口，退出码 0/1/2 可直接挂 CI。

### 接通时挖出的三个静默失效

| # | 问题 | 后果 |
|---|---|---|
| 1 | `make.sh` 末行是 `gate … \| grep -E "PASS\|FAIL"` | **管道的退出码是 grep 的**：gate 判 FAIL，grep 匹配到 "FAIL" 返回 0，`set -e` 不中断 ⇒ 出片脚本"成功"退出、坏片照样进 `out/` |
| 2 | `check-beats` 用 `process.argv[1] === fileURLToPath(...)` 判是否 CLI | 工作区经符号链接访问时两个路径形式不同 ⇒ 判 false ⇒ **静默什么都不做、退出码 0**。实测从片目录调用时预检形同虚设 |
| 3 | `check-beats` 只在 params 有 `beat` 字段时按拍分组 | 旧管线（`build.py`）不写 beat ⇒ 每个 scene 独立成组、组内 1 段 ⇒ `N>M` 永不成立 ⇒ 9 段 0 屏的片被判「没有重放」 |

三条都改成显式失败/显式兜底，并且 `gate` 新增 `--require-beats`（分镜不一致从告警改为拦截）。

### 一次回滚：改档位拍数把已有片打崩了

我把 `guide.json` 的「速览」拍数从 5–7 改成 7–9，结果 `planBeats` 给模板 A 出 9 拍，而现有脚本只有 7 拍，
`build.mjs` 取到 `undefined` 直接崩（`s is not iterable`）。

**拍数是内容契约**，改一处会让所有已写好的片失效。已回滚，只保留真正该修的语速（5.5→4.0）与字数区间。

## 文案层：`tools/narration-lint.mjs`

画面有 gate、节奏有 pacing、事实有台账，而文案此前没有任何机器约束。lint 把 13 条原则里
**能自动判的**挑出来：

- 每拍 >28 字且 screens 不够（必然拆段重放）
- 总字数 ÷4.0 与档位目标偏差 >20%
- 定义式/预告式开场、报幕式过渡、总结清单式结尾
- 单句 >35 字、连续三句同构、因果/动机词 <0.4/拍

判不了的（主线唯一性、比喻承重、数字换算、术语后置）**明确写在输出里，不假装能测**。

```bash
node tools/narration-lint.mjs --all
```
