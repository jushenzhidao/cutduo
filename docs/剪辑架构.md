# 剪辑渲染架构

> 依据：`renderd/renderd/*.py`（7621 行）、`renderd/docs/{IR,API,OPS,SECURITY}.md`、
> `cutproof/`、`motiongit-lab/`。本文只写能从代码与文档核对到的结构，不写愿景。

---

## 一、第一性原理：剪辑是一个确定性函数

把这个系统还原到底层，它要解决的问题只有一句：

```
成片字节 = f(素材内容, 时间线, 引擎版本, 字体集, 输出规格)
```

一旦承认这一点，架构上的每条分界线都不是风格选择，而是这个等式逼出来的：

| 等式里的项 | 架构后果 |
|---|---|
| 素材内容 → 必须**内容寻址**（sha256），不能用路径当身份 | 同一份素材换路径不该重渲，改一个字节必须重渲 |
| 时间线 → 必须**整数帧**，不能出现浮点秒 | 29.97/23.976 下浮点秒必然累积漂移，且不同引擎取整规则不同 |
| 引擎版本 / 字体集 → 必须进缓存键 | 否则升级后返回旧片，承诺就变成假的 |
| 输出规格 → 必须显式声明，且**不可表达即报错** | 静默降级等于替客户做了他不知道的决定 |

三条不可协商约束（`docs/IR.md` 原文）：**整数帧 · 内容寻址 · 不可表达即报错**。

## 二、七层与模块对应

层与文件的映射是硬边界：跨层只能单向调用，反过来就是设计事故。

| 层 | 职责 | 模块（行数） |
|---|---|---|
| 接口层 | HTTP / MCP / CLI 三种入口，鉴权、配额、限流 | `api.py`(468) `mcp_stdio.py`(226) `cli.py`(384) `auth.py`(199) |
| 编排层 | 幂等提交、预检、入队、领取、租约、重试分类 | `service.py`(582) `runner.py`(698) `worker.py`(97) |
| 素材层 | 探测 → 决策 → 归一化；出站防线；交付 | `ingest.py`(662) `netguard.py`(162) `delivery.py`(104) `subtitles.py`(145) |
| 表达层 | IR 校验、模板变量、文字栅格化与字形覆盖 | `ir.py`(381) `templates.py`(252) `textlayer.py`(157) `fonts.py`(228) |
| 编译·执行 | IR → FFmpeg filtergraph / MLT XML；子进程渲染 | `compile_ffmpeg.py`(366) `compile_mlt.py`(284) `render.py`(168) |
| 验证层 | L0 素材 / L1 结构 / L2 感知 / L3 语义；证据图；回执 | `validate.py`(283) |
| 持久化 | 队列、事件、缓存、配额、审计、限流窗口 | `store.py`(1105) `store_pg.py`(279) `config.py`(171) `errors.py`(152) |

**为什么 IR 在表达层、编译在其下**：IR 是**事实来源**，filtergraph 与 MLT XML 都是它的编译产物，
可以随时丢、随时重编。反过来把 XML 当事实来源，就等于把某个引擎的实现细节写进契约。

### 接口层的实现事实（易说错的一处）

| 入口 | 传输 | 证据 |
|---|---|---|
| REST | HTTP/1.1，Bearer token | `api.py` 的 `do_GET / do_POST / do_DELETE` |
| MCP · 本地嵌入 | **stdio**，行分隔 JSON-RPC 2.0 | `cli.py` 的 `renderd mcp --tenant`；`mcp_stdio.py:serve_forever()` 读 `sys.stdin` |
| MCP · 服务端部署 | **Streamable HTTP**，`POST /mcp`，JSON 响应模式 | `api.py` 的 `h_mcp()`；协议版本 `2025-03-26` / `2024-11-05` 可协商 |
| CLI | 本地进程 | `cli.py` |

**两条传输共用同一份业务分发**（`MCPServer.handle()`），所以工具集、参数、错误码只有一套定义。
传输层只做四件事：定租户、取 body、逐条分发、打包回包。

**租户来源是这两条路唯一真正分岔的地方**：

| 传输 | 租户来源 | 理由 |
|---|---|---|
| stdio | Bearer token **或** `RENDERD_MCP_TENANT` 环境变量 | 「谁 spawn 进程，谁就是谁」——进程与环境都由调用方创建 |
| HTTP | **只能** Bearer token（`from_env=False`） | 环境变量兜底在服务端等于「一个配置就让所有客户变成同一租户」 |

其余差异只有协议细节：纯通知回 `202` 无体、批量上限 32 条、`GET /mcp` 回 `405 + Allow: POST`
（MCP 客户端会先探 SSE，回 405 比 404 更快让它回落到 POST）。验收：`make test-mcp-http`（16 项）。

## 三、一次任务的端到端时序

```
① POST /v1/render
   auth → 租户解析 → preflight（schema + 素材探针 + 字体覆盖 + 安全区）
   → 幂等键 (tenant, idempotency_key) 命中则直接返回原 job_id
   → 入队（jobs.status=queued）

② worker 领取
   UPDATE … RETURNING 单语句原子领取 + 写 lease_until（不用"先查后改"，那在多 worker 下必然双领）

③ 素材归一化（ingest）
   probe（ffprobe + 抽样解码） → decide（规则表产出动作集） → normalize（mezzanine）
   动作写进 receipt.L0_ingest，digest 进缓存键 —— 禁止静默改变素材语义

④ 编译
   IR → filtergraph（FFmpeg）或 XML（MLT）；文字在编译期栅格化成 PNG 图层

⑤ 渲染
   子进程 ffmpeg，threads 固定 4 并入缓存键（x264 字节输出与线程数相关）

⑥ 验证
   L1 结构（字段全等 / 同后端字节一致）
   L2 感知（VMAF/SSIM）—— 只有拿到 reference 才有意义，只做回归
   L3 语义（字形覆盖 / 安全区 / 响度 -14 LUFS / 黑场）—— 唯一能判"首次对不对"的层
   → receipt v1 + 证据图（抽帧拼图）

⑦ 交付
   本地卷 + HMAC 签名 URL，或预签名 PUT 直传客户 OSS
   webhook 回调：解析一次、钉住 IP、投递期零解析（防 DNS rebinding）

⑧ reaper
   独立进程扫过期租约并重排 —— 不这么做时，所有 worker 挂掉会让任务永久卡 running
```

## 四、五条决定性的架构判断

**1. 文字必须在编译期栅格化。**
让目标机现算字形，就把输出绑定到那台机器的 freetype 版本，跨端一致从物理上不可保证。
代价：必须装 Pillow，且字体集哈希要进缓存键。无 Pillow 时含文字模板直接拒绝编译，不降级。

**2. 缓存键是六元组，不是 IR 哈希。**
`sha256(规范化 IR + 后端 + 引擎版本 + 字体集哈希 + 输出规格 + threads)`。
少任何一项，"同样输入同样字节"就是空话。

**3. L2 不能判首次正确性。**
没有参照片时算 VMAF 等于自欺。回执里 L2 恒为 `applicable=false`，而不是假装通过。

**4. 队列语义只能靠单语句原子性。**
`UPDATE … RETURNING` + `lease_until`，多实例重复扫描是幂等的。
租约回收抽成独立 reaper，API 进程默认启动 —— 这是消掉单点故障的唯一办法。

**5. 失败必须可执行。**
错误码带 `code + message + hint + field + allowed_values`；`transient`（超时/OOM/编码会话）才重试，
`permanent`（素材坏 / IR 非法 / 字体缺）立即失败。对永久错误重试只会烧算力并延迟客户拿到原因。

## 五、三个项目的分工（一个系统的三个切面）

```
cutproof          证明「这条路能走通」：21 条故障语料 + 断言库 + 五步 CI 门禁
   ↓ 结论沉淀（判定标准）
renderd           把它做成产品：幂等、队列、租约、缓存、配额、回执、REST + MCP
   ↑ 素材与压力来源
motiongit-lab     真实模板（.motion = ZIP 源码包）与进程模型基准（SKIA / Chromium）
```

| 项目 | 定位 | 交付形态 |
|---|---|---|
| `cutproof/` | P0 可验证性闭环：素材进得来 → 成片敢交付，全链路可重跑 | `ci/gate.sh` 五步门禁，约 1 分钟 |
| `renderd/` | 产品化渲染服务：IR 进，成片 + 证据回执出 | REST + MCP 双接口，SQLite / PG 双后端，FFmpeg / MLT 双编译后端 |
| `motiongit-lab/` | 模板运行时实验与性能基准 | `.motion` 解包、改参、逐帧渲染、并行度实测 |

**边界纪律**：`cutproof` 里的判定标准是 `renderd` 验收的上游依据，不允许 `renderd` 反过来定义"什么算对"。

## 六、运行时形态

| 形态 | 组成 | 适用 |
|---|---|---|
| 单机最小 | 单进程 + SQLite（零依赖） | 开发、2–4 worker |
| 生产 | PG 16 + api / worker 各自扩副本 + Caddy TLS | 云端单机到中等规模 |
| 容器 | `renderd:0.1.0`（~300 MB，10 层），可选 `:0.1.0-mlt`（+450 MB 带 melt） | 已推 `ghcr.io/jushenzhidao/renderd` |

横向扩展的边界在 `store.py` 一个类：换队列实现只改这一处。
**没有引入 Redis**：租约靠 PG 的 `FOR UPDATE SKIP LOCKED` 与 `jobs.lease_until` 就够，
状态、配额、审计、幂等全部留在同一个关系型存储里，出事故才能对账。

## 七、已知缺口（架构层，不是 bug 层）

| 缺口 | 性质 | 触发条件 |
|---|---|---|
| 镜像只有 `linux/arm64` | 本机 Colima 无 `buildx`，无法出多架构 | 生产为 x86_64 时不可用 |
| 文件卷未多机化 | 产物走本地卷，多机共享盘未做 | PG 后端可扩副本，但产物仍需共享存储 |
| HDR 是预览级 tone mapping | `zscale 线性光 → hable → bt709`，无创作意图 | 客户要求广播级调色 |
| 真实素材回归缺失 | 21 条合成语料只覆盖故障模式，不覆盖真实噪声分布 | 上量前必须补 50–100 条 |
| webhook 无 outbox | 回调失败靠重试，没有持久化发件箱 | 要求投递至少一次时需补 |

## 八、读这套代码的顺序（给接手的人）

1. `docs/IR.md` —— 先看契约，5 分钟建立"什么是事实来源"；
2. `renderd/ir.py` —— 校验规则，看系统拒绝什么；
3. `renderd/runner.py` 的 `Runner.run()` —— 一次任务的主干；
4. `renderd/validate.py` 顶部三行注释 —— L1/L2/L3 的分工，最容易被误解的地方；
5. `renderd/store.py` 的 `CREATE TABLE` 段 —— 队列语义与幂等的真正实现；
6. 最后再看 `api.py` —— 它只是把上面这些暴露出去，不含逻辑。
