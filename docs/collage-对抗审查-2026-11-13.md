## 二、PASS

### 1. 11 段结构与上游逐段一致

上游 `guide.json.duration.rules` 的原长与我们的 `scenes[].t1 - t0`：

| 段 | 上游 | 我们 | 差 |
|---|---|---|---|
| hero / recipe / open / pack | 4.5 / 6.5 / 3.5 / 6.5 | 同 | 0 |
| flow / adapt / reuse | 10 / 4 / 5.5 | 同 | 0 |
| spec / share / finale / end | 4 / 4 / 4 / 4.5 | 同 | 0 |

11/11 段误差 0，首尾相接无缝隙，总长 57.000s = `durationSeconds`。

### 2. 输出规格

`1920×1080 / 60fps / 3420 帧 / 57.000000s / h264 / 3.68MB`，ffprobe 实测，非自述。

### 3. 交付门禁

`node src/gate.mjs` → PASS（flat 1.8% / black 1.8% / hook 0.17 / mean Y 30.4）。
两项告警是设计内的：无音轨、首帧淡入接近黑场（参考片同样如此）。

### 4. 运动节拍（补齐维度后）

`bench/motion-scan.mjs`，全片 5fps 采样、列剖面互相关求横向位移：

| | 参考片 | 复刻件 | 比值 |
|---|---|---|---|
| 移动帧（>200 px/s） | 8 / 284（2.8%） | 3 / 285（1.1%） | 0.38× |
| 均值 | 419 px/s | 547 px/s | 1.31× |
| 峰值（P90） | 720 px/s | 800 px/s | 1.11× |

同量级。这条是本轮唯一**新加**的维度——加之前，`recipe` 段是 2876 px/s 的滚动带，
而参考片该段 26/31 帧位移为 0。**没有这个工具，这个错误永远不会被发现。**

### 5. 场景表不依赖切点检测

### 6. 品牌洁净度

`grep -rn "MotionGit\|motiongit" kits/collage` 只命中注释、README、
以及 `presets/demo.json`（参考片复刻件，显式保留）。**成片与默认值里没有别人的品牌。**

## 三、WEAK

### 7. 保真度：0.59 均值，不是"复刻到像素"

逐场景 SSIM（参考片 vs `demo.json` 复刻，同内容同时间点）：

| 场景 | SSIM | 场景 | SSIM |
|---|---|---|---|
| hero | 0.636 | reuse | 0.535 |
| recipe | 0.616 | spec | 0.617 |
| open | 0.631 | share | 0.612 |
| pack | 0.575 | finale | 0.606 |
| flow | 0.563 | end | 0.646 |
| **adapt** | **0.442** | 均值 | **0.589** |

基线与口径：同尺寸**纯黑**帧 vs 参考 hero = **0.086**。所以 0.59 不是噪声，是真实的结构相似；
但它离"复刻"很远——差异来自字体实例、光晕、程序化插画、以及最差的 `adapt`（双窗布局本体重构过）。

**口径纠正**：此前用"字标包围盒 1px 差"当保真证据，那只能证明**一个元素**在**一帧**上对，
不能外推到整片。

### 8. 内容模型覆盖 33%，不是 1:1 映射

| | 数量 |
|---|---|
| 上游 `copy-contract.json` 槽位 | **229**（15 个 section） |
| 本 kit `args` 字段（`cutduo.json` 全片计） | **75** |

上游 11 个顶层参数（`sourceEdits` / `voiceover` / `voiceoverMode` / `soundtrackMode` /
`music` / `media` / `copy` / `brand` / `header` / `sceneSequence` / `durationSeconds`）
我们只映射了 **2 个**（`brand` / `scenes`），其余用 per-scene args 取代。

**正确表述**：借的是**场景结构与语义块**，不是 229 个槽位的字段级契约。
README 已按此收敛，不再写"借它的内容模型"。

### 9. 吞吐口径

三次连跑：10.2s / 10.4s / 12.5s ⇒ 335 / 329 / 274 fps。
片中曾写"332 FPS"（单次最好值），**属于挑最好成绩**。已改为 330（三次中位）。
README 已写区间 10.2–12.5s。

## 四、FAIL（能力缺失，明确记账，本轮不修）

| # | 上游有 | 我们 | 影响 |
|---|---|---|---|
| 10 | `hold` 停留点：已审核静止点可停 0–6s（1/60 秒粒度） | **未实现**。只能拉长 `t1`，动画会提前播完变成尾部静止，停留位置不可控 | 文案变长时无法在指定构图停留 |
| 11 | 音频：33 个动作音效事件 + 配乐 ducking + `soundtrackMode` 三态 | 只有画面，音轨靠 `--audio` 外挂 | 见下方「音效的四层断点」 |
| 12 | 媒体载体 14 个（`demo` / `portrait` / `wall00–11`），含视频时钟规则 | 作品墙是**程序化缩略图**；无视频载体与播放时钟 | 客户素材进不来，「12 格作品墙」只能是示意 |
| 13 | `copy` 是**一个整体对象**（229 槽，plan 阶段校验容量） | per-scene args，schema 只校验骨架 | 无法复用上游的 `copy-contract.json` 直接喂内容 |

这四条决定了当前定位：**"能出同风格片的独立版式"，不是"可直接替换上游产线的 drop-in"**。

### 附录：音效的四层断点（逐层查证）

「33 个动作音效丢失」不是单点故障，是四次断在四个不同的地方：

| 层 | 事实 | 证据 |
|---|---|---|
| ① 资产 | **上游发行时主动剥离**：`audio-content-boundary.removed` 34 条，其中 33 条 role = `original-demo-audio-or-production-record`（`final-mix.wav` 15.7MB / `music.wav` 20.9MB / `narration.wav` 15.7MB / `music-default.m4a` 1.4MB / 13 组 `phrases/*` 各 mp3+wav / 3 个元数据） | `unzip -l content/release.bin` 中 0 个音频文件 |
| ② 保留声明 | `retained["native/assets/audio/sfx.wav"]`（role=`independent-source-effects`）**声称保留**，但包里 88 个加密对象合计仅 3.43MB、最大 356KB，`integrity.json` 里 0 条 wav | `protected/descriptor.json` |
| ③ 事件表 | 33 个事件的时间戳/增益在 `protected/core.enc`（56KB，AES-256-GCM + Ed25519 验签，需平台公钥与解锁缓存） | `guide.json.runtime.audio` 只给语义，不给表 |
| ④ 我方能力 | 即使拿到 `sfx.wav` 也用不了：pipeline 只有一条 `--audio` 整轨，没有「事件轨 + 按场景重放 + 停留处静音 + 人声下 ducking」 | `src/pipeline.mjs`（**已补**，见 §四） |
| ⑤ 官方 API 通路 | 音效相关两条能力**都是 disabled**：`sfx.search`（授权音效，0 积分，`configured=false`）/ `sfx.generate`（定制音效，1 积分），reason 均为「尚未开放」。同批里唯一 `ready` 的音频能力是 `music.search`（背景音乐库，0 积分） | `node assistant/motion.mjs api <pkg> status`（只读，0 积分） |

**一处必须更正的巧合**：`33-event SFX`（`guide.json.runtime.audio`）的 33 是**事件数**；
`removed[]` 里的 33 是**文件条数**。两者数字相同、含义无关，此前被混着说。

**能不能补**：从参考片抽音轨不行——那是他们的成片混音（音乐+音效+人声已叠在一起，不可分离）。

还有一条常被忽略的线索：被删清单里有 `LICENSE-ASSETS-CC0.txt` 与 `music-default-provenance.json`，
说明原始 demo 音频**是 CC0 素材**。所以"拿不到"不是版权墙，是**发行策略 + 通路口径**：
文件被删、出处记录也被删，无法反查是哪几个 CC0 文件。

结论：想要声音只有两条路——自配（CC0 库或程序合成，需先有事件轨与混音器，**已实现**），
或接受无声。
