## 一、先回答「上次学到哪」

2026-11-14 的结论是：**代码侧 1–2 小时，成本全在素材**；三条路里只有 dataviz 值得半蒸馏，批量搬不推荐。
这次验证了另一面：**素材只在"要跑它自己的 build.sh"时才是成本**。只出画面时，素材依赖只有字体。

实测（本机）：

| 检查 | 结果 |
|---|---|
| SSH 稀疏克隆（`--filter=blob:none --sparse`） | 33MB，只取 `core/ + 4 个风格` |
| 只留 `core/render`（6 个文件） | **72KB**，不需要 three、3D 资产、TTS/music tier |
| 字体 | 每支风格 3–7 个 Google Fonts 文件，`raw.githubusercontent` 直下 |
| 单帧 | 31–84ms |
| 整片 | **59s 样片 26s 渲完**（4 worker，CRF14） |

## 二、为什么选 midcentury-toon

| 风格 | 内容模型 | 换内容的真实成本 |
|---|---|---|
| `midcentury-toon` | `content.json` 驱动：hook / 3 steps / payoff(平面图) / tip / outro | **改 JSON**（本次实测 3 小时含中文与混音） |
| `cel-anime-80s` | `story.js` 是 19 个具名镜头，`scenes1/2.js` 写死摩托快递 | 重写分镜与角色绑定，2–4 天 |
| `rubber-hose` | `scenes.js` 51KB 写死追逐戏 | 同上 |
| `scifi-toon` | 同族，写死情景喜剧 | 同上 |

判据不是"哪个好看"，是**内容是否在数据里**。midcentury 的镜头函数只吃 `content.json` 的字段，所以换主题不用碰绘制代码。

## 三、选题为什么从「超市动线」改成「扫地机原理」

第一版写的是「牛奶为什么在最里面」，中文内容都做完了，渲出帧才发现**道具是写死的**：

| 段落 | 写死的道具 | 超市题材的冲突 |
|---|---|---|
| hook | 开箱 → 扫地机弹出来 | 开场就在讲一台机器，不是牛奶 |
| payoff | 充电座 + 扫地机沿路线走 | 动线是对的，主角不对 |
| tip | 一根电线被手拎起来 | 超市地上没有电线 |
| end | 扫地机滚回充电座 | 同上 |

要改就得画四张新图（纸盒换成牛奶盒、充电座换闸机、电线换小票、结尾换购物车），那是重画不是换文案。
所以改成讲这台机器本身：**它怎么知道房间有多大**——开箱、充电座、电线、沿墙路线全部变成论证的一部分，零改图。

这条经验可复用：**换宿主的成本不在"能不能跑"，在"道具/角色是不是也被写死了"**。验收方法是先渲 4–6 张关键帧，而不是先写文案。

## 四、中文要过的三关

1. **字形**：三个族名（Oleo / Slab / Jost）都没有 CJK，直接方框。做法是新增 `fonts-zh.css` 把**族名**映射到 ZCOOL 快乐体 / 思源黑体 Black / Medium，而不是去改 60 处 `ctx.font`。软链 `assets/fonts` 避免 18MB 重复入库。
2. **时长**：段落长度按时长取整到 132 BPM 的小节；上游末步写死 2 小节（3.64s），中文末句 5.93s 会被下一段切掉。改为按时长取小节。
3. **断句**：字幕卡宽度按 `text.length/12` 估时长，中文 20 字 ≈ 2.7s，够用；配音走 edge-tts，时间点以页面 `window.SRT` 为准（它已含 J-cut 提前半拍），不要在外部按顺序猜。

## 五、混音（可复制）

```bash
# 旁白 6 句 + 合成垫底，人声按 window.SRT 的 t0 落位
# 先测原始混音电平，再按差值做线性增益；loudnorm 单遍动态模式会把峰值压回去
ffmpeg -i hook.wav ... -i bgm.wav -filter_complex "
 [0:a]adelay=1978|1978[v0]; ... [6:a]volume=0.16[bg];
 [v0]...[bg]amix=inputs=7:normalize=0,
 acompressor=threshold=0.09:ratio=3.2:attack=6:release=260:makeup=9,
 volume=-2.6dB,alimiter=limit=0.74:level=false[out]" -map "[out]" -c:a aac_at -b:a 192k mix.m4a
```

实测：−16.0 LUFS / 真峰值 −4.3 dBTP。

**AAC 坑（新）**：macOS 上 ffmpeg 原生 `aac` 编码这段密集内容，源峰值 −2.2 dBFS，解码后变成 **+7.7 dBFS**；换 `aac_at` 恢复 −1.8。之前 cute-mv 那次没暴露，是因为内容不同。以后一律 `-c:a aac_at`，并且**编码后再测一次峰值**。

## 六、诚实边界

- 配乐不是 50 年代 cool jazz：上游 `score.py` 依赖不在仓库的 CC0 采样库，本片用 `synth-bgm` 的 chillwave 垫底。
- 没有做口型/姿态差异化：主持人只有一套身体，靠手部动作区分步骤（这是风格本身的限定动画，不是省事）。
- 没有注册成 kit / API：单支片子，先不产线化。

## 七、产线化：一条命令（2026-11-15 补）

`vendor/lemo/render.mjs` 把「配音 → 时长 → 时间轴 → 混音 → 画面 → 封装 → 自检」串成一条命令：

```bash
node vendor/lemo/render.mjs --params content/lemo-vacuum/script.json --out out/x.mp4
```

实测同片复现：**画面同帧 md5 完全一致**，只有混音响度差 0.3 LU（手工版 −15.8，命令版 −15.5）。
47s 片全流程约 40s（TTS 6 句 + 渲染 15s）。

三个实现要点：

1. **先设 `PLAYWRIGHT_CHROME` 再 import `page.mjs`**：该模块在顶层读环境变量，先 import 后设等于没设。
2. **配音缓存按文本判断**：`audio/<句>.wav` + 同名 `.txt` 同时存在且文本一致才复用，改文案自动重合成。
3. **混音要收敛**：限幅器会吃掉一部分增益，一次算不准；测一次修一次，最多两轮，落在 −16 ± 0.4。

## 八、第二支片暴露的两个版面约束

做「没电了，它怎么接着扫」时踩到两处，都属于**平面图的隐含假设**：

| 症状 | 原因 | 修法 |
|---|---|---|
| 红线斜穿两面墙 | `buildPath` 第一步从 `dock` 直连到第一分区；dock 放在最右分区时这条线横跨整张图 | **充电座必须落在第一个分区内**，否则起点连线穿墙 |
| 「书房」像厨房 | `zones[].checks` 画的是棋盘格地砖，只有厨房/卫生间讲得通 | 非湿区不要开 `checks` |

另外：`planProgress` 把回充段压在最后 0.7 拍（约 0.3–0.45s），字幕若提前承诺「这条虚线」会对不上。
本片把字幕改成描述路线本身，不去指认那 0.45 秒。
