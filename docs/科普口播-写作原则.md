# 科普口播写作原则

> 适用：`paper` / `science` 版式的科普片，2–8 分钟，口播驱动、画面配合解说。
> 来源：蒸馏 `anything2explainer` 的 `reference/narration-guidance.md`（PolyForm Noncommercial），按本仓口径重写，非原文照搬。
> 用法：写 `script.json` 之前读一遍，写完跑最后一节的检查表。

## 0. 唯一的检验

把一句话读出声，然后问：**听众此刻是否知道了、看见了或感受到了前一句之前他不知道的东西？**
没有，这句就是填充物。5 分钟片大约能放 45–50 句，每一句都要过这一关。

## 1. 从处境切入，不要从定义切入

在说出概念名之前，先把听众放进一个具体场景、问题或谜题里。定义到来时，应当像他早就有的那个问题的答案。

- 反例：「本福特定律是一种描述自然数据首位数字分布的定律。」
- 正例：「随便翻开一页税收数据、一份河流长度表、一栋楼的高度清单——第一个数字是 1 的概率，比是 9 的概率大六倍。这不是巧合，也不是造假。」

以「X 的定义是」「在本期视频中我们将」开场的，把最贵的十几秒花在了虚无上。

## 2. 一条主线

全片回答一个问题，或跟随一段旅程：一个从头到尾的过程、一个最终化解的张力、一个被解开的谜。

每一段都是这条线上可见的一步，听众随时说得出「我走到哪了、这一步为什么接上一步」。

**失败形态是词条式堆砌**：一串概念，每个都被同等对待。判据很硬——**如果各段可以打乱顺序而不损失内容，就是没有主线，回去重找**。

## 3. 先动机，后机制

讲任何一个东西，按这个顺序：**没有它会出什么问题 → 它怎么运作 → 它给你带来什么**。

绝不要去解释一个听众还不想被解释的机制。所有「为什么」句是让科普片显得聪明、而不是像百科的句子；它也是控篇幅时最常被砍掉的句子——**要砍先砍机制细节，不要砍动机**。

## 4. 句子层面的具体

每一个抽象名词后面，跟一个听众能想象的实例：一个真有人会问的问题、一件真会发生的事、一个有名字的东西。

**数字永远不要复述。**它只有两条路：换算成可感的尺度，或者删掉。听众感受不到的数字就是噪音。

| 别写 | 改写 |
|---|---|
| 「23 个人里有 253 对组合」 | 「一个班 23 个人，两两握一次手，一共 253 次——比教室里的椅子还多」 |
| 「准确率提升 12.4%」 | 「一百次判断里，少错了十二次」 |

## 5. 比喻是工具，不是装饰

只在**能让听众做出一个没有它就做不出的推论**时用；用就用到不能再预测为止，一旦失真立刻丢掉。

一个贯穿几拍的好比喻，胜过硬塞六个一次性的聪明比喻。**绝不要按段配比喻**——听众听到的是模板，不是内容。

## 6. 声音：一个觉得这事有意思的人，在跟聪明朋友说话

平实的词、口语的缩写、偶尔的判断（「这就是关键」「听着理所当然，其实不是」）。

对局限坦诚（「大概」「没人完全知道为什么」）比自信更能建立信任。不要教科书腔，不要企业腔，不要预告你接下来要讲什么。

## 7. 变换节奏

长解释句之后紧跟一句短促的收尾。一个问题、一个停顿、一个揭晓。

**句式单调是「感觉无聊」的直接成因**——哪怕内容本身没问题。读出声，标出任何连续三句长度、结构都一样的片段，改掉其中一句。

## 8. 术语是给已经理解的东西贴标签

先用白话把想法讲清楚，再贴名字（「……这个大家叫它 X」）。这样引入的术语不花成本；先甩术语再解释，会让听众多花一句在焦虑上。

**每一个你引入的名字，后面都必须再用到**，否则它根本不需要一个名字。

## 9. 早亮风险，晚给回报

第一分钟内听众就该知道：这件事做得好或做不好，会改变什么（钱、时间、什么变得可能）。

结尾带着新的理解回到开场的场景或问题，并**重新框定它**。结尾是了断，不是总结清单，也不是告别。

## 10. 密度：宁可少讲透，不要列全

要砍的：重复表述、只起通告作用的过渡（「接下来我们看看……」）、超过三项的清单（除非清单本身就是重点）、任何唯一职责是「求全」的句子。

相邻两句在不同抽象层次说同一件事时，**留具体的那句**。

## 11. 说出画面说不出的话

口播负责：原因、后果、比较、判断。
画面负责：结构、次序、数量。

**绝不要为图解配旁白**（「这里我们可以看到」「看这张图」）。一句话只是在描述屏幕上有啥，就砍掉——让屏幕自己说。

## 12. 精确才会被信任

名称、日期、带出处的真数字、真实的产品名。近似值就标明是近似值。**绝不要把事实磨圆成一句口号。**

一支让人兴奋但略有错误的科普片，抵不上一支平静而正确的。

## 13. 在接缝处交接（多段片必做）

段与段的交界是听众最容易迷路的地方：上一个想法结束了，下一个还没开始，一张标题卡除了报幕什么也没干。

- **段末留钩子**：把下一段要解决的问题、代价或缺口说出来，让听众自己产生「那接下来呢」。
- **段首先承接再开题**：第一句回指上一段的成果，再提出本段的问题。
- 反例两种：段首从零起头（「什么是 X」）→ 割裂；只报幕（「接下来我们看 X」）→ 空转。

判据：不该有人需要问「为什么这段接在那段后面」，也不该有任何一段从静止状态起步。

## 14. 导航标签不是标题创意

`brand` / 章节名 / `cast` 这些会出现在画面上的词，是**导航标签**：观众瞄一眼就知道这段讲什么。

- 写成「名词短语 + 方面/动作」，2–6 字；同一片里各段结构平行。
- 正例：`为什么算错 / 直觉的漏洞 / 验证一次`
- 反例：`感觉还行 / 两把尺子 / 搭台留痕`——评价句、比喻、俏皮话，猜不出内容。

比喻和金句留给口播与画面，**不要放进导航标签**。自检三问：
① 只看这几个词，没看过片的人能说出这段讲什么吗？② 每个都是名词短语吗？③ 连起来是一条看得懂的主线吗？

## 本仓口径（写之前先算清楚）

| 项 | 值 | 来源 |
|---|---|---|
| 语速 | **4.9 字/秒** | 实测 336 字→70 s、448 字→91 s；不要用 3.2 估 |
| 字幕 | 62px 单行上限 **26 字**，超了按标点折行并降档 | `src/` 字幕排版 |
| 每段时长 | 一拍按 ≤7 s 拆子段；`screens[k]` 的时刻**必须小于子段时长**，否则永不出现 | `docs/时间轴-契约` |
| 每屏 `cast` | 2–6 字，缺省会退回标题 ⇒ 关键词卡重复标题 | `kits/paper` |
| 目标时长 | 字数 ÷ 4.9 ≈ 语音秒数；成片另加段末留白 | — |

算例：想出一支 90 秒的片 → 90 × 4.9 ≈ **440 字**，约 30–36 句，8–10 拍。

## 起飞前检查表

写完 `script.json`，逐条过（打勾才算完成）：

- [ ] **开场句**：已经有人身处某个情境里了吗？（§1）
- [ ] **各段能不能打乱顺序还不损失？** 能 → 没有主线，回去重找（§2）
- [ ] 数「为什么」句和「怎么做」句：每三句「怎么做」至少配一句「为什么」（§3）
- [ ] **每个数字**：都换算成了可感尺度，或者已删（§4）
- [ ] **每个比喻**：能让听众推出点什么吗？用了不止一次吗？（§5）
- [ ] 有没有句子在通告、总结、或描述画面？有就砍（§6、§10、§11）
- [ ] 读出声，标出连续三句同构的片段，改掉一句（§7）
- [ ] **每个术语**：先白话讲清、再给名字、后面还会再用（§8）
- [ ] **每个段界**：上一段留了问题，下一段以回答它开头，而不是冷启动（§13）
- [ ] **结尾**：是对开场的重新框定，不是总结清单（§9）
- [ ] **导航标签**：只看这几个词，能说出每段讲什么（§14）
- [ ] **字数**：÷4.9 落在目标时长 ±15% 内（超了加删句子，别改语速凑）
- [ ] 每句都画得出来：讲的是哪一种画面关系？画不出的句子改掉或删掉（§11）

## 最常见的四种失败形态

| 形态 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 词条式 | 每段都在定义、可以任意排序 | 没有主线（§2） | 找一条过程/张力/谜题当骨架，段 = 主线上的一步 |
| 百科腔 | 「X 是一种……」开场 | 从定义切入（§1） | 换成处境或数字反差 |
| 空转过渡 | 「接下来我们看……」 | 没有动机（§13） | 段末给缺口、段首承接 |
| 念数字 | 一句话里三个百分比 | 没做尺度换算（§4） | 留一个、换算、其余删 |
