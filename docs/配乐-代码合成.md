# 配乐：代码合成（`tools/synth-bgm.mjs`）

> 2026-11-14 落地。解决一个结构性问题：配乐依赖本机 Apple Loops，而那是**不入库**的资源。

## 为什么要有

`tools/audio-bed.mjs` 的文件头自己写着：

> 曲目路径是本机资源（`/Library/Audio/Apple Loops/Apple`），**不入库**；找不到就报错并列出可用曲风。

实测本仓 `assets/` 下 loop 文件数 **0**。也就是说：换一台机器、或进 CI，就出不了带配乐的片。而且每换一种曲风都要手工调 `TRIM` 线性补偿（hiphop 要 ×2.6，因为 Afloat 比 electrohouse 低 9–13 dB）——这是"用现成素材"的固有代价：电平不是你定的。

`synth-bgm.mjs` 从零合成：参数在代码里，输出可复现，换机不失效。

## 怎么用

```bash
# 独立生成
node tools/synth-bgm.mjs --out assets/audio/bgm/lofi-90.wav --duration 90 --style chillwave

# 走现有音频链（替代 Apple Loops，其余不变）
node tools/audio-bed.mjs --slug benford --style chillwave --synth
```

四种曲风：`electrohouse`（122bpm，四拍底鼓）/ `chillwave`（84bpm，正弦铺底）/ `hiphop`（88bpm，boom-bap）/ `ambient`（72bpm，无鼓无贝斯）。

给了 `--params` 就从段边界推 `drop`：**配乐的高潮和画面的高潮是同一个时刻**。

## 客观对比（同一支片，只换配乐来源）

`content/benford`（68.49s，15 条音效）：

| | 代码合成 | Apple Loops |
|---|---|---|
| 整体响度 | −17.1 LUFS | −16.9 LUFS |
| LRA | 3.6 LU | 3.9 LU |
| 真峰值 | −1.1 dBFS | −1.2 dBFS |

**在交付指标上等价。** 差异只在音色——这一项无法用指标验证，需要人耳判断（样例见 `deliverables/bgm-demo/`）。

## 架构（吸收自 mgaudio，不移植其实现）

mg-styles-15 的 `lib/audio/mgaudio` 是一套完整的 DSP 库（numpy + numba + pedalboard，PolyBLEP 抗混叠振荡器、TPT ladder 滤波、Karplus-Strong、FM、19 种 recipe）。它的三条架构约定被采用：

1. **form 以 drop 为锚**：`intro → build → drop → outro`，和声从 drop 起算（intro 走进行末尾＝回转）。
2. **music 与 sfx 分两组**：本工具只做 music；音效仍由 `buildMix` 的 `cues` 负责，音乐在每个音效同步点附近让位（现有 `sidechaincompress` 已经在做）。
3. **`Form(duration)` 是参数**：不是硬编码 10 秒。`drop` 默认 `0.42*D`，`build/outro` 都按比例算。

不移植实现的原因：那套依赖三个重库，与本仓「Skia 直出、零浏览器」的取向相反。本文件纯 Node（Float32Array + 一阶 IIR），90s 约 1–2 秒算完，**零新依赖**。

## 两个必须记住的坑

**1. 鼓点必须有起音包络。** 第一版 kick 从 0 直接跳到峰值，频谱上是一根贯穿全频段的竖线（click 声）。加 2ms `attack` 后消失。hat 同理（1ms）。

**2. 长片的 drop 不能一路到底。** 90s 的片子若 `outro` 压在片尾，`drop` 段就是从 11.4s 到 87.1s（84% 都是最高能量），段落结构等于没有。修法两层：
- `outro` 落在 drop 之后的 78% 处，至少留 2 小节；
- `drop` 区间内每 **8 小节**做一次呼吸（最后 2 小节回落到 0.62 再顶起来）。

## 确定性

不用 `Math.random()`，用 xorshift32 固定种子。同一个 `--style/--bpm/--duration/--params` 永远得到同一个文件。

## 未做
