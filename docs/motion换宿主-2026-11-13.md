# .motion 模板「换宿主」可行性验证（2026-11-13）

## 结论

`.motion` 模板的**绘制层可以直接跑在 `@napi-rs/canvas`（Skia）上**，不需要「蒸馏」重写成另一套代码，
只需换 canvas 宿主 + 补三处宿主数据。单镜头验证通过（`comments` / `counter`）。

复现：`node bench/motion-host/poc.mjs comments 1.2`

## 为什么可行（静态分析 + 实测）

解包 `templates/vendor/mac-desktop/package/content/release.bin`（3.4 MB，普通 zip，`protection: None`）：

| 项 | 事实 |
|---|---|
| 镜头源码 | **55 个 `.js`，每个 2–6 KB**，一镜头一文件 |
| 绘制方式 | **纯 Canvas2D**，`draw(c, t)` 由时间驱动，无 `requestAnimationFrame` |
| 核心模块 | `core.js` / `g.js` / `desk.js` / `hud.js` / `props.js` / `media.js` —— **DOM 依赖 0** |
| DOM 只在 | `main.js`（宿主入口，11 处）、3 处 `createElement`、`document.fonts` |
| 附带资料 | `SHOTS.md` 110 KB 规格、`catalog.json` 154 KB 参数目录、45 张官方预览图 |

`@napi-rs/canvas` 提供的正是 Canvas2D API，所以 `draw(c, t)` 几乎原地可跑。

## 三个障碍与解法

**① `data/film.js` 缺失。** `filmkit.js` 依赖它（时间轴、节拍、inserts），但包里没有——由宿主生成。
官方 `tools/motion.mjs` 是混淆压缩的（单行 61 KB，含签名校验），读不了。
PoC 里手写了一份最小实现（`fps/width/height/end/talkEnd/ins/beats/globals/presenter/shots/custom`），
单镜头够用；整片需要按 `instance/film.json` 生成完整时间轴。

**② 字体是 woff2，且 Skia 不做族名回退。** 这是本次唯一的真坑：

- 模板自带 `engine/fonts/Geist-*.woff2`（8 个字重），`@napi-rs/canvas` 不吃 woff2；
- 模板的 `FAM.zh` 首选 `"PingFang SC"`，浏览器会自动回退到系统字体，**Skia 不会**——
  于是全部中文变成豆腐块（实测第一轮就是这样）；
- 解法：把仓库自带的 `assets/fonts/NotoSansSC-*.otf` 注册成别名 `PingFang SC`：

```js
GlobalFonts.registerFromPath('assets/fonts/NotoSansSC-Medium.otf', 'PingFang SC');
```

**③ 宿主编排要替换。** `main.js` 负责镜头切换、转场、presenter 窗口、壁纸——这部分正好由
`desktop-kit` 的骨架与 `render-bench.mjs` 的编排承担，不必移植。

**另有一个参数坑**：每个镜头的 `props` 契约不同，用错参数只画出窗口壳、没有内容。
模板自带 `meta.props`（schema + default）与 `meta.example.props`，按「schema 默认 ← example 覆盖」拼即可。

## 整片宿主验证（同日追加）

单镜跑通后再进一步：**直接用模板的 `main.js` 驱动整片**，不重写编排。

```bash
node bench/motion-host/poc-full.mjs          # 1/8/20/40s 四帧
node bench/motion-host/poc-full.mjs --bench  # 测单帧成本
```

结果：`init: done`、零警告、画面完整——蓝色壁纸、菜单栏（访达/文件/编辑/显示/窗口/帮助 +
日期时间）、桌面图标（工作文件夹 / 口播稿.txt）、摄像头窗口（ON AIR + 时间码）、13 个 Dock 图标。

**`main.js` 只有 171 行，DOM 依赖只有四类**，全部可用三行 shim 顶掉：

| DOM 用法 | shim |
|---|---|
| `getElementById('cv')` | 返回我们的 `createCanvas(W, H)` |
| `createElement('canvas')` | `createCanvas(1, 1)` |
| `document.fonts.load/ready` | `Promise.resolve()` |
| `document.title` | 普通属性（用于判断初始化完成） |

**缺的 4 个 `data/*.js` 全部有空值回退**，不必生成真实数据也能出片：

| 文件 | 作用 | 空值后果 |
|---|---|---|
| `film.js` | 时间轴 | 必须真数据（取 `instance/plan-*.json` 的 `FILM`） |
| `venv.js` | 音乐音量曲线 | `{ fps: 30, v: [] }` 即可 |
| `face.js` | 人像框跟踪 | `{ n: 0 }` → 摄像头窗口画占位剪影 |
| `subs.js` | 字幕 | `[]` → 不画字幕 |

**渲染速度**：连续 90 帧实测 **1.01 ms/帧（单核 985 fps）**，与自研 `desktop-kit` 的 0.95 ms 同量级。
换宿主没有牺牲直出优势。

## 适用边界：只有 Canvas2D 开放模板能换宿主

有人问「用 promo-ink 跑一遍」。实测结论是**不行**，而且顺手扫清了全部 5 个本地模板：

```
模板                       protection    js   enc  换宿主
mac-desktop              open          86     0  ✓ 可行
camera-mode              open          45     0  ✗ DOM/CSS 渲染（有 dom.js）
paper-perspective        protected      0   592  ✗ 源码加密
paper-perspective-11     protected      0   592  ✗ 源码加密
promo-ink                protected      0    83  ✗ 源码加密
```

两条判据，缺一不可（`node bench/motion-host/check-hostable.mjs` 可直接跑）：

1. **`content.protection` 必须是 `open`**。`protected` 的包内容层是 **AES-256-GCM 密文**
   （`protected/objects/*.enc`），README 明写「私有核心已封装，只有平台签名验签通过才视为已验证发行」。
   解包绕过属于破解技术保护措施，不做。
2. **引擎必须是 Canvas2D**。`camera-mode` 虽然开放，但它的 `src/dom.js` 是
   「Tiny absolute-positioned DOM kit」——每个元素是真实 `<div>`，靠 CSS `transform`/`filter` 定位，
   文字度量走 `offsetWidth`。换宿主等于自己写半个浏览器布局引擎，不成立。

判据里有个细节容易判错：`document.createElement('canvas')` 是**离屏画布，可 shim**
（`mac-desktop` 有 3 处，实测跑通）；`createElement('div')` / `('img')` 才是真 DOM。

### 这解释了历史

`skia-kit` 当初为什么要逐像素反推 `paper-perspective`——**它是加密的，拿不到源码**。
同理 `paper-perspective-11` 与 `promo-ink`。当时可选的只有反推。

而 `mac-desktop` 是 open + Canvas2D，所以它成了唯一能换宿主的样本，也正好是 `desktop-kit` 复刻的对象。

### 对采购的含义

以后买模板先跑一次 `check-hostable.mjs`：

- 想要「半天接进产线、4–9 倍速出片」→ 选 **open + Canvas2D** 的模板；
- 只有 protected → 只能反推（35 分钟起）或走 Chromium（55 fps）；
- open 但 DOM → 只能走 Chromium。

## 并行加速

`frame(t)` 无状态这个前提已验证（`poc-full.mjs --check`：同一时刻「直接渲染」与「跑一段后回渲染」
**逐字节一致**）。因此分片并行安全，实现见 `render-parallel.mjs`——每个 worker 独立初始化
（解包共享、`buildScenes` 各自跑），各编一段 mpegts，主进程 concat。

2819 帧 / 46.98s / 1440×1080@60 / x264 veryfast crf20：

| workers | 墙钟 | 吞吐 | 相对官方 55 fps |
|---|---|---|---|
| 4 | 16.45 s | 171.3 fps | 3.1× |
| 8 | 8.04 s | 350.5 fps | 6.4× |
| 16 | 6.17 s | 457.1 fps | 8.3× |
| **24** | **5.87 s** | **480.3 fps** | **8.7×** |
| 32 | 6.13 s | 460.2 fps | 8.4× |

**甜点在 24 worker**，与 `desktop-kit` 的结论相反（那里 8 就饱和、12/16 更慢）——
因为模板镜头绘制更轻（1.01 ms vs 3.7 ms 含 GPU 壁纸），能喂更多 worker。
32 回落是编码与内存带宽竞争。

**正确性两重验证**：

1. 无状态：`--check` 逐字节一致；
2. 分片边界：跨边界相邻帧差 **0.002**，小于段内相邻帧 **0.020** → 边界连续，无错位；
   16w 与 24w（分片边界完全不同）的 SSIM **0.9996**，差异只来自编码 GOP 位置。

复现：

```bash
node bench/motion-host/render-parallel.mjs --workers 24
node bench/motion-host/render-parallel.mjs --workers 8 --limit 600   # 快速验证
```

> 注意：本次 instance 只有 2 个 shot（单个 talk 镜头占满全屏），是**最轻**的场景。
> 55 镜成片里评论墙/图表/翻牌等复杂镜头会拉高单帧成本，但机制相同，并行倍率不变。

## 成本重估（修正前一版）

前一版说「整片 55 镜约 1–2 天」偏保守——那里面混了「用模板做一条片」的内容工作。真实拆分：

| 项 | 耗时 | 性质 |
|---|---|---|
| 单镜跑通（`poc.mjs`） | 约 15 分钟 | 移植 |
| 整片宿主跑通（`poc-full.mjs`） | 约 25 分钟 | 移植 |
| 素材注入（人像帧序列 / 图片 dataURL） | 约 2 小时 | 接线（`clip`/`photo` 机制已有） |
| 音频字幕（TTS → `subs.js`） | 约 2 小时 | 接线（TTS 管线已有） |
| 接入 8 worker + 编码 | 约 1 小时 | 接线（`render-bench` 已有） |
| **移植合计** | **约半天** | |
| 写 55 镜分镜 + 文案 | 另计 | **内容**工作，与换宿主无关 |

结论：**移植是半天的事，不是两天。** 之前估慢，是把「做内容」算进了「移植」。

## 成本对比（旧版保留）

| 路径 | 单镜头 | 整片（55 镜） | 画质 |
|---|---|---|---|
| 逐像素反推（`desktop-kit` 走的） | 需先归纳成组件类 | 35 分钟第一版 + 多轮对齐 | 有损，靠猜 |
| **换宿主（跑同一份源码）** | **约 10 分钟** | 约 1–2 天（数据生成 + 宿主 + 素材） | **像素级一致** |

反推那条路的成本在「归纳」（55 镜归成 18 类）；换宿主的成本在「数据与编排」，绘制本身几乎零成本。

## 边界与风险

- **许可证**：模板包可自用、可改，但 **PLAYBOOK 第 133 行明确「不得再分发模板本身」**。
  换宿主后的产物（渲染器 + 我们自己的分镜）可以分发，模板源码不行。
- **单镜跑通 ≠ 整片可交付**：还差完整 FILM 生成、素材注入（`images` 是 dataURL）、音频字幕对齐。
- **模板自带静态壁纸**：`comments` 返回 `wall: 'paper'`，壁纸由宿主画。想接我们的 GPU 流体壁纸，
  需要改宿主的壁纸层，不是改镜头。
- **不建议重做 `desktop-kit`**：它已有 18 类组件、13 项自检、5 支交付片。换宿主应**用于新模板**，
  不是推翻现存产线。

## 复现

```bash
node bench/motion-host/poc.mjs                # comments，三帧
node bench/motion-host/poc.mjs counter 1.0    # counter，指定时间
# 产物在 bench/motion-host/out/
```

依赖：`templates/vendor/mac-desktop`（本地下载，不入库）、`unzip`、仓库自带 Noto Sans SC。
