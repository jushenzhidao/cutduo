# video-talkcraft 蒸馏（2026-11-15）

> 源：`github.com/Vincentwei1021/video-talkcraft`（1078 文件 / 36 MB）。
> 定性：**引擎 + 方法包 + 素材包**三合一。可平移的是它的**元数据模型**，不是那 108 张卡的视觉。

## 一、它到底是什么

| 层 | 内容 | 规模 | 对我们的价值 |
|---|---|---|---|
| 方法 | `SKILL.md` 8 步流程（体检→稿→配音+时间戳→素材→SHOTBOOK→实现→渲染+三重验收→交付） | 497 行 | 中：流程与我们重叠，验收更细 |
| 方法 | `references/`：`design-language.md` / `taxonomy.md` / `layout.md` / `semantic-annotation.md` / 108 张卡的 md | 121 文件 | **高**：卡片 schema 与语义索引是模型 |
| 素材 | `template/cards/*.tsx`（React 实现）+ `demos/`（HTML 可播放） | 138 + 152 | 低：视觉绑定 Remotion |
| 引擎 | `workbench/`（Vite 预览）+ `runtime/`（Remotion） | 246 文件 | 无可平移 |

一句话：它解决的是"**素材驱动**的口播片"（实拍/截图/网页/图片占画面主体），
我们解决的是"**数据驱动**的图示片"。交集只有"数据信息图"和"字幕花字"两类，
共 15 + 22 张卡，而这部分我们已有 13 个 family 覆盖了大半。

## 二、能平移的三样（都是模型，不是代码）

### 1. 卡片 frontmatter：14 个字段的元数据模型

```yaml
name / 标题 / 一句话 / 适用 / 时长 / 能量 / 类别 / 输入 / 语义 / 素材形态 / 位置 / props / 优先级 / 代码
```

其中三个字段是我们没有的：

- **能量（低/中/高）**：同一件事有轻有重。选卡时先按语义过滤，再按能量挑档位。
  我们的 family 没有能量概念 —— `data-bar` 既做开场钩子也做中段举证，节奏被动一样。
- **输入（人 / V / 截图 / 图 / 界 / 文 / 场）**：选卡的第一道过滤。我们只有"文/数据"，
  所以 108 张里 80 多张对我们直接不可用 —— 这条过滤替我们省掉了逐张评估。
- **位置（开场/中段/收尾）**：同一张卡在不同位置语义不同。

### 2. 语义索引：13 类封闭词表（选卡第二道过滤）

> 钩子 / 论点 / 例证 / 数据 / 对比 / 列举 / 定义 / 步骤 / 转折 / 设问 / 金句 / 标题 / 引用

**关键纪律：一张卡只打它专门服务的语义，不打"什么都能配"。** 这条比词表本身重要 ——
"什么都能配"等于没有索引。

它还有 `weight`：`main` 主句（允许进新元素）/ `sub` 陪衬句（只做微调，不进新元素）。
**这正是我们锚点机制缺的一层**：现在每一句都允许出新元素，8 段片子就有 8 次"满屏重来"。

### 3. 参数表第三列「调节手感」

不是取值范围，是**改了会怎样**：

| 参数 | 典型值 | 调节手感 |
|---|---|---|
| `stopZ` 停靠焦距 | 1.05 | 1.0 邻站齐平画幅边（贴边感），>1.1 上排照片顶到安全边 |

我们的 `kits/diagram` 参数表只有"取值范围"。这条可以整体平移成文档纪律 ——
一个数字没有"越界的后果"，下一个人调它就是在赌。

## 三、两条硬规则，直接吸收

### 三段式

> 所有动效遵循 **入场（0.2~0.8s）→ hold（可伸缩）→ 出场（0.15~0.5s）**；
> **入场永远比出场更用力**；**同屏重音同一时刻只能有一个**。

我们现在的 `revealFade` 默认 0.3s，只覆盖了"入场"，没有出场，也没有"同屏只能一个重音"。
后者其实就是我们踩过的坑：第二轮优化里 `activeIndex` 高亮 + 新元素进场同时发生，
观众不知道该看哪个。

### 版式轮换闸（可量化）

> 同卡连用 ≥3 镜 FAIL；呈现卡 >1/3 FAIL；节奏表连续 3 镜同形态同容器 FAIL。

这条对我们直接适用：13 个 family 做 8 段，很容易 `data-bar → compare → data-bar` 来回切。

## 四、不可平移的四个假设

1. **Remotion / React 宿主**。它的每张卡是 tsx 组件，坐标系 960×540（`camTo(z, px, py)` 里
   `x = 480 − z·px`）。我们是 Canvas2D 直绘 1920×1080，几何全在 `box` 里算。
2. **一镜一卡占满屏**。它的卡是整屏画面；我们的图在版心内，外面还有标题、单位、注释、字幕。
   它的布局红线（`design-language.md §5`）不能直接套。
3. **素材是必需项**。它有硬规"全片零 B-roll / 图片 = 讲 PPT，FAIL"。我们恰恰是纯图示片，
   这条对我们是反的。
4. **卡即资产**。它的 `card_lint` 要求"实现必须复制自模板 tsx，相似度 ≥0.55"。
   我们的路线是重写（`kits/diagram` 13 类都是自己画的），这条规则与我们相反。

## 五、落地：`tools/check-shotbook.mjs`

把"版式轮换闸"和 `beat_gap_check.py` 的洞察合起来，做成**渲染前**的体检：

> `beat_gap_check` 的核心洞察是：**"哪个镜头会空台"从时间表就能算出来，不必等全片渲染完**。
> 对应我们的 gate 是 `--blank`，那是渲完才知道的。这张表在渲染前一秒就能出。

```bash
node tools/check-shotbook.mjs kits/diagram/presets/render-cost-20s.json --timing out/rc20.timing.json
```

实测输出（20 秒片，3 段）：

```
段   family        时长      锚点    最长空窗      位置
1   data-bar      8.55    6     4.3       0.4s
2   compare       7.23    4     4.1       9.9s
3   definition    4.07    1     3.0       16.9s
warn  第 1 段（data-bar）0.4s 起约 4.3s 无事件
```

三条警告**都是真的**，不是误报：

- 段 1 的 4.3 秒空窗 = "标签先立住、报数留在第二句"的代价（行锚点 0.42s，条锚点 4.70s）
- 段 2 的 4.1 秒空窗 = 左列出来（10.07s）到右列出现（14.01s）之间
- 段 3 的 3.0 秒空窗 = 一句话讲完就静止

**判据与边界**：

- 元镜头（`bignum` / `timeline` / `glyph` / `framecount`）不参与锚点判据 ——
  它们的事件不在 `items` 上（framecount 每帧都在变、glyph 逐字点亮），硬套只会造假警报。
- 只报不拦，退出码 0。**"空窗"不等于"错"**：三段式本来就允许 hold，
  关键是每一窗都答得出"这窗里什么在动、为什么不动"。
- 时长优先取 `--timing` 的真实值；preset 里的 `duration` 只是占位（`vo.mjs` 会覆盖）。

## 六、没吸收的，以及为什么

| 内容 | 理由 |
|---|---|
| 108 张卡的视觉实现 | 素材驱动，与我们的数据驱动不同源；且绑定 Remotion 坐标系 |
| `semantic_annotate.py` 的 26 词标注流程 | 我们是 3–8 段短片，逐句标注的成本 > 收益；但 `main/sub` 的**分层思想**值得进 preset |
| `SHOTBOOK` 工作单 | 8 段以内脑内可持有；超过 10 段一定崩 —— 这条我们认，但现在的片子还没到 |
| `preflight.py` 素材对账 / 三重验收 6 条闸 | 我们没有素材层；`gate` 已覆盖像素侧（flat/black/freeze/hook/LUFS） |
| `workbench` 在线预览工坊 | 依赖 Remotion + Vite，换宿主的成本高于收益 |

## 七、下一步（按性价比排序）

1. **把 `weight: main|sub` 加进 preset**：sub 句只做微调、不进新元素。预计能砍掉一半的"满屏重来"。
2. **给 13 个 family 补"能量"字段**：同语义下按能量挑 family，而不是靠记忆。
3. **补出场**：现在只有 `revealFade`（入），没有出场。段落切换时上一段的元素是硬切消失的。
4. **参数表补"调节手感"列**：`kits/diagram/README.md` 的参数表先补，再回填各 family。
