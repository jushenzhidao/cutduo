# desk 版式动效方案

> 起因：产品介绍片交出去时被说「动态效果完全没了」。
> 但量下来原版的 title / talk 段**也是 0.00% 变化**（完全静止）。
> 所以问题不是"动效缺失"，是**动效在时间轴上的分布**。
>
> 这份文档把"动感"拆成可量化的四层，并给出每层的参数规范与验收方法。

---

## 一、先把问题说准

用帧间差分量化（全分辨率，不能缩图——13px 的鼠标缩到 240px 宽就不见了）：

| 片 | 段数 | 平均段长 | 帧间变化 | 完全静止的帧对 |
|---|---|---|---|---|
| 原版 demo | 16 | 3.5 s | 0.00–29.3% | 多数段 0.00% |
| 我的第一版 | 17 | 5.8 s | 0.01–45.5% | 0/85（有微弱变化） |

**结论**：原版不是"一直在动"，而是**段短、动效占比高**——3.5 秒的段里动 1.5 秒，占 43%；
我 5.8 秒的段里动同样 0.9 秒，只占 15%，剩下 5 秒定格。

> 观感 = 动效时长 ÷ 段时长。段越长，同样的动效越"没感觉"。

---

## 二、四层动效（按性价比排序）

### 第 1 层 · 入场动画（每段开头，0.3–0.5 s）

**已有**，所有段型都自带（`pr(t, t0+…, t0+…+0.42)` 淡入 + 上浮）。

不可调，也不用调。它的作用是"告诉观众这屏来了"，但**只占段长的 5–10%**，撑不起动感。

### 第 2 层 · 鼠标落点（`args.cursor`，每段 2–3 次）

**这是最容易被忽略的一层**——原版 16 段只用了 1 处，我第一版 0 处。

```json
"cursor": [
  { "x": 430, "y": 420, "at": 1.2, "from": [650, 760] },
  { "x": 700, "y": 560, "at": 3.6, "from": [430, 420] }
]
```

- `at` 是**相对段起点**的秒数；动画固定 0.8 s，末端带一次点击涟漪。
- **`at` 要分散到段中段**，不要堆在开头。段长 6 s 就给 1.2 / 3.6 两个点。
- 坐标是 1440×1080 像素；`from` 不写就从上一次的落点（默认 300,700）出发。
- 语义上要**指向这屏正在说的东西**（点通知条、指曲线高点、指排名第一行）。

**实测效果**：每段帧间变化从 0.0–0.1% 提到 0.4–1.0%。

> 代码侧已改：`cursor` 支持数组（`kits/desk/desktop.mjs`）。原来只认单个对象，
> 一段只能飞一次 0.8 秒。

### 第 3 层 · 持续律动（电平柱，全程 2–3%）

摄像头窗口底部那 7 根绿色电平柱，原来是**写死的高度**：

```js
box(…, 6 + (i < 4 ? 6 : 2), …)   // 前 4 根 12px、后 3 根 8px，永远不变
```

现在改成三条正弦叠加：

```js
const lvl = |sin(t*5.4 + ph)*0.55 + sin(t*9.7 + ph*1.7)*0.3 + sin(t*2.1 + ph*0.6)*0.15|;
```

- **5.4 Hz**：主节奏（说话音节的量级）
- **9.7 Hz**：细碎抖动
- **2.1 Hz**：缓慢起伏
- 每根相位错开 `0.85`，才有"来回扫"而不是"整体一起跳"
- 后 3 根只在 `lvl > 0.45` 时点亮

**实测**：该区域帧间变化 2.4–3.5%，且**全片持续**——这是唯一覆盖 100% 时间轴的动效。

### 第 4 层 · 慢推（`photo` 段，1.3–3.5%）

全屏照片有 `1.05 → 1.12` 的慢推（`drawPhotoCover` 的 zoom 参数）。

作用是让静止的实拍图"活着"。代价是它会裁掉边缘 7%，构图要靠 `fx / fy` 调焦点。

---

## 三、段长是总开关

动效层的数量有上限（入场 1 次 + 鼠标 2–3 次 + 电平柱常驻）。**段越长，摊得越薄**。

| 段长 | 入场 | 鼠标 ×2 | 电平柱 | 有效动效占比 |
|---|---|---|---|---|
| 3.5 s | 0.4 | 1.6 | 全程 | ≈ 70% |
| 5.8 s | 0.4 | 1.6 | 全程 | ≈ 45% |
| 8 s | 0.4 | 1.6 | 全程 | ≈ 33% |

**规范**：

- **单段 ≤ 6 s**。超过就拆（配音也要跟着拆，文案按 4.9 字/秒重算）。
- 若必须长段（>7 s），**鼠标落点加到 3 个**，且间隔不小于 1.8 s。
- `photo` 段可以到 8 s（慢推是持续的）。

## 四、验收方法

### 手动

```bash
# 抽同一段的两帧，比该区域的帧间差
ffmpeg -ss 12.0 -i out/xxx.mp4 -frames:v 1 a.png
ffmpeg -ss 12.4 -i out/xxx.mp4 -frames:v 1 b.png
ffmpeg -i a.png -i b.png -lavfi "blend=all_mode=difference,format=gray" -f rawvideo - | …
```

### 自动（已实现：`gate.mjs --motion`）

```bash
node src/gate.mjs out/xxx.mp4 --motion
```

做法：2fps 抽帧 → `tblend` 与前一帧求差 → `signalstats` 取 Y 均值（0–255）。
连续 ≥ 2 秒的差分都低于 0.08 就算"这段卡住了"，只报不拦。

**三向验证**：

| 片 | 结果 |
|---|---|
| 纯静态图转成的 6s 视频 | 报 1 处（2.5–4.5s） |
| desk 片（有电平柱） | 零告警 |
| paper 片（benford） | 报 5 处（最长 28.5–31s） |

**一个必踩的坑**：`tblend` 的**前 7 帧输出的是原图而不是差分**（YAVG 等于原图平均亮度 3.47）。
不加 `select='gte(n,2)'` 跳过预热帧，纯静止的片会被判成"一直在动"。

判据参考值（实测）：

| 内容 | 帧间变化 |
|---|---|
| 完全静止（写死的元素） | 0.00–0.05% |
| 只有电平柱在动 | 2.4–3.5% |
| 元素入场 / 鼠标飞行 | 0.4–2.0% |
| 换屏（壁纸整体变化） | 13–48% |

**注意**：`freezedetect` 抓不到这类问题——它的阈值是 0.2% 像素变化，
而电平柱只占画面 0.02%。要用**全画面均值差分**，不是 freeze。

## 五、检查表（出片前）

- [ ] 每段 ≤ 6 s（超过就拆文案）
- [ ] 每段至少 1 个 `cursor`，长段 3 个，`at` 分散
- [ ] `cursor` 的落点指向本屏正在讲的东西，不是随便一个坐标
- [ ] 壁纸随章节变色（`chapters[].wall`，别全写 `light`）
- [ ] `photo` 段给了 `fx / fy` 焦点
- [ ] 段型不要重复太多（18 种里选，同一支片至少覆盖 8 种）
- [ ] 跑一遍全分辨率帧间差分，确认没有 >2 s 的静止区间

## 六、踩坑记录

1. **缩图测量会骗人**。第一次测出 `0.00%` 是因为把画面缩到 240px，
   13px 的鼠标在缩略图里不到 1 像素。**必须全分辨率差分。**
2. **`cursor` 原来只认单个对象**，一段只能飞一次。改成数组后才有"一直在操作"的感觉。
3. **电平柱写死**是最隐蔽的一处：它在画面里一直存在，观众不会意识到"它本该动"，只会觉得"这片子死板"。
4. **壁纸写死 `light`** 同理：整片一个底色，等于放弃了章节的节奏。
5. **段型太少**（8/18）会让前 30 秒就看完所有样式，后面全是重复。
