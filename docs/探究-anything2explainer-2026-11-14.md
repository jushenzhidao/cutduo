# anything2explainer 蒸馏（2026-11-14）

> 对象：`Vincentwei1021/anything2explainer`（211 文件 / 152 KB 规范 + 18 MB Remotion 模板 + 5.1 MB 样片帧）
> 判据：本项目「半蒸馏」标准 —— 上游是**版式枚举**还是**机制参数**；换宿主能否讲新内容，还是只能复现那一支片。
> 用途口径：**科普类**（长 3–8 分钟、口播驱动、需要讲清机制）。

## 一、结论

1. **它不是视频生成器，是「方法包」**：9 阶段流程 + 4 个确认点 + 6 份写给 agent 的规范 + 1 支 44 镜头样片当标尺 + 一个能编译的 Remotion 模板。渲染部分（React 组件 / 字体 / 18 MB 模板）对本仓零价值；**价值全在 `reference/` 那 152 KB 里**。
2. **最稀缺的资产是一条方法论：把「画面好不好看」翻译成可自动判定的数字。** 主体 ≥170px 且带光、<110px 持续 >45 帧记缺陷、一帧紫色色块 ≥8 记缺陷。它解决的正是本项目 QC 的结构性盲区——门禁全过、成片还是「小而暗」。
3. **但它的判据一条都不能照抄**，三条口径同时错位（§三实测）。本次只吸收「判据的形式」，阈值全部按本仓语料重标。
4. **许可证是 PolyForm Noncommercial**：工具包商用需作者授权（成片归创作者）。所以**只吸收规则与结构，文字与代码一律重写**，不拷文件。

## 三、三条不可平移（实测，不是推断）

上游全部阈值都在 **1280×720 / 30fps / 黑底白线 / 镜头式** 这一组前提下成立。本仓是 **1920×1080 / 60fps / 浅底深字与深底并存 / 段落式**。逐条量过：

### 1. 帧率：逐帧差分随帧率线性变小，时间基线错了 6 倍

上游「静止」的定义是 320×180 灰度平均变化 < 0.35，但它是**每 3 帧抽一张**、片是 30fps ⇒ 实际时间基线 **0.1 秒**。

同一支片（`birthday-paradox-final`，60fps）两种口径：

| 采样基线 | 判静止占比 | 最长静止 |
|---|---|---|
| 相邻帧（0.017 s） | 96.7% | 9.2 s |
| 0.1 s（与上游同尺度） | 93% | 17.8 s |

差值不是噪声，是慢动作在短基线上的差分被系统性压小。**所以 `tools/pacing.mjs` 默认 `--equiv-fps 10`（0.1 s 基线），而不是「相邻帧」。**

### 2. 底色极性：上游用「亮度 >120 取前景」，在 `paper` 上会把整张纸识别成主体

`kits/paper` 的底色是 `PK.bg`（浅色纸），正文深字；`kits/science` 是 `#0B1418` 深底。上游 `frame_metrics.py` 的 `bright = lum > 120` 只在后者成立。**所以本仓的节奏量改用「变化量」而不是「前景色」——差分与底色无关，这是选差分口径的原因。**

### 3. 版式家族：静止阈值差 15 倍，一个数管不了两个家族

同一套口径（内容区 y 10%–86%、0.1 s 基线）在本仓成片上实测：

| 片 | 版式 | 全片静止占比 | 最长静止 |
|---|---|---|---|
| `cute-mv-demo` | MG（连续运动） | **6%** | 0.57 s |
| `benford` | paper | 86% | 5.17 s |
| `gut-antibiotic` | science | 86% | 6.83 s |
| `selection-bias` | paper | 91% | 5.92 s |
| `birthday-paradox-final` | paper | **92%** | **17.77 s** |

结论：**上游「静止 ≤3 s」只是 MG 风格的口径。**直接搬进来，4 支科普片全判失败（其中 3 支是健康片），而对 MG 片毫无约束力（它天生 6%）。这不是「加个余量」能解决的，是判据本身绑定了风格。

## 四、已落地的吸收

### 1. `tools/pacing.mjs` —— 节奏体检（新增）

```
node tools/pacing.mjs out/x.mp4 --params content/x/params.json     # 默认：排版式口径
node tools/pacing.mjs out/x.mp4 --strict                            # MG / 短科普口径（上游 3 s）
```

三个读数，语义按本仓重定义：

| 读数 | 定义 | 判定 |
|---|---|---|
| `still%` | 段内静止帧占比 | **只报不判**，当版式指纹用（<20% = 连续运动型） |
| `最长静` | 段内最长一段「画面无变化」 | 排版式 ≤8 s（语料最大值 + 余量）／`--strict` ≤3 s |
| `hold` | 段末最后一次大变化之后还稳了多少帧 | **下界**判据 ≥30 f@30fps；只在 `still%≥20%` 时判 |

阈值来历（可复核）：

- `8 s`：健康语料最长 6.83 s，取最大值 + 1.2 s 余量。`birthday-paradox` 的 17.77 s 被单独标出——它就是「节奏拖」的实证。
- `hold ≥30 f`：4 支科普片实测 min 37 f（benford）→ 30 f 安全；只有「落位即切」才会掉到个位数。
- `still% <20% → hold 不判`：`cute-mv` 全片 6%、hold 恒为 0，不豁免会 100% 假阳性。
- **单段模式（没给段界）不判 hold**：那时它量的是「片尾最后一个元素到结束」，没有切点——`night-card` / `chalkboard` 会读 14 f，是口径不是缺陷。

实现上踩到两个坑，都会让 hold **恒为 0、全片误报**（记录下来，改算法前先看这两条）：

1. **段界与视觉切点不是一回事**：params 的 `t1` 来自音频时长，实测 `gut-antibiotic` 段界 16.488 s、画面 16.40 s 就切了。差这几帧，切点本身就落进段内，差分飙到 40 → hold=0。
2. **一次硬切会让差分偏高若干帧**（`diffMean[i]=|帧i − 帧i−k|`，实测拖尾 4 帧：0.60→3.33→6.17→7.07→6.90）。所以必须**先从段尾跳过整段活动帧、落到最后一个安静帧，再往回数**；反过来（先数、遇活动就停）起点永远落在拖尾里。
3. 另有一条系统偏差：运动停止后的头 k 帧读不出来，`hold` 恒少 k 帧。合成用例实测：静止 1.0 s 后切，不补 k 读 27 f、补 k 读 30 f。

正反向自检（2026-11-14 实跑）：

| 用例 | 期望 | 实测 |
|---|---|---|
| 合成：运动到底才切 | 判「落位即切」 | hold 14 f ✗ ✓ |
| 合成：静止 1.0 s 后切 | 通过 | hold 30 f ✓ ✓ |
| benford（健康排版式） | 全过 | 0/15 段不达标 ✓ |
| birthday-paradox（静止离群） | 报出最坏段 | 6/9 段不达标，最坏 17.77 s ✓ |
| gut-antibiotic（science，7 段） | 全过 | 0/7 ✓（修掉切点误报前是 4/7 假阳性） |
| cute-mv / api-mg（MG） | 不误报 | 0/1 ✓（hold 豁免生效） |
| benford `--strict` | 按上游口径应大面积失败 | 9/15 不达标 ✓（证明阈值确有区分力） |

跨版式鲁棒性（11 支，含 1080×1920 竖屏 / 1440×1080 4:3 / 24–60 fps）：零崩溃，全片静止占比
78–93%（排版式）、**7% 与 6%（MG）**。即**只有 MG 这一族是连续运动**，其余七套版式都接近静态——
这进一步证实 §三.3：3 s 规则在本仓只对一套版式有意义。

### 3. 未落地（按你的选择暂不做）

- **构图量化**（主体尺度 / 主角区柔光 / 紫色碎片）：算法要处理浅底极性，且 `paper` 的主元素本来就是大字号而非「发光主角」，直译会误判。要做需要先给 `paper` 定一套「谁是主角」的标注口径。
- **补段型**：`paper` 现有 11 型，覆盖画面关系表 24 行中的 8 行。缺口：时间轴/放慢、公式、表格/榜单、网络图、漏斗、反馈环、层级纵深、两路汇合、容器准入、视差「很多」。
- **高光时刻相对帧表**：可直接加进 `kits/paper`，但要先定「一章 = 几个 scene」。

## 五、值得记住的上游教训（与视觉无关，可直接用）

1. **计数动画的中间值也是「上画面的数字」。** 年份 1995→1998 线性滚，中间年份会清晰可读 4–6 帧；若不在事实清单里就是事实错误。修法：滚动全程 ≥9px 模糊 + 落定帧归 0，或不计数。
2. **出处灰小字不能挂在镜头最后一个字幕块上**，必须 ≥2.5 s 停留，否则等于没送达。这条与「落位即切」同源。
3. **`fadeIn(n=0)` 返回 0，用它做首帧入场必然空一帧。** 本仓对应坑：`t=0` 时 `ease(0)=0`，第一帧全空。
4. **不要照抄 agent 的自评**，要抽验；但也不要急着断定它错了——先看全证据。
5. **协议里提到的工具必须在共用层真的存在**，否则每个组自己发明一份（上游出现过 4 份不同公式的 `softOp`）。
6. **主题本身是几何的（推 vs 变焦），必须让底层机制真的不同**，否则观众看到的两幅图一样，整章等于讲错。
