# 编码与并行优化实测（2026-11-13）

同一支分镜 `content/demo-voiced.json`（4127 帧 / 68.783s / 1440×1080@60 / GPU 壁纸 / 裸帧），
只改一个变量。机器 30 逻辑核（10 性能 + 20 效率）。

## 1. 编码器对比（8 worker）

| 编码器 | 墙钟 | 吞吐 | 体积 | 相对基线 |
|---|---|---|---|---|
| **libx264 veryfast crf20** | **9.89 s** | **417 fps** | **6.63 MB** | 基线 |
| h264_videotoolbox 6M | 9.82 s | 420 fps | 50.12 MB | 7.6× |
| hevc_videotoolbox 4M | 9.72 s | 424 fps | 37.93 MB | 5.7× |

**速度没有差异，体积差 5.7–7.6 倍。** 硬件编码在这条产线上三点全输。

等码率再验一次（1200 帧，`-b:v 1M`）：videotoolbox 实际产出 1.6 Mbps / 4.0 MB，
x264 crf20 是 0.68 Mbps / 1.7 MB —— 仍差 2.4 倍，且码率控制不准（要 1M 给 1.6M）。

原因：瓶颈不在编码器。8 worker 下并行效率已达 85%（理论 490 fps / 实测 417 fps）。

## 2. Worker 扩展性（1200 帧）

| workers | 绘制 | 传帧 | 单帧合计 |
|---|---|---|---|
| **8** | 4.03 ms | 12.82 ms | **16.85 ms** |
| 12 | 4.83 ms | 15.38 ms | 20.21 ms |
| 16 | 5.51 ms | 20.37 ms | 25.88 ms |

**8 是甜的，更多反而更慢。** 30 核机器上仍有 22 核空闲，但单帧成本上升 20% / 54%。

证据指向共享资源竞争而非 CPU：壁纸层从 2.28 → 2.58 → 2.92 ms（多个 headless-gl 上下文争抢），
以及 8 个 ffmpeg 各写一个 `.ts` 分片的 I/O 竞争。

## 3. `-tune animation`（1200 帧）

| 配置 | 体积 | 单帧 |
|---|---|---|
| 默认 | 1.70 MB | 16.38 ms |
| **`-tune animation`** | **1.30 MB（−24%）** | 16.84 ms（+3%） |

画质：字幕区局部 SSIM **0.9915**；4 倍最近邻放大对比，字形边缘无可见模糊、色块或振铃。

**这是唯一的免费收益。** 适用面很广——本仓所有模板都是平涂色块 + 文字，正是 x264 的
animation tune 针对的内容类型（它降低对高频细节的保留，而这类内容本来就没有高频细节）。

## 4. 结论与优化顺序

| 优先级 | 措施 | 收益 | 状态 |
|---|---|---|---|
| 1 | `--tune animation` | 体积 −24%，速度几乎不变 | **已接入**，实测通过 |
| 2 | 保持 x264 veryfast crf20 | — | 硬件编码已证否 |
| 3 | 保持 8 worker | — | 12/16 已证否 |
| 4 | 壁纸降频（fBm 每 2 帧算一次） | 单帧 −6% | 待做，风险：快转场可能跳变 |
| 5 | 取帧零拷贝（原生 addon） | 单帧 −6% | 待做，成本：新模块 + FFI |
| 6 | 降到 30 fps 或 1280×960 | −15~50% | 改内容规格，非代码优化 |
| ✗ | 硬件编码 | 无 | 已实测证否 |
| ✗ | Rust 重写渲染器 | ≤5% | 绘制已跑在 Rust（napi-rs + skia-safe） |

**这条产线在 1440×1080@60 下已接近该架构的极限（8.5× 实时）。**
再快只能改内容规格（fps / 分辨率），不是改代码。

## 复现

```bash
# 编码器对比
node desktop-kit/tools/render-bench.mjs --preset content/demo-voiced.json \
  --bg gpu --pipe raw --workers 8 --codec vt264 --bitrate 6M --out /tmp/vt.mp4

# tune 对比
node desktop-kit/tools/render-bench.mjs --preset content/demo-voiced.json \
  --bg gpu --pipe raw --workers 8 --limit 1200 --tune animation --out /tmp/a.mp4

# worker 扩展性
for w in 8 12 16; do node desktop-kit/tools/render-bench.mjs --preset content/demo-voiced.json \
  --bg gpu --pipe raw --workers $w --limit 1200 --out /tmp/w$w.mp4; done
```

参数：`--codec libx264|vt264|vthevc`、`--bitrate 6M`、`--tune animation`。
