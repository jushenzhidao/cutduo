# 02 · Dreamina Motion Showreel 音效蒸馏（2026-11-16）

> 源：同 01 那支片（`refs/jimeng/01-motion-showreel/source.mp4`）。
> 方法：不是听，是**测**——两条包络（全频 RMS / 3kHz 高通 RMS，10ms 帧）+ ffmpeg 场景检测，
> 再按时间对齐。工具：`tools/sfx-probe.py`。
> 落地产物：`tools/sfx-synth.mjs` + `content/jimeng-showreel/sfx.json`。

## 一、全片最重要的一条：切点必然有瞬态

四个硬切点，四个音频事件，**没有例外**：

| 切点 | 最近的音频事件 | 偏移 | 类型（检测器判定） |
|---|---|---|---|
| 2.533 | 2.524 | **−9 ms** | impact |
| 9.633 | 9.678 | **+45 ms** | impact |
| 11.067（段内白闪） | 11.065 | **−2 ms** | impact |
| 12.300 | 12.322 | **+22 ms** | whoosh |

偏移全部落在 ±50ms 内。这不是巧合：**画面的切与耳朵的切绑在一起**，
观众感到"剪得利落"的物理来源就在这里。原片在 15 秒里只切四次，每一次都配了瞬态，
一次没漏——反过来说，如果切了点却没配音效，那一下会明显"发虚"。

## 二、切点前后还有一段 riser

最清楚的一例跨越切点：

```
12.003 ──────────── 12.300（切点）──────────── 12.641
        riser 0.638s，峰 Δ 22.8 dB，8 次高频突增
```

前半段（12.0–12.3）还在旧画面里，是"要变了"的预告；切点处由 impact 接管。
**riser 跨越切点，不是紧贴切点结束**——这是它听起来自然的原因。

同期还有一个 riser 对应画面事件而不是切点：

```
1.257 ──────── 1.497   riser 0.24s，峰 Δ 25.5 dB
```

它落在 `拼不起来。` 这行大字出现的时刻（1.30s）。
**音效跟的是画面事件，不只是剪辑点。**

## 三、其余高频事件是音乐，不是音效

高频突增聚类共 18 组，其中两组特别长：

- 3.751–4.889（1.138s，9 次）
- 5.308–6.306（0.998s，9 次）

它们不对应任何画面变化，间隔均匀——是**配乐里的镲片/琶音**。
判据不是"高频突增"，而是**"能不能对上画面结构"**。
18 组里只有 5 组与画面有关，命中率 28%。这条是本篇最容易被误用的地方。

## 四、可平移的四条

1. **每个硬切点必须有一个瞬态，容差 ±50ms。** 没有例外，没有"这一下比较轻所以不用"。
2. **大段落切换铺 riser，跨越切点**（前 60% 在旧画面，后 40% 在新画面）。
3. **软过渡（同一画布内重排）用 whoosh，不用 impact。** 原片的 5.0 / 7.5 两处没有硬切，
   也没有 impact——只有轻微的高频掠过。轻重必须分开，否则六镜会听起来像六次撞击。
4. **文字/元素的落位可以配 tick 或 riser**，跟画面事件而不是时间网格。

## 五、不可平移的三条

| # | 上游表现 | 为什么搬不了 |
|---|---|---|
| 1 | 全频 Δ 阈值可定在 8 dB | 原片是 ambient 底，留白多；换成**满配乐**的片子，一个合理的 impact 全频 Δ 只有 7.x dB。阈值必须按目标片的 BGM 密度重新标定，照抄会漏掉全部 impact（实测：我们的片子里三个 impact 只有 1 个过线，另两个靠高频路径才命中） |
| 2 | 音色是这四种 | 原片的音源是商业音效库，我这里全部合成（低频下滑 / 带通噪声 / 短 click）。结构对，质感单薄一档 |
| 3 | 高频=音效 | 28% 命中率，直接当规则会把配乐当音效 |

## 六、对抗审查

1. **假阳性（镲片）**：已量化——18 组高频簇里 13 组是音乐。所以 `sfx-probe` 的输出**只能用来对照画面**，
   不能当"音效清单"直接落地。
2. **假阳性（首帧）**：检测器第一版在开头报了一个 Δ=105 dB 的突增，原因是观察窗为空、
   基线取了 −120 dB。已修为"窗口不足 5 帧不判"。**任何"相对前文"的检测器都有这个问题。**
3. **假阴性（轻音效）**：tick 类事件（−15 dB 以下、5–8ms）全频包络几乎不动，只有高通包络能抓到；
   只看全频会认为"这里没音效"。
4. **分类标签不可靠**：impact 的噪声爆有 3 kHz 以上残留，会同时触发 whoosh 检测。
   第一版按距离排序，把同一个音效报成了 whoosh；改为"50ms 内有 impact 优先认 impact"。
   **偏移量比类型标签可靠。**
5. **口径**：本片 4 个切点 4 个命中，是 4 个样本。n=4 不足以支撑"容差 ±50ms 是普适定律"，
   只能支撑"这支片这么做"。要泛化得再测 5–10 支同风格片。

## 七、落地

```bash
# 1. 反推任意成片的音效结构
uv run --no-project python tools/sfx-probe.py <video> --json out/sfx-probe.json

# 2. 按 cue 表合成并混入
node tools/sfx-synth.mjs \
  --cues content/jimeng-showreel/sfx.json --dur 15 \
  --out out/jimeng-sfx.wav \
  --mix out/jimeng-showreel.mp4 --out-mixed out/jimeng-showreel-sfx.mp4
```

产物 `out/jimeng-showreel-sfx.mp4`：15.000s / 450 帧 / **LUFS −15.9** / gate PASS。

cue 表里的 10 个音效（3 impact / 3 riser / 2 whoosh / 2 tick）全部按上面四条规则摆放，
每个 cue 带 `note` 写明它对应哪个画面事件——改片的时候照着 note 挪，不要凭时间轴猜。

两个实现上的坑：

- **impact 必须有中频 click（1.8 kHz / 12 ms）**。只有低频时，在满 BGM 里全频 Δ 不到 8dB，
  检测器认不出、人耳也听不见"那一下"。
- **归一化要留 3.5 dB 余量**。留 1.5 dB 时，与 BGM 相加再过 `aac_at`，真峰值到 −0.3 dBTP（削波风险）。
  macOS 的 aac 编码器抬峰值是老问题，只能靠编码前多留。

## 八、这套东西的适用边界

它解决的是"**剪辑点的听觉咬合**"，不解决"音效好听"。
一支没有切点、靠运镜和长镜头推进的片子，这套 cue 表基本用不上。
反过来，任何快节奏的段落式短片（产品宣传、功能演示、showreel）都能直接套：
先数切点，每个切点放一个 impact，再把段落内的元素落位补 tick。
