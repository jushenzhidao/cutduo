# 素材决策规范（BGM / TTS / 生图 / 动图 / 视频 / 数字人）

> **一条总原则：生成只发生在「内容准备」阶段，渲染阶段只读冻结文件。**
>
> 理由不是洁癖。这套管线的核心资产是**可复现**——同参数逐帧一致、可多 worker 分片、
> 可离线重跑、可 diff 两版差异。一旦渲染期去调生成 API，这四条全废：结果不可重放、
> 分片会各自生成不同素材、断网就出不了片、改一个错字要重新烧钱。
>
> 所以：**生成一次 → 落盘 → 记来源 → 之后所有渲染只读文件。**

---

## 一、判定顺序：先问「缺什么」，不问「好不好看」

审美判断不可执行，信息缺口可以。每次要决定用不用生成式素材，按这个顺序问：

```
1. 这段要传达的信息，用一句话说清是什么？
2. 里面有可被证伪的断言吗？    → 有，先查证并写出处（§三·五），再谈画面
3. 现有版式能不能承载？        → 能，不生（版式比生成素材更稳、更快、可无限改）
4. 本地已有素材吗？            → 有，用（先翻 assets/media 与 refs，别急着检索）
5. 需要「真实存在的具体对象」？ → 素材检索，不要生成（模型没见过就会编）
6. 缺的是「声音」还是「画面」？
   ├─ 声音
   │   ├─ 缺人声、有脚本        → TTS
   │   └─ 缺情绪底色            → BGM
   └─ 画面
       ├─ 一张静图就够          → 生图
       ├─ 静图在这段里显得死    → 动图（图生视频，3–5s）
       ├─ 必须是实拍级镜头      → 视频生成
       └─ 必须出现「说话的人」  → 数字人
7. 生成 / 检索 → 冻结 → 写 source → 过验收（见 §四、§五）
```

第 2 步是最容易被跳过的一步。**能用版式表达的抽象概念，不要生图**——
「增长」「焦虑」「连接」这类词，版式里的数字、对比、时间轴比插图准确得多，
而且改文案不用重生成。

## 二、触发矩阵

| 缺什么 | 用什么 | 在什么片子里是"默认" | 明确不该用的场景 | 相对成本 |
|---|---|---|---|---|
| 情绪底色 | **BGM** | 几乎所有非实拍片 | 现场声本身是内容（vlog、探店） | 极低（0 积分或自建） |
| 人声 | **TTS** | 有口播稿但没录音 | 有真人录音；需要笑声/哭腔/方言表演 | 低 |
| 具体画面（静） | **生图** | 缺图示、需要统一风格的插图 | 能用版式/图表；有实拍素材 | 中 |
| 画面要动（单动作） | **动图** | 静图镜头 >2s 显得死 | 镜头 <2s；已有视频素材 | 中高 |
| 实拍级镜头 | **视频生成** | 开场钩子、场景建立、拍不到的场面 | 能用模板动效；单镜头 >10s | 高 |
| 说话的人 | **数字人** | 口播出镜、教学讲解 | 只需旁白；形象要求高（恐怖谷） | 高 |

成本列不是钱的问题，是**返工成本**：改一句文案时，BGM 不用动、TTS 重跑一段、
生图要重生成一张、视频要重生成一条、数字人要重跑整段口型。

## 三、各类细则

### BGM

| 项 | 口径 |
|---|---|
| 时长 | ≥ 片长即可，管道按 `-t 片长` 截断；**不会自动循环**，短了会留静音尾巴 |
| 电平（BGM 单独） | 均值 **−24 ~ −28 dB**。此时 BGM 是唯一音轨，太轻等于没有 |
| 电平（BGM + 口播） | 先 `amix`，BGM 压到比人声低 **10 ~ 15 dB**。实测三支口播均值 −23.6 dB ⇒ BGM 应 −34 ~ −38 dB |
| 结构 | 前 4–6s 淡入、最后 6–8s 淡出；结尾比画面早收 |
| 来源 | CC0 / 自建合成；商用必须记来源与许可 |
| 不触发 | 现场声是内容；解说密集到人声已占满频段 |

一句话：**BGM 是所有生成式素材里性价比最高的，默认该有；它的作用是垫底不是表现。**
最容易犯的错是拿「单独版」的电平去混口播——那样人声会被压住，且没有 ducking 可救。

### TTS

| 项 | 口径 |
|---|---|
| 入口 | `tools/build-sync.py --tts edge --voice <name> --rate <±%>` |
| 音色 | 一支片 ≤ 2 个音色；多音色按角色映射，不要随机换 |
| 语速 | 工具默认 `+5%`（`build-sync.py:118`）。正式口播从 `+0%` 起校准；情绪向 `-5%`，信息密集 `+5 ~ +8%` |
| 对齐 | **时间轴跟配音走**（`guide.voicing` 的 lead/gap），不要让配音迁就固定时间轴 |
| 产物 | wav/PCM 必须转 AAC 160k 再进 mp4，否则部分播放器整轨静音 |
| 不触发 | 有真人录音；需要表演性语气（TTS 平，长段会疲劳） |

### 生图

| 项 | 口径 |
|---|---|
| 分辨率 | ≥ 目标画幅的 **1.5 倍**，留裁剪与推近余量 |
| 风格 | 必须能用 3 个形容词描述，且与模板同色系；换了风格就整片不一致 |
| 内容 | **禁止画面内文字**——模型生成的字基本是错的，必须画字就用版式叠 |
| 人物 | 禁止可识别的真人脸；需要人像就用剪影/背影/远景 |
| 数量 | 一支片 ≤ 6 张。再多说明信息量本该由版式承载 |
| 不触发 | 抽象概念（用版式）；有实拍；需要精确数据或结构（用图表） |

### 动图（图生视频，3–5s）

| 项 | 口径 |
|---|---|
| 时长 | 3–5s，可循环；超过 5s 边际收益骤降 |
| 运动 | **单一动作**：缓推、缓拉、粒子飘、光影呼吸。多主体运动会崩 |
| 帧率 | ≥ 24fps，与成片一致；不一致要补帧 |
| 输入 | 必须给首帧图，构图才可控 |
| 不触发 | 镜头 <2s（看不出动）；静态图 + Ken Burns 已够（模板本来就会推近） |

### 视频生成

| 项 | 口径 |
|---|---|
| 时长 | 单镜头 ≤ 10s；要更长就拆镜头，不要硬拉 |
| 首尾帧 | 尽量给首帧图控构图；只给文本等于放弃控制 |
| 用途 | 只用于**开场钩子**与**场景建立**；信息承载仍交给版式 |
| 不触发 | 能用模板动效；需要精确文字/数据；需要多镜头连贯叙事 |
| 合规 | 平台要求标注 AI 生成时如实标注 |

### 数字人

| 项 | 口径 |
|---|---|
| 时长 | 单段 ≤ 30s。口型误差随时间累积，越长越明显 |
| 画幅 | 竖屏优先；半身景别比全身稳（手部最容易崩） |
| 验收 | 口型同步、眨眼频率、手指、牙齿。四项任一明显崩就不要用 |
| 不触发 | 只需旁白（用 TTS）；形象要求高（恐怖谷会毁掉整片可信度） |
| 替代 | 先用「TTS + 头像静图 + 呼吸动效」验证脚本，确认后再上数字人 |

## 三·五、检索：什么时候必须联网

生成和检索是两条不同的线：**生成解决"东西不存在"，检索解决"东西存在但我不知道"**。
所以判据也不同——生成看信息缺口，检索看**能不能被证伪**。

### 一条分界：事实要查，表达不要抄

| 内容 | 例子 | 怎么办 |
|---|---|---|
| **事实**（可以被证明真假） | 人口、剂量、法规条款、版本号、价格 | **必须查，且必须写出处** |
| **表达**（句子怎么说） | 文案、比喻、句式、节奏 | **不许搜"类似文案"来改** |

第二条容易被忽略。搜"同类文案参考"只会产出"像别人的东西"，还会把别人没验证过的断言一起抄进来。
文案的唯一来源是内容本身——你要讲的那件事，你已经知道的部分。

### 三类检索，产出与落点都不同

| 类型 | 触发条件 | 产出 | 记录在哪 |
|---|---|---|---|
| **事实查证** | 文案里出现可被证伪的断言 | 结论 + 出处 | `content/*.json` 的 `_note` |
| **素材检索** | 需要"真实存在的具体对象"：城市街景、产品、历史照片、开源字体/BGM | 文件 + 许可 | `assets/media/<片子>/manifest.json`（`type: "stock"`） |
| **参考检索** | 要复刻某种画面语言或结构 | 只写进 `SPEC.md` / `guide.json` | **不进口**，不落素材 |

### 必须查的六类断言

出现以下任一类，**不许凭记忆写**：

1. **数字**：人口、面积、增长率、剂量、时长、比例
2. **时间**：年份、月份，以及"最近""目前"这类相对时间——必须转成绝对时间
3. **法规与标准**：名称、条款、生效日期、适用范围
4. **医学/健康口径**：剂量、适应症、禁忌、就医阈值（`content/period.json` 是范本）
5. **价格与费率**：订阅价、单价、汇率、手续费
6. **版本号与兼容性**：软件版本、协议版本、API 变更

### 不该联网的四种情况

1. 版式能表达的抽象概念（同 §一 第 2 步）
2. 本地已有素材——**先翻 `assets/media/` 与 `refs/`，再谈检索**
3. 通用常识（水在 100℃ 沸腾、一天 24 小时）
4. 为了"找灵感"搜文案（见上面那条分界）

### 三个硬要求

1. **一手优先**：官方文档 / 统计公报 / 临床指南 > 二手转述 > 百科。
   `content/period.json` 的 `_note` 是现成范本——ACOG、NHS、默沙东诊疗手册、腾讯医典，逐条标了来源。
2. **带日期**："据某报告"必须能回答**哪一年的报告**。相对时间一律转绝对。
3. **可复核**：写到别人能重新找到的程度——机构 + 文档名 + 年份，最好带章节或条目。

### 检索结果也要冻结

与"渲染期不调生成 API"同源：**检索只发生在内容准备阶段**。
查到的数字写进 `_note`，找到的素材落盘并登记 manifest，之后渲染只读这些，不再联网。

### 一个反例（真实踩过）

`content/period.json` 的 `_note` 里四条医学口径写得完整，但 `content/period-voiced.json`
（配音重排版）的 `_note` 被生成脚本覆盖成了「由 build-voices.py 按真实配音时长重排」——
**出处丢了**。用配音版出片时，那段文案就变成了"无来源断言"。

⇒ 重排/派生类脚本**只许追加 `_note`，不许覆盖**。这条已作为检查项加进 `asset-audit.py`。

## 四、冻结记录（这条是规范能落地的前提）

**没有 `source` 的素材不许进片。** 记录写在素材清单里，不是写在文件名里。

```jsonc
{
  "id": "hero-01",
  "kind": "image",                    // image | video | audio
  "path": "assets/media/<片子>/hero-01.png",
  "source": {
    "type": "generated",              // generated | stock | shot | synthesized
    "model": "…",                     // 用的哪个模型
    "prompt": "…",                    // 生图/生视频必填，便于重跑
    "seed": 12345,                    // 能固定就固定
    "generatedAt": "2026-11-13T10:00:00+08:00",
    "cost": { "credits": 0, "tier": "free" }   // 0 就是 0，别写"大约"
  },
  "license": "self-generated",        // 或 CC0 / 已购买 / 授权方
  "frozen": true
}
```

四个 `type` 的含义：

| type | 含义 | 是否必须能重跑 |
|---|---|---|
| `generated` | 模型生成（图/视频/数字人） | **是**，prompt + model + seed 三项齐全 |
| `synthesized` | TTS / 程序合成（含 BGM） | 是，脚本 + 参数可重放 |
| `shot` | 实拍 | 否，但记设备与日期 |
| `stock` | 图库/素材站 | 否，但记来源链接与许可 |

`frozen: true` 是承诺：**这个文件是最终版，渲染只读它，不重新生成。**

## 五、三条红线

1. **渲染期不调生成 API。** 违反这条，可复现、分片并行、离线重跑、版本 diff 全部失效。
2. **无 `source` 不进口。** 三个月后你一定想不起来那张图是哪来的、能不能商用。
3. **生成素材不承载关键信息。** 数字、结论、流程、对比一律用版式画。
   生成素材只负责「氛围」与「具象化」，它一旦承载信息，改一个数字就要重生成整张图。

另有一条软约束：**一支片里 `generated` 素材不超过总镜头数的三分之一**。
超了会出现两个问题：风格不统一（每张图有细微差异），以及改稿成本失控。
它不承载信息，所以可以整段删掉换版式——这也是为什么前面说「不承载关键信息」。

## 六、和现有管线的接法

| 素材 | 落点 | 引用方式 |
|---|---|---|
| 图片 | `assets/media/<片子>/*.png|jpg` | `content/*.json` 的 `photos: { key: path }` |
| 视频片段 | `assets/media/<片子>/clips/<key>/` | `clips: { key: { dir, fps } }`（帧序列） |
| 音轨 | `assets/audio/*.m4a` | 渲染时 `--audio <path>` |
| 模板自带素材 | `templates/own/<name>/assets/` | `asset-manifest.json`（含 role 与来源） |

TTS 是唯一已经脚本化的一环：`tools/build-sync.py --tts edge`。
其余五类目前是「手工生成 → 丢进 `assets/media/` → content 写路径」。

2026-11-13 补了 `assets/media/<片子>/manifest.json`：nanjing（5 条）与 hotpot（5 条）
已按各自 `content/*.json` 的 `_note` 原文回填；period 的 2 条在 `_note` 里没有来源说明，
**故意保持 `unknown`**，等确认后再填——不猜。新素材按 §四 登记，
`asset-audit.py --init-manifest` 可生成骨架。

## 七、检查工具

规范要能落地，得有人替你检查。`tools/asset-audit.py` 按上面四节的规则扫 `content/*.json`：

```bash
python3 tools/asset-audit.py                    # 全量审计，只报告
python3 tools/asset-audit.py content/x.json     # 单支
python3 tools/asset-audit.py --strict           # P0/P1 判失败（已进 smoke.sh）
python3 tools/asset-audit.py --fix-paths        # 旧路径自动改写（文本替换，不重排版）
python3 tools/asset-audit.py --init-manifest    # 生成骨架；镜头里写了 credit 的自动预填
python3 tools/asset-audit.py --apply-credit     # 把已有清单里的 unknown 按 credit 回填
```

**来源证据有两处，优先信后者**：

| 位置 | 性质 | 例子 |
|---|---|---|
| `content/*.json` 的 `_note` | 作者写的散文说明 | 「补充素材取自 Pexels 免费许可」 |
| `shots[].args.credit` | **随画面渲染的字段**，片子上那个角标就是它 | `"credit": "Pexels"` |

`credit` 更可信：它是成片里真实出现的信息，`_note` 可能写于早期、之后换过素材。
工具会优先用 `credit` 预填，并且按取值判类型——`"本人实拍"` 判 `shot`，其余图库判 `stock`。
`credit` 的写法并不统一（实测有 `"Pexels"` / `"Pexels 素材"` / `"本人实拍"` 三种），
所以匹配用关键词，不是全等。

分级与是否阻断：

| 级别 | 含义 | 阻断 |
|---|---|---|
| **P0** | 引用解析不到文件/目录 | 是 |
| **P1** | 清单里没有这条，或 `source.type` 非法 | 是 |
| **P2** | 缺 prompt/seed/`frozen`，不影响出片但影响重跑 | 否 |
| **W** | `type: unknown`，清单建了但来源待查 | 否（发布前必须填） |

清单位置：`assets/media/<片子>/manifest.json`，条目按 `id` 或文件名与 content 的 key 对应。

**为什么 P0 排在第一位**：2026-11-13 重构把 `edits/assets/` 挪到 `assets/media/` 后，
6 个 content 里的 24 处引用全部失效，而 `loadPhotos` 是静默跳过的——直到渲染到那个镜头
才抛错。这类问题比"没写来源"紧急得多，所以放在 P1 前面查。

## 八、最短可执行版

记不住上面所有细则，只记这三条也能保证不翻车：

1. **先问版式能不能承载**，能就不生成。
2. **生成一次就冻结**，渲染只读文件，prompt/seed 写进清单。
3. **生成素材只做氛围，不做信息**；数字和结论交给版式。
